# Private independent HTTP provider preparation

This unfinished optional package has no public exports, installation capability
or permission to transmit. It has no AI SDK or Cloudflare dependency.

Its initial request codec consumes the original admitted Common Provider/Task,
mapped input and strict structured schema. Common emits one nonstreaming choice,
the explicitly installed model ID and the original generation settings. Exact
Unicode, newlines, empty instructions and mapped data-text are preserved. JS
does not parse or reconstruct the input/schema. This initial non-reasoning
physical subset uses `max_tokens`; reasoning-model rewrites are unsupported.
The [official Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
marks this field deprecated and incompatible with o-series models. The initial
compatible endpoint/model profile must explicitly support the selected field;
this preparation is not a claim of universal current OpenAI model support.
Token/seed values outside the selected exact safe-integer subset refuse before
request construction; the common Task retains its wider Int64 domain.

Preparation is a finite synchronous read-only convenience, not cooperative
physical preflight. It retains the original projection tuple/schema string
while the outbound writer and checked schema emitter coexist. Those temporary
holdings and their work must be funded by the existing original Ledger before
any installed use. No numerical profile is supplied.

Endpoint/TLS/DNS and credentials remain trusted Host installation selections,
not Program parameters. The physical transport, original durable Entry,
current final-send gate, bounded raw read, selected Store persistence, Common
response validation, cleanup, replay and public Named Result path are not yet
connected to public installation here. SDK-free does not mean resource-free or
currently accepted.

The private `createHttpChatPreflight` supplies the existing Common async plan/call
API with one fixed transport. It prepares endpoint/header/body/response bounds
before Entry, records call custody before invoking the exact installed fetch and
starts it without an intervening await, notification or reconstruction. Common
retains final current authority/egress/one-shot validation. Known missing ports
refuse preparation; a missing binding observed after Entry keeps Unknown and
cannot regain a consumed start. An already aborted preparation starts no physical
request, without declaring the original Run Cancelled.

Bounded raw bytes are independently saved through the original installed raw
port, including incomplete transport observations. JS does not decode Chat
answers or infer completeness. Store failure/backpressure, unsuccessful reader
or raw cleanup, and explicit one-Promise same-call reconciliation retain the
original buffers/callbacks. Reconciliation does not rewrite terminal Unknown
or resend. Cleanup only clears local references after the corresponding original
physical/raw owners confirm retirement; escaped saved views remain separately
owned. A never-settling transport remains held, not a fabricated cleanup ACK.

`adapters/host-common/model-response-reader.mjs` is the single physical-reader
source. `scripts/generate-model-response-reader.mjs` reproduces identical private
copies for A and B; `--check` rejects drift. The current A copy is byte-unchanged.
Independent package consumers need neither the other adapter nor its SDK.

Node mechanism cases use explicit Common/Entry/saved-view doubles. A loopback
case uses two separately configured fixture endpoints and the existing bounded
notification Owner, one physical request each. These are not public Named Result,
actual nominal Store ACK, current-cut, numerical funding or live acceptance.

The separate `infer-http-raw-store` cases connect this same private HTTP port
to the existing encrypted Store/holding implementation. They check exact raw
bytes after Store reopen, commit-reply loss with stable same-cell reconciliation
and no second request, and cancellation with failed descriptor release while
the distinct content handle remains owned. Only the failed original descriptor
retries; retired cleanup releases neither handle again. These cases execute real
loopback HTTP and Store I/O, but Common request/Entry/grant/receipt remain explicit
doubles. They are not actual canonical admission, current-cut, original funding,
public Named Result or fresh-process Run restoration.

The initial profile needs explicit one-choice/no-stream/no-tools/no-retry
conformance against two independent compatible fixtures and an authorized live
public route. Unsupported settings or codec/endpoint capability must refuse
before send rather than trigger fallback. Formal packing, external installation
and all public/live acceptance remain incomplete M4a/M5 work.

The private `createInstalledHttpChatRegistration` connects this SDK-free port
to the existing Host `registerModelProviders` entry. It returns only the
existing exclusive async form, with original read installation, raw capture
selection, canonical binding originals and quantity selection borrowed from
their existing Owners. Missing originals/runtime/context refuse before
projection or sending. Installation SDK absence stays absent or explicit NULL;
it is not a dummy SDK, provider metadata, completion or funding capability.

Task/selector/prompt payload selection is exact, without normalization or a
second evaluator. Endpoint, headers and bounds are selected and snapshotted
before any operation; credentials come only from the trusted Host's secret
supply, never Program URLs or input. The physical caller still needs its
original admitted Provider, notification and deferred raw persistence binder.
The same Common preflight/Entry/current gate, raw Store, cleanup and final
typed output checks remain mandatory.

This assembler supplies no nominal original admission or numerical supplier.
Its immutable configuration/bounds/header tuples and closure borrows, plus
each physical request/reader/save overlap, must be counted in the original
Host/Run inventory. Normal package exports remain empty. The independent Node
registration cases use Core/Entry/selection/receipt doubles; they are not an
installed public Result or permission to use the selected fixture allowance.
