# Private independent HTTP provider preparation

This unfinished optional package has no public exports, installation capability
or permission to transmit. It has no AI SDK or Cloudflare dependency.

Its initial request codec consumes the original admitted Common Provider/Task,
mapped input and strict structured schema. Common emits one nonstreaming choice,
the explicitly installed model ID and the original generation settings. Exact
Unicode, newlines, empty instructions and mapped data-text are preserved. JS
does not parse or reconstruct the input/schema. This initial non-reasoning
physical subset uses `max_tokens`; reasoning-model rewrites are unsupported.
The [official Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
marks this field deprecated and incompatible with o-series models. The initial
compatible endpoint/model profile must explicitly support the selected field;
this preparation is not a claim of universal current OpenAI model support.
Token/seed values outside the selected exact safe-integer subset refuse before
request construction; the common Task retains its wider Int64 domain.

Preparation is a finite synchronous read-only convenience, not cooperative
physical preflight. It retains the original projection tuple/schema string
while the outbound writer and checked schema emitter coexist. Those temporary
holdings and their work must be funded by the existing original Ledger before
any installed use. No numerical profile is supplied.

Endpoint/TLS/DNS and credentials remain trusted Host installation selections,
not Program parameters. The physical transport, original durable Entry,
current final-send gate, bounded raw read, selected Store persistence, Common
response validation, cleanup, replay and public Named Result path are not yet
connected here. SDK-free does not mean resource-free or currently accepted.

The initial profile needs explicit one-choice/no-stream/no-tools/no-retry
conformance against two independent compatible fixtures and an authorized live
public route. Unsupported settings or codec/endpoint capability must refuse
before send rather than trigger fallback. Formal packing, external installation
and all public/live acceptance remain incomplete M4a/M5 work.
