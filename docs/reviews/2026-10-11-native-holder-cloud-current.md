# Native holder current Resume routing

## Connection

The real resident holder joins an admitted effect-resume poll to the existing
exact retained task and installed Host/Reviewer/Provider configuration. It now
uses the original Review's Cloud-current adapter from #1435 instead of using
an installation-supplied observation as the delivery's current claim.

The current-read client is the same operator-installed TLS/Site-credential
control client used by observations. The endpoint preserves that configured
origin/Site/generation path and replaces only `/outbound/observations` with
`/outbound/effect-resume-current`. A poll cannot choose an endpoint, credential,
key or Provider policy. An unsupported endpoint or missing independent
installation leaves original custody pending, without a synthesized observation
or a fallback to the transported claim.

A holder-local monotonic sequence distinguishes reads even at the same local
clock instant. It is bounded to one counter, never a second execution identity
or unbounded inventory. Exhaustion fails closed. The original dispatch CID and
local clock correlate each query; real current admission still comes from the
authenticated Cloud Owner read and existing common fence. Physical slot and
delegation checks remain the existing Site checks before and after that read.

## Evidence and remaining boundaries

Matching Native compilation verifies the actual holder call, operator read
configuration and existing Review/row Owner API. Added URI/challenge white-box
cases are compiled but not executed without the allocated Native window. No
physical Effect success is inferred from compilation.

The production command's Review policy/publication and Host/Reviewer/Provider
installation ports remain mandatory and uninstalled by default. This routing
change does not manufacture a deployment policy. A subsequent independent
installation must supply those existing typed Owners, then actual Worker/Native/
Store acceptance must verify approval/restart, no duplicate send, saved-response/
unknown custody, Named Result and formal release.

This child depends on OSS #1435, with final destination OSS main after its
parent. Cloud #266 supplies the current-read endpoint (after #265/#264). No
formal five-package/Native binary adoption, Hosted CI, Heavy execution, Provider
mutation or Preview deployment is performed. Historical #88 custody remains
separate from new execution results.
