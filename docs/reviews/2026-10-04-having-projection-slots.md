# Computed SELECT aliases in HAVING

This unit repairs existing grouped SELECT name resolution. It does not expand
the language profile or introduce a new evaluation owner.

## Defect and repair

These valid grouped queries were rejected by the integrated baseline:

```sql
SELECT x + 1 AS y, COUNT(*) AS n
FROM t GROUP BY x HAVING y > 2 ORDER BY y;

SELECT -x AS x, COUNT(*) AS n
FROM t GROUP BY t.x HAVING x < 0 AND t.x > 0 ORDER BY x;
```

`having_column` handled aggregate aliases, exact computed GROUP keys and direct
column projections. It had no evaluated slot for another expression over a
grouped input. The baseline execution of the two new positive tests failed
both cases (`run-fQGDis`, `focused-test-wuGY14`).

The lowerer now uses the saved grouped SELECT input scope to derive demanded
projection expressions before the HAVING filter. HAVING and SELECT share the
same physical slot, including two aliases of the same input expression.
Qualified input references use the existing range resolver. Temporary slots
are absent from the visible column list and are removed by the ordinary SELECT.
The reuse map expires before subsequent Pipe operations.

Ungrouped input references, SELECT sibling references, fabricated qualified
aliases and ambiguous aliases still fail with the existing typed expression
diagnostic. Expression work limits and original source origins remain enforced.
Execution uses ordinary Program `derive`, `filter`, `select` and `sort` operations,
the common checker/planner and standard Host. No D-owned CTE, assert or Effect
logic is changed.

## Independent expectations and public acceptance

[MoonBit regressions](../../src/query_program/having_projection_slots_test.mbt)
include a complete handwritten JSON Program. Its single `x + 1` derivation is
shared by both HAVING references and both SELECT output aliases. Both the
generated and expected Program use the normal checker; the expected Program
is not generated by the lowerer.

[Public fixtures](../../scripts/fixtures/having-projection-source-input.mjs)
define ten positive cases and four preparation refusals:

| Boundary | Independent obligation |
|---|---|
| JSON control and computed alias | ID groups 2 and 3 produce `next=3,n=1` and `next=4,n=2` |
| Same-name alias/input collision | `HAVING id < -1` uses output `-id`; it retains groups 3 and 2 |
| Qualified input | `HAVING records.id < 3` uses the input; it retains groups 2 and 1 |
| Repeated projection | `next` and `also` share one evaluated value; only group 2 remains |
| Nullable grouped input | The NULL group is filtered; the projected column remains nullable |
| Empty input | Empty rows retain the independently declared output schema |
| CTE JOIN input | The computed alias uses the qualified grouped JOIN slot |
| Following Pipe | A further `id + 1` consumes the projected value, producing 4 and 5 |
| Parameters | Typed declarations and values survive lowering and normal checking |
| Four scope refusals | No durable Run admission or provider I/O |

The existing packed runner compares Named Result rows, full ordered column
contracts via `Result.describe()`, completed streams, request replay/attach and
one shared Source read session. Internal columns must be absent. These cases
are registered in the normal packed corpus; `--having-projection-only` selects
them for bounded local diagnosis and does not replace normal CI registration.

The original case's outer `FROM records` bypassed all CTE bindings:

```sql
WITH b AS (SELECT 1 AS k), c AS (SELECT 1 AS z)
SELECT r.id + 1 AS next, COUNT(*) AS n
FROM records AS r JOIN b ON r.id = b.k JOIN c ON b.k = c.z
GROUP BY r.id HAVING next > 1 ORDER BY next;
```

A bounded preparation probe of the exact prepack-built bridge classified this
as `QueryLowering(UnsupportedCte)`. Removing HAVING still produces that refusal.
`compile_cte_query` currently requires the outer principal input to be one of
its CTE bindings. The equivalent acquired-CTE form prepares successfully in the
same environment. This is a separate CTE composition coverage gap, not a reason
to change the HAVING expectation or expand this unit into D-owned CTE lowering.
The probe establishes preparation only, not packed execution success.

The change retains contract version 0.1, public APIs, wire and stored-data
formats. Previously rejected sources acquire a normal Program and its normal
identity; no independent CID vectors are regenerated from product output.
Full Core/all-target, native, proof and performance campaigns are left to CI.
