# QUALIFY: ordinary analytic/filter/projection connection

## Scope and independent requirements

This unit connects the selected GoogleSQL QUALIFY clause to existing Program
operations. It depends on the qualified-star and star-REPLACE Frontend branches;
the final merge destination is main. The adopted main ancestor is
`b98a50ff763d1367e344fdfa8aea380ec8749132` (the sole Graph contract).

Reference: [GoogleSQL QUALIFY](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/query-syntax#qualify_clause).
The condition keeps only TRUE, runs after analytic computation and before
DISTINCT/ORDER/LIMIT, and requires a window in SELECT or QUALIFY. Window calls
need not be exported. Existing supported inline OVER functions and signatures
are reused; this unit does not add named WINDOW declarations or window owners.

The original source failed parsing at parent
`5c19826ce53cea9f66bef6642555c3b4f94955be`:

```sql
SELECT x, ROW_NUMBER() OVER (ORDER BY y) AS n
FROM t QUALIFY n <= 1 ORDER BY x
```

`src/query_program/qualify_test.mbt` authors the entire expected Values ->
analytic -> filter -> select -> sort -> Named Result Program independently and
checks it with the usual checker before comparing compilation. Public JSON
control, row multisets, ordered results and column contracts are independently
authored in `scripts/fixtures/qualify-source-input.mjs`.

## Implementation boundary

- The bounded parser captures clause-owned OVER and aggregate calls into AST
  placeholders. It never rewrites submitted SQL or patches a lowered Program.
- Window arguments use the original SELECT input scope. QUALIFY aliases use
  evaluated output slots, while qualified inputs retain their original meaning.
- Scalar aliases demanded by QUALIFY are evaluated once and reused in SELECT.
  Other scalar projections remain after the condition. Cached slots expire at
  materialization and cannot be reused under a subsequent Pipe scope.
- Hidden aggregate calls use the existing GROUP/HAVING collection and checker.
  JOIN uses the existing shared-scope lowering. All type, NULL, capacity, failure
  and execution decisions remain common-owner responsibilities.
- The grammar/rules change updates their manifest and dependent metadata through
  existing generators. The independent canonical test retains the REPLACE
  predecessor. Existing Program identities are not relabeled as the new grammar.
