## Scope

This private caller connection starts from main `1887855e9bf867ba9c3abb724dc52ebe4be3daa1`, which contains #1460, #1462, #1463, #1464, #1466 and #1467. The final merge destination is main. The resident CLI accepts the optional, independently operator-selected `--effect-review-root` and `--effect-catalog-root`. Both nonempty roots are required by this finite configuration path. Missing configuration supplies no policy or grant and leaves original task responsibility pending. Source, Resume and Local issuer settings are not fallback roots.

`run_holder` passes the existing execution's unchanged output-export limits, actual SQLite library and publication Store to the private callback factory. Creating callbacks performs no file read, service installation, Provider request or grant use. Policy loading is lazy: the existing serving loop checks its separate evidence permission and obtains genuine original completed consumer/producer custody before invoking the Catalog callback.

The first genuine original consumer pins the selected policy to its exact dispatch. Policy files are admitted by the existing loader; Catalog grant signature and original scope are admitted by the existing installer. The policy continuity callback also feeds the Catalog installer's existing current predicate, so later configuration changes cannot authorize a stale read merely because the original Catalog files remain unchanged. Snapshot continuity is not evidence-disclosure authority.

Acquired Catalog handles transfer immediately to `HolderEffectCatalogReviewCustody`, including an authority change during setup. Existing task cleanup retains failed handles and returns reservations only after the relevant Owners confirm cleanup. No additional custody list, scheduler, Ledger, permission or cleanup evidence is created. Publication receives policy only for the same selected original dispatch and derives its URL from the genuinely persisted original report.

## Authorization remains unconnected

The production invocation still does not supply `effect_evidence_read`; its existing default remains false. Consequently, setting the two roots alone does not invoke Catalog acquisition, Review observation or publication. Run admission, original/current custody, configuration snapshots, Store authority CID and consumer binding CID do not substitute for the pending existing Host authorization entrance. Reviewer authority and Source permission also remain separate.

This PR does not make public Effect operational. Raw unadmitted Catalog response-body durability, approval-wait restoration, actual Provider I/O and final Result/release acceptance retain their own obligations. An installation exception is reported using fixed local reason codes without logging configured contents, keys, token paths or wire bodies.
