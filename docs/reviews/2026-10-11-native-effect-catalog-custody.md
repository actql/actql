# Original Native Effect Catalog custody

## Boundary

An admitted Catalog projection alone cannot replace the original describe
response after a restart. The Store factory retains the exact response bytes,
status, use CID and existing Catalog projection in the existing encrypted
private evidence custody. It uses the independent `effect_catalog` role;
Catalog evidence is never disguised as capture or Preview evidence.

The caller obtains the original binding, resource and use CID from trusted
retained Host/producer context. Restoration does not select those expectations
from the saved record or from a candidate response. The existing Catalog Owner
checks the named projection, body hash, use CID and binding before persistence
and after authenticated readback. Raw UTF-8 response bytes are preserved,
including decomposed Unicode and CR/LF sequences.

This factory admits successful status-200 describe evidence only. It grants no
Provider permission, Reviewer authority, approval, dispatch or Effect send.
Failed or uncertain physical requests keep their existing caller's unresolved
responsibility. Missing custody is a refusal, not permission to describe again.
Production holder policy installation remains a separate connection step.

## Original slot and Store authority

The scoped holding preimage is an ordered string array: the private custody
domain, actual Store authority, namespace, Provider principal, environment,
connection revision, organization, Site key and generation, Connector
registration and revision, resource origin, original invocation and dispatch
CIDs, original sync occurrence, and resource. It is distinct from the response
hash and encrypted nonce. The original use CID is checked independently during
restoration; changing it cannot turn a candidate response into original evidence.

The record appends the use CID, status, raw-body hash, base64 raw body and
existing Catalog wire. Closed decoding and exact re-encoding reject substituted
binding, body, hash, use, status, extra fields or alternate private spellings.
The existing private cipher authenticates the role and holding identity. Store
record, cipher and capacity limits remain unchanged.

## Cleanup

The existing Store transaction reserves and persists the encrypted body
atomically. Retry reads the original ciphertext instead of overwriting it with
a fresh nonce. Cleanup saves and confirms the tombstone before returning the
exact reservation. A failed cleanup retains the same owner and capacity.

The tombstone retains only the scoped holding and original reserved-byte count.
After encrypted-body retirement, restoration can reconstruct a cleanup-only
custody and retry the existing capacity release without fabricating encrypted
bytes. It cannot confirm evidence or persist the active response again. The
existing capacity Owner checks the exact reservation and prevents double return.
This is not a new Ledger or a new recovery permission.

## Closed-role consumers and parent

The changed closed-role consumers are:

- `adapters/host-common/private-publication-holding.mjs`: existing private
  holding preparation.
- `adapters/store-local/publication-store.mjs`: exact private evidence readback.

The existing cipher envelope, authenticated-preimage template and old roles are
unchanged. The interface is generated by `moon info --target native`.

The fixed parent is main `f17e9fb2c93c84d0008d09018692f2c0e3f90d17`.
This Store boundary uses no API introduced by the pending holder #1448/#1449
stack; its final merge target is main independently. Production holder
installation follows separately. No submitted parent head is rewritten.

## Evidence scope

The portable cases cover exact bytes, every binding field, original use, hash,
status, bounded closed decoding, an independent holding digest and cleanup-only
reservation metadata. Node cases use the actual Store and private holding
adapter for lost commit reply, readback, reopen, role separation and retirement;
their control fixture does not issue semantic Catalog evidence or permission.
Independent AES-GCM vectors cover the new role against all existing roles.

Matching Native Store/holder checks compile the authored SQLite/crypto cleanup
case and the existing consumers. That physical case is not executed by portable
tests. Its strict opt-in requires `ACTQL_REQUIRE_NATIVE_EFFECT_CATALOG_TESTS=1`
and the actual isolated SQLite/crypto fixtures; an early return is not evidence.
Native physical execution, TLS, Provider requests, public approval, Named Result
and formal release are not established by this change. No Heavy acceptance,
deployment or actual send is included.
