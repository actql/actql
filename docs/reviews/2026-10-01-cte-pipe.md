# WITH and Pipe CTE integration

## Baseline and scope

BASE_SHA: `e444d1e97bdbf6473a2bcf6011236521ccd0cc55` (origin/main, #125).
The implementation branch is `feat/frontend-cte-pipe`.

This unit connects WITH followed by a Pipe query and relational Pipe queries
inside CTE bodies. The adopted Pipe r1 query-head and placement rules permit
these forms. A single parser retains the source, syntax-node, CTE-count and
work budgets. A CTE body ends at its own parenthesis, and only the complete
query accepts a statement terminator. CTE INFER, recursive declarations and
Graph CTE bodies remain rejected. This does not add double-quoted identifiers,
real INFER execution, materialization, general nested WITH or a dbt runtime.

## Semantic mapping and independent evidence

| Input route | Existing representation | Acceptance |
| --- | --- | --- |
| WITH SELECT body followed by Pipe | CtePart plus ordinary Pipe operations | Unchanged dbt SELECT ephemeral consumed by Pipe |
| WITH Pipe body followed by SELECT | CtePart containing ordinary relational operations | Minimal `pipe-cte-body` reproduction |
| WITH Pipe body followed by Pipe | The same CtePart and query operations | Unchanged dbt Pipe ephemeral consumed by Pipe |
| Multiple declarations and reused CTE | Checked Stage Result reference | Existing SELECT CTE tests and Pipe chain scope tests |
| Forward/self reference, dropped range, missing column | Ordinary lowering rejection | Independent negative sources |
| CTE INFER or internal statement terminator | Original-source syntax diagnostic | Parser placement tests |

The lowering test authors a complete JSON Program independently of the
compiler and compares all four SELECT/Pipe combinations against it, then
passes the generated Program through the ordinary checker. The Values fixture
contains duplicate rows and nullable fields. CTE reuse retains one producer,
not a substitution that repeats acquisition.

The dbt acceptance keeps `project/` models and compiled source bytes unchanged.
Expected rows are authored in `probes/dbt-compat/cases.json`; comparisons keep
duplicates, check NULL and explicit order, and compare `Result.describe()`
columns including their full contracts and declaration order. `rows()` must
reach normal completion and agree with `all()`. Empty-source acceptance also
checks schema, so no row sample is used to infer types.

## Reproduction

Use the pinned repository MoonBit/Node toolchain and root npm dependencies.

```sh
moon test --target js -p actql/actql/query_syntax -p actql/actql/query_program
node scripts/local-checks.mjs changed
node scripts/local-checks.mjs run spec
npm run probe:dbt-compat
```

The probe packs five public packages using their prepack builds, installs them
outside the repository, and runs Embedded Local and real HTTP against a
synthetic DuckDB source. It preserves source SHA, compiled-source digests,
tarball digests and detailed results in `_build/dbt-compat-evidence/` before
reclaiming its own successful installation. No external model is invoked.

## Identity and remaining work

The Grammar Manifest binds the changed query EBNF and source rules, so dependent
compilation identities change. The 0.1 contract identifiers and machine Program
input remain unchanged. Manifest pins, normative import CIDs and canonical
contract fixtures are regenerated from source; existing golden Programs are
not rewritten from compiler output. There are no checker, planner, provider,
Run-owner or SDK execution changes.

Real INFER remains unverified pending A's formal executable handoff. The known
intermediate A SHA is not adopted here. Broader query, quoting and
materialization work is outside this unit.
