# Numeric derive through the existing compositional pipeline evidence

## Problem and resulting behavior

The bounded typed-pipeline evidence admitted six Relation operations. Numeric
`derive` already executes through `SnapshotMap`, but that operation could not
use the common generator, shrinker and independently observed composition gate.
Register one successful numeric instance and its local obligations. The existing
pipeline now checks seven descriptors with 49 directed adjacent pairs; no
operation-specific generator, shrink coordinator, Session law, chain law or
production Owner is added.

The admitted instance adds one fresh field equal to an admitted numeric source
field plus an integer in -2..2. It preserves NULL and declared nullability,
original fields, duplicate occurrences and their order. Arbitrary expressions,
shadowing, numeric ranges outside the bounded successful profile, and demanded
failures are not newly accepted by this evidence profile. Their independent
existing refusal, resource and Host tests remain necessary.

## Retained obligations and extension procedure

The first 86 fixed inputs are byte-for-byte the original six-descriptor corpus,
including case identities. The common typed generator contributes 28 additional
inputs containing `derive`; it supplies all 13 new directed adjacent pairs.
New IDs alone receive an `extension:` prefix if needed. All old and new concrete
semantic obligations must have actual witnesses. The complete union contains
114 inputs, 22 concrete predicates, 49 pair obligations and 41 empty outputs.

The new descriptor supplies premise admission, output contract, Program syntax,
an independent value oracle, argument generation and reductions. Five local
obligations require nullable NULL propagation, nonzero arithmetic with the
source retained, a downstream reference to the derived field with nonempty
result, duplicate/occurrence order preservation and the empty output contract.
The existing shrinker refuses deletion of a producer when that would leave an
invalid downstream derived reference.

The actual observation harness adds the `SnapshotMap` route only; it does not
contain the arithmetic oracle. The common consumer checks checked/kernel
schemas, selected route, every intermediate output, ordered final values,
child/parent work and stopped/cleanup correspondence. Adding a new operation
requires a reviewed local descriptor, independent expectations, its real route
and remaining algorithm/resource/Host obligations. Operation names alone do
not establish connection or ownership guarantees.

The corpus-retention wrapper is a shared change, not a zero-common-change
experiment. Its retained foundation is the original six-descriptor corpus;
this PR does not promise that arbitrary future registry changes preserve every
subsequently generated extension input. The same completion/admission procedure
must still validate any future extension. No test is retired and no past
mutation result is relabeled as new arithmetic-kernel mutation evidence.
