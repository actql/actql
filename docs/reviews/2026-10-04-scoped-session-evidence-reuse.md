# Scoped Session evidence reuse

## Acceptance boundary

The first executable reuse scope is the existing `mutations-js` action. Main
always runs all 26 registered actions fresh. Every selected PR still accounts
for all 26 obligations, runs the executable Lean plan checker, and authenticates
the complete inventory at the final required check. The other 25 actions,
JS/Wasm/native final correspondence, serial-chain and capacity campaigns,
pipeline partitions, public/Host and physical acceptance remain selected by
their existing rules. No production owner, ledger or compatibility path changes.

The comparison period is explicit: a full-main origin must first be compared
with a later full-main fresh execution under the same closed conditional input
contract. The later run's final check must confirm that comparison and the same
thirteen scientific mutation observations. Only after that entire main run and
its `check` job succeed can a subsequent ordinary PR adopt the later original.
The initial integration run, a partial/unconfirmed comparison, a producer-only
success, a PR origin or an internally matching count is insufficient. There is
no permanent dual-CI campaign or manual reuse switch.

`session-applicability-<run>-<attempt>-<revision>` contains the final consumer's
canonical observation. It is separate from the immutable Session source ZIP.
Authentication binds the actual run/attempt/workflow/repository, successful
final-check owner, source archive identity/digest, executed certificate,
complete independent catalog, original receipt digests, target/scope and
scientific observations. The main ancestor and full checkpoint jobs are
reconstructed from real Git and live Actions metadata. A candidate's supplied
ancestor labels or a current-run success cannot authorize cross-revision reuse.

Before execution, missing/expired/unavailable acceptance selects fresh work.
Completed identity/digest/attempt inconsistencies are refused, not labeled as
availability. After an action is omitted, its retained original and acceptance
are mandatory at final check. Original receipts remain byte-identical; the
candidate application and acquisition plan are separate. Reused work is labeled
`reused-not-executed`, with null current execution counts/time, never as a fresh
candidate mutation detection.

## Conditional runtime contract and effects review

`isolated-contract.mjs` fixes a finite reviewed experiment cohort, toolchain
pin, hosted image and kernel release. Current candidate inputs independently
bind actual source/configuration bytes and modes, recursive snapshot membership,
Node/Moon/core/shell/library bytes and internal link targets, image definition,
fixed environment and actual kernel/CPU profile. Product changes cause fresh
execution; they do not require a new experiment review when the registered
experiment cohort is unchanged. Changes to a fixture/oracle, unknown package
configuration, toolchain, policy or environment keep the affected action fresh.

| Reviewed cohort | Scientific effect and bound dependencies |
| --- | --- |
| `mutations.mjs`, `evidence.mjs`, `action-inputs.mjs` | Thirteen unique production replacements; fixed JS suites/filters; executed assertion failures; byte-exact restoration over the actual complete snapshot. Time and temporary/process identifiers are diagnostic only. |
| `session_contract_wbtest.mbt`, `session_wbtest.mbt` | Deterministically enumerated Session histories, counters, tokens, quantum, cleanup/error/retry and integer boundaries. |
| `bounded_session_contract_wbtest.mbt` | Fixed adapter observations, cumulative/delta work and completion/retry contracts. |
| `local_managed_set_wbtest.mbt`, `local_managed_nest_wbtest.mbt` | Literal row fixtures, expected values/order/ports, two-consumer and cancellation/cleanup steps through actual registered adapters. |
| `physical_graph_wbtest.mbt`, `local_managed_group_wbtest.mbt` | Compiled helper definitions used by those selected integration cases. Their bytes and all transitive production/package inputs remain bound. Unselected tests are not new execution evidence. |

This is a conditional trust contract, not a universal compiler/OS determinism
proof. It trusts the specified deterministic operations of the pinned Node/Moon
runtime, hosted Linux/Docker process/filesystem semantics, the bound CPU
architecture and collision-resistant digests, and deterministic verdicts of
the reviewed finite experiments under those semantics. `/proc`, virtual device,
clock and entropy facilities are not proved absent by copying ELF libraries.
The selected scientific verdicts do not use their values; process timing affects
availability/failure, never a successful substitute for an assertion detection.
Timeout, compiler failure, missing observations or failed restoration cannot
create successful evidence.

The image has no network or host mount, no inherited CI credentials, a read-only
root and fresh writable scratch. Actual execution verifies image contents,
environment, required shell startup and restoration. The fourteen reviewed
literal package configurations apply only to the exact JS/toolchain hashes;
native linker/stub options cannot silently authorize a native scope. No preceding
whole-installation residual is erased: the host runtime inventory and its Lean
byte-limit/MoonBit-link gaps remain open for the other actions.

Lean proves the conditional plan model and checks the actual mixed fresh/reused
obligations. It does not prove the JS dependency extractor, GitHub API, Docker,
compiler or all MoonBit production implementations. `tested-refinement` is not
promoted to `verified-refinement`. The mutation projection separately binds each
ID to its production path, actual suite/filter/target and assertion failure
count; thirteen unrelated detections are not the same experiment.

## Normal development and measurement

No contributor asks G for permission to reuse evidence. The ordinary selected
PR workflow prepares its candidate inputs, resolves the trusted main ancestor,
and selects fresh or qualified-original acquisition automatically. New local
obligations stay registered in the independent action catalog; descriptors,
scope and premises must not be copied from receipts. Unknown extraction/effects
require a reviewed policy change and fresh verification, not a guessed cache key.
The existing operation-specific semantics/boundaries and physical regressions
remain the contributor's responsibility.

Optional comparison downloads live outside `.artifacts/session-actions`.
Only an actually adopted source ZIP is retained inside that upload, preventing
recursive uploads of earlier comparison archives. Main artifacts contain no
adopted prior ZIP. Git inputs are read in bounded binary-safe batches; same-owner
receipts share API/ZIP authentication while retaining independent action/target
and original digest checks. There is no transitive receipt provenance ledger.

Measure the ordinary producer/final job and step durations, runtime inventory,
isolated preparation, image build/execution/inspection/close, checkpoint lookup,
archive transfer/inspection, acceptance lookup and final verification. Record
both archive sizes. Do not compare only the avoided mutation subprocess with
zero-cost reuse, or call the fresh integration run a measured speedup.
