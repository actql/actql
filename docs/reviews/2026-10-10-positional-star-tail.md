# Positional values through ordinary Pipe stars

## Counterexample and selected meaning

At main `9a6b103d28364b2d1a7aab6e6eadcba79ee2495d`:

```aql
SELECT 0 AS a
UNION ALL (FROM t |> SELECT -x |> SELECT *)
ORDER BY a
```

Independent input x=1,2 requires a=-2,-1,0. The unchanged star preserves
already evaluated columns, including anonymous columns; it neither names an
anonymous value nor reevaluates the negation. Main rejects this text with
`UnsupportedProjection`, while an independently authored ordinary JSON control
with two selects of the evaluated negation passes the common checker.
The saved two-case baseline is `run-wfXrKL` / `focused-test-aZraFt`, 1/2.
This is a frontend refusal, not evidence of a wrong executing Run.

The selected GoogleSQL reference is
`d82db99a923a46571f543a13899dc791a7b6f743`, `docs/pipe-syntax.md` SELECT
and `docs/query-syntax.md` SELECT/implicit aliases. It describes SELECT's
current table columns and anonymous expressions that cannot be referenced
by name. Existing specification `docs/spec/query-text.md` retains current-star
column order and materialized Pipe scope. This repair adds no new semantics.

## Minimal lowering repair

`positional_set_terminal_projection` walks backward through ORDER/LIMIT and
unchanged, unqualified single stars to the SELECT that supplied their values.
The existing positional scalar/aggregate/analytic slots and ordinal alignment
then apply to that projection. Existing star, DISTINCT, sort, limit and common
checker/runtime mechanisms perform their ordinary work. No SQL rewriting,
Program correction, new execution owner, capacity change, pin or wire change.

A qualified star, EXCEPT/REPLACE, an additional expression or other operation
is not treated as an unchanged star by this helper. Existing behavior and
scope checking remain in place; this is not a permanent language restriction
or a claim that those other compositions are fully connected. In particular,
WHERE-tail connection remains #1285's separate unmerged repair.

The existing private-output guard still denies receiver names that happen to
match generated physical columns. Duplicate authored aliases remain ambiguous;
an old input range is not restored by star. Public columns come from the left
set input, not private physical names.
