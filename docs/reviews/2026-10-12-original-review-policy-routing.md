# Original resident Review policy routing

Scope: connect the existing private Review policy and Catalog installation to
the resident holder caller. This does not grant evidence disclosure, approval,
Provider access, or permission to deploy.

The optional operator argument `--effect-review-root` names the fixed local
policy/grant files already read by the existing loaders. The control process
forwards its own arguments to the holder. A Program, poll body, proposed Review,
or Resume cannot select this directory. Without the argument the installation
is unavailable; without the independent current evidence gate the caller does
not load it at all. `effect_evidence_read` remains false in production.

After successful consumer execution, the existing task driver selects its
original producer, retained consumer, journal, and request. Only that context
may supply the existing Catalog grant's invocation and dispatch scope. The
loader composes the existing policy, credential service, Catalog custody, and
Store; it issues no new permission, Ledger, or execution responsibility.

The exact task's Catalog custody now retains its first publication policy.
Later progress ticks use that same Checkpoint identifier, lifetime, custody key,
and budget. They cannot select a replacement publication policy through an
independent dispatch callback. Both preparation and upload recheck the original
context and installed policy. After service acquisition, changed policy denies
use but does not discard acquired handles: the existing task cleanup retains
the installation and retries its close and Catalog custody cleanup.

The existing `observe` → `persist_and_retain_report` → typed ACK → original
Review upload order is unchanged. Artifact routing still comes from the
genuine retained report's Checkpoint and configured Site/generation route.
Existing Resume, row Ledger, final Receipt, Result, and release Owners remain
the only execution and cleanup paths.

Validation scope: formatting and matching Native CLI caller compilation only.
No Native executable, Provider request, crypto, TLS, Worker/Store integration,
public SDK approval, Result, release, Preview, or Hosted CI was executed for
this change. The current Host evidence authorization entry, reconstructed
physical Review/row handles, and finite end-to-end acceptance remain pending.
Coordinator restart with a retained live Site Review and full Site process
reconstruction must be reported separately; neither compilation nor original
wire readback proves either restart acceptance.
