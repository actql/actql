# Original computation capacity custody

This is the finite Native caller connection after the read-only extent primitive
in #1540. It does not adopt numeric representation coefficients, establish a
production funding profile, or complete public Effect acceptance.

## Original Owner and order

The existing capture binding Owner checks the original six contracts before
this connection accepts a Host-declared `ResidentEffectComputationCapacity`.
`contract_bytes` covers the extended canonical trees, their backing, and four
contract Strings. `control_bytes` covers the additional active six-reference
record and its funding/cleanup control. `workspace_bytes` separately covers the
bounded traversal frames, temporary six-reference array and extent descriptors.
The separate `max_utf16_units` bounds measurement of the simultaneously
retained contract Strings and canonical tree; it is not the Store wire limit.
These are independent representation bounds; encrypted Store length is not
their substitute. A positive envelope is not a proof of the Native layout.

The original CapturedDAG Ledger first retains the physical Store charge. The
same capture Owner is installed before admitting the metadata reservation, so
metadata admission failure retains the physical cleanup responsibility. Existing
`reserve_capacity` admits contract plus control retention and scratch before the
six-reference record or measurement is retained. Measurement uses the original
contracts and #1540, with the existing per-contract node/depth bounds and the independently
configured representation text bound. A contract within the unchanged wire
limit may have a larger combined retained text extent.
Measurement failure retains the same nominal token for cleanup and sends no
report. It does not create a replacement computation chain.

Repeated persistence requires the same declared envelope and live token. Store
reopening keeps that token. No new attempt/transfer/send allowance is obtained
from the byte-only reservation. The existing current input, evidence disclosure,
recipient/write and signing/send fences remain separate.

## Cleanup

Only successful existing Store cleanup records physical retirement. Failed or
uncertain cleanup retains both charges and all six references. After physical
confirmation, the original physical token is settled once, the six references
are dropped, and the metadata token is settled. Failed settlement retains the
same nominal responsibility; it neither reopens the body nor allocates another
metadata reservation. The active funding record is dropped after settlement.
The pre-existing closed capture handle in the task map remains a nominal handle,
not an additional retained computation graph.

The guard does not require producer `Released` before settlement. Existing
`ResidentSourceCompute.close` waits for its actual Ledger usage to reach zero;
capture cleanup therefore precedes that formal close rather than waiting for it.
Named Result, Source, receiver, borrow, Preview and Checkpoint retain their
separate existing Owners and cleanup conditions.

## Independent simultaneous control

The Catalog caller's seven-field `HolderEffectCatalogInitialUse`, the added
installation reference, and current/claim/save closures also exist on restore-only
paths. Their lifetime is not implicitly paid by the capture token. They remain
part of the original initial-use record/control/workspace envelope and its
separate Journal/Resource cleanup. Any adopted Host layout must account for their
simultaneous retention as well as this capture record. This connection chooses
no coefficient and does not close that numeric profile obligation.

## Refusal and verification scope

No supplied capture envelope returns `ComputationCapacityMissing` before Store
preparation/persistence. This is a private installer gap, not a restriction on
Programs. Existing production callers default to no envelope; no permissive
default, synthetic Allow or automatic profile is installed.

Four portable tests use small independent charges to check exact retention vs
scratch, no send/attempt allowance, crossed-Ledger refusal, atomic one-short
admission, missing components and overflow. An original issued ResultDefinition reproduces
the incorrect wire-derived text refusal and succeeds under the independent
measurement bound, without changing its wire/CID or any wire limit. The existing physical Native capture
and review fixtures receive explicitly test-only charges and distinguish Store
bytes from Ledger representation retention. Their reopen/retry and final cleanup
assertions remain strict. They also check missing configuration, unchanged token
on repeated persistence, changed-envelope refusal and removal of original extent
after cleanup. Native compilation is not execution evidence for those fixtures.

Actual layout calibration, physical Native/SQLite failure execution, formal
package adoption, Provider operations, public approval/Result/release, hosted CI
and deployment remain unperformed in this unit. Genuine unmerged parent units
remain dependencies; the final destination is OSS main.
