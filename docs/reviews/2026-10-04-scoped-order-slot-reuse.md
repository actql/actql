# Scoped Pipe ORDER BY slot reuse

## Defect and independent counterexample

Baseline: `a4132d64f9cd83022d38bcb9c4e79d981fb2f803`.

```aql
FROM records |> AS original |> SELECT -id AS id
  |> ORDER BY -id |> RESULT answer
```

For input IDs `[1, 2]`, projection produces `[-1, -2]`. ORDER resolves
`id` to that output, so its keys are `[1, 2]` and the expected Result is
`[{"id":-1},{"id":-2}]`. Reusing the SELECT expression instead sorts
on `[-1,-2]` and reverses the rows. DISTINCT materialization has the same
reference collision. Qualified `original.id` keeps the input meaning.

The [query scope contract](../spec/query-text.md#scope-and-lowering) requires
output-alias precedence and reuse of evaluated values without reevaluating
the SELECT expression. The adopted immutable range/AS rules remain intact.
The expected Program in `pipe_order_scope_test.mbt` is independently authored:
SELECT negates input `x`; a separate ORDER helper negates the evaluated output
slot. It is not generated by the lowerer under test.

## Repair boundary

Scoped SELECT retains its input binding snapshot and evaluated output bindings.
Scoped ORDER uses the existing SQL/JOIN `reusable_order_expression` check to
compare reference meaning before sharing a SELECT slot. Repeated ORDER
expressions still share one hidden slot. Hidden sort columns stay outside
DISTINCT and the public Named Result. This changes incorrectly generated
Programs; it changes no grammar, wire, contract version or law pin. Corrected
Programs can have different canonical identities because their operations differ.

This repair does not edit the assertion, terminal Effect, Source predicate or
JOIN-limit locations owned by the composition work in #273. The shared CTE
acquisition predicate counterexample remains a separate handoff. The aggregate
input-scope counterexample is a separate repair unit.

### Remaining execution boundary

```aql
FROM records |> AS original |> SELECT DISTINCT -id AS id
  |> ORDER BY -id |> RESULT answer
```

For IDs `[1, 1, 2]`, the independent expectation remains `[-1,-2]` after
duplicate elimination. Lowering and ordinary checking pass. A diagnostic on
the recorded runtime traced the first failure to
`adapters/local-node/strategy-bundle.mjs`, `runPrepared`, at
`strategyModule_local_ManagedStart`: `Execution(Physical(ExecutionLimit))`.
No task completes. `StrategyNotComplete` and `ACTQL_E_UNPUBLISHED_RUN` are
subsequent symptoms. The unchanged-expression DISTINCT control completes.
The diagnostic temporarily exposed the existing error cause in a private test
installation, restored the exact installed bytes, and is not product acceptance.

The positive DISTINCT fixture is retained unchanged. This PR does not raise
the Host ceiling, remove DISTINCT/ORDER, or alter independent expectations.
Its full packed corpus remains unfinished until this execution boundary closes.
