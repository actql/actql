# Resident completed holder connection

The resident `execute` holder distinguishes the original NativeSettled record
from a startable dispatch before entering the execution path. For the completed
producer it rebuilds the exact saved envelope, original Run and checked task,
then calls the standard-host restoration adapter around the existing Runtime.
It creates no new dispatch, start claim, execution evidence or Source acquisition.
The ordinary start path uses the same checked executor registry installer.

The saved envelope is admitted against current Site delegation and generation,
original attempt, Source identity, input binding and Run lifetime before Native
registry selection. An actual slot observer rechecks the already acquired or
inherited descriptor against the current private named file. A fresh opener
cannot take the lock through that observer. Closed, transferred and replaced
descriptions cannot authorize restoration.

The holder keeps one `ResidentCompletedAttempt` and Runtime through retry. Its
current port checks the physical slot, Site binding, original Run lifetime,
delegated authority and the existing durable cancellation record before and
during output restoration. A ready value enters the existing output/handoff
loop. Cleanup-only failures transfer the same Runtime to the existing cleanup
loop; pending acquisition retains the slot and responsibility, never another
execution attempt.

## Evidence and remaining boundaries

Selected envelope tests cover the original two-task producer and refusals for
another attempt, Site generation, Coordinator, grant, Source, expired Run and
missing materials. They are admission evidence, not Native execution success.
Actual Native slot tests verify non-acquiring observation, same description,
replacement/closure refusal and existing process/descendant handover behavior.
The Native resident CLI is checked and built with its actual consuming types.

The controller selects an absent completed producer from a checked retained
plan/transfer intent and its original saved envelope, using the existing queue.
Current delegation, cancellation, completed custody and the exact checked edge
are verified before selection; the recreated holder rechecks the actual slot.
A receiver status query does not acquire a holder or advance Transfer.

The saved start claimant selects the original process bundle holding. The
existing bundle Owner retains that exact identity idempotently; the same Runtime
returns it after physical cleanup instead of leaving the dead process holding
behind or issuing another execution claim.

Receiver reservation/borrow reconstruction after a committed handoff still
needs acceptance under that exclusive holder. A pending Runtime now keeps a
separate immutable cleanup-custody port tied to the actual exclusive slot and
original Site generation/runtime. Run expiry or cancellation can reconstruct
only the saved physical cleanup handle; a newer releasing/unknown journal
revision also follows this path before any readable restoration. Revocation
after physical restoration retains the attached release callback. Losing the
exclusive slot preserves responsibility and blocks physical cleanup and refunds.
A temporarily unavailable retained root retries opening only the original
cleanup handle, preserving its generation and content identity.

The existing real Native fixture can interrupt a producer after its completed
evidence and file custody are durable, select the same holder from the retained
intent and continue the consumer. It checks the original and recreated bundle
holdings as well as Source/executor counts and normal release. These checks are
not public Cloud two-task acceptance or generation-changing Site restart.
Formal five-package/Native adoption waits for merged reviewed OSS
source. The earlier Native diagnostic timeout and old #88 Runs remain separate
unresolved evidence. This change includes no deployment, merge or old-Run
terminal rewrite.
