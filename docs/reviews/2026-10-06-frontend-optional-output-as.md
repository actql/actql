No unmerged dependency or execution Owner change.

## Contract and counterexample

The selected GoogleSQL checkout is
`d82db99a923a46571f543a13899dc791a7b6f743`.
[SELECT aliases](https://github.com/google/googlesql/blob/d82db99a923a46571f543a13899dc791a7b6f743/docs/query-syntax.md#explicit_alias_syntax)
allow an explicit output alias without AS; Pipe EXTEND uses the same spelling.
This is the pinned language contract, not a claim about every hosted service.
The existing Program already supports named scalar, aggregate and analytic
projections. The parser previously recognized only AS followed by a name.

Counterexample: `SELECT 1 id, 'hello' label`. The independent complete Program
passes the ordinary checker, but the source failed before lowering. Pre-fix JS
0/1: `run-HsxmWa`, `focused-test-6MBniG`. Its expected Program is handwritten,
not generated by the compiler under test. A second independent Group Program
fixes `SELECT COUNT(*) n`; ordinary `NeedsInputs` remains the Host's proof
closure responsibility rather than being reported as execution readiness.

## Repair and scope

The shared projection parser accepts the same explicit name with or without AS.
It preserves quoted names and does not consume unquoted reserved GoogleSQL
keywords as optional aliases. The complete reserved list was compared against
the pinned lexical reference. This affects SQL/Pipe SELECT, EXTEND, AGGREGATE
and existing selected analytic projections. It adds no AST interface or
lowerer/evaluator special case. Name resolution, sibling visibility, demand,
column order and types retain their existing common contracts.

Unsupported clauses remain syntax rather than accidentally becoming output
names. Anonymous computed/function outputs remain a separate coverage gap;
aggregate and analytic outputs still require a name. No new public Result
name is invented.
