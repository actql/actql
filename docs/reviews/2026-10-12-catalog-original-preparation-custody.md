# Catalog preparation on original funded custody

The private Catalog installer must cover its original Journal record, control,
operator snapshot, scope, seven-field initial use, installation, current/claim/
save callbacks and their overlapping preparation workspace on the producer's
original Ledger. It cannot use aggregate spare Ledger capacity, an unrelated
token, missing Journal/Resource records or an unsent guess as funding.

The existing completed consumer selects its nominal acceptance custody through
the retained producer edge. `read_catalog_preparation_capacity` checks its same
Journal, confirmed acceptance, open byte-only token and current Site admission,
then reads the exact original dispatch and stamp. Original revision 0 or 1 is
accepted for this read-only preparation comparison. Revision 1 never becomes
another initial eligibility or claim, including a lost claim reply. Foreign,
missing/replaced, unknown and retiring custody refuse without reserving or
settling anything; the original responsibility remains retained.

The private installer requires an explicit trusted Host preparation envelope
before invocation/snapshot/service setup, and repeats that same nominal coverage
alongside its independent original/configuration current fences. No Host layout
or numeric coefficient is adopted here. Its existing caller does not yet supply
a reviewed envelope, so the default `None` stays unavailable. This is a missing
installation connection, not a language restriction on initial Catalog access.

The supplied bound must include the full lifetime above and the new captured
three-Int64 envelope reference; it must include concurrent original snapshot and
current file reread scratch. Wire limits and UTF16/heap/storage representations
remain distinct. A positive envelope alone proves neither actual layout nor
original identity, Host/credential permission, a Provider outcome or cleanup.
The existing same nominal cleanup and one-shot Resource claim/save remain the
only lifecycle operations. No new Owner, token, grant, wire or CID is introduced.

The new actual SQLite counterexamples cover one-short retention/workspace,
overflow, lost claim reply followed by restore-only preparation, and foreign,
replaced/missing originals. Native check compiles their definitions; execution
requires a separately authorized Native window and is not claimed here.
Portable original row-byte and byte-capacity cases remain independent of those
unexecuted physical assertions.

This child retains the genuine private Catalog/Local dependency chain through
#1536 and the published #1513 retry fix. Common coverage is the separate #1553.
The final destination is main after those genuine parents are accepted; adopting
main capture funding does not accept the private parents. Actual Native/Provider,
numeric production profile, package cohort, public approval/recovery/Effect/
Result/release and Hosted CI remain unperformed.
