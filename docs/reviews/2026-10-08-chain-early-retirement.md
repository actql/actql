# Conditional early chain retirement uses common evidence

The existing built-in chain reclaims a completed intermediate execution while its parent is running, retains the exact accepted output, and prepares the successor only after cleanup confirms. The original productive model admits cleanup only at parent terminal. Its source-bound certificates cannot establish this different lifetime by renaming the scope.

## Implementation and inherited obligations

`Retirement.lean` adds 19 conditional laws over the existing `RelationChain.State`. It reuses accepted child/control accounting and execution-responsibility laws. Its exact consumer propositions and axiom audit establish original-budget preservation, retained completed-output references, pending custody, idempotent retirement and no new Compute/successor after scoped stopping. Pending means an accepted, already stopped intermediate child; false/error projects to unchanged custody rather than new productive permission.

The original checker still audits its exact 54 laws, including the separate delayed-stop and pause contract. The companion audits 55: 36 shared Session/chain laws and 19 additions. Shared laws are counted once as inherited guarantees, not 55 new laws or 109 independent guarantees.

The existing producer executes the eight existing `relation_chain_lifetime_wbtest.mbt` cases per selected target, with its original Session, prompt, delayed-stop and pause fixtures. The final graph requires the separately executed model, exact finite reviewed coverage, actual target and current artifact digests. Model/fixture substitution, a missing test or premise, both-sided scope widening and a physical-memory upgrade are refused. Workflow selection, Session action catalog, product Owners and runtime fixtures are unchanged.

This supplies one reusable protocol/connection boundary for built-in numeric binding/group/JOIN and authored Values/UNNEST cases. A new eligible kernel needs its semantic, resource and connection evidence; it does not get permission to omit them. Common laws and the existing eight lifetime cases are referenced rather than copied into an operation-by-fault matrix. No old test has been removed.

## Limits and resumption

This is a formal contract model plus finite executed connection, not universal MoonBit implementation refinement. One owed execution does not include retained output allocations, metadata cursors, closures or physical GC. It proves neither a maximum-child physical capacity nor the complete reservation bound. Active-child cancellation, delayed stop, arbitrary family callbacks, liveness, foreign identity, child semantics and logical resource bounds remain separate obligations. Existing conservative fallback and all three-target acceptance obligations are retained.

Wasm/Native runtime, packed/physical acceptance, complete mutation campaigns and Hosted Actions acceptance were not newly run for this unit. Current local JS evidence is not an Actions original. Compatible later-main qualification, ordinary-PR `mutations-js` reuse, related-input fresh fallback and acquisition/authentication/checker-inclusive net savings remain the preserved external unit. No Actions origin polling, dispatch/retry, Ready or PR merge is performed. This unit does not report CI-time savings.
