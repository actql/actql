# Install the Provider grant after original Source capture

The existing producer invocation issuer uses the actual Source evidence and
capture start/completion times. Its invocation CID cannot be chosen in advance
for a fresh Run. The approved-row Owner requires the Provider grant to bind that
same invocation; a definition CID or another captured Run is not a substitute.

The Remote holder therefore opens its optional Provider installation on the
first exact Resume instead of before the Source start claim. Source acquisition
continues to use its own unchanged delegation, claim and cleanup Owners. Provider
permission is not Source permission or Reviewer approval.

The original signed grant must be available from the existing trusted issuer
and original Host context at this later boundary. The existing verifier admits
the envelope, and the installation compares the actual dispatch, attempt, Site
generation and runtime before opening HTTP/SQLite resources. A foreign grant
does not poison the retained installation or authorize I/O. The approved-row
Owner still validates the captured invocation and full request before sending.

Until configuration is available and admitted, Resume stays pending under the
same task/Review responsibility. A later explicit Resume may retry installation;
it does not reacquire Source, rerun Compute, consume a credential use or send a
Provider request. After installation succeeds, the holder retains exactly one
Owner and its original snapshot. Changed configuration does not select another
grant or refresh the original authority. Existing close/retry responsibility is
preserved until the installation's resources are confirmed closed.

This is an initialization-order connection, not grant issuance, Catalog response
custody, Review/publication installation or completed public Effect acceptance.
The source of the trusted signed grant remains the existing issuer; no signer,
Site operator or candidate wire becomes the Reviewer. Physical crypto, Provider,
restart, Result and formal release require their own acceptance.

The authored dispatch projections are scope tests, not signed authority or
physical I/O. Matching Native compilation checks the actual holder's deferred
callback. No early-return or skipped Native crypto test establishes execution.

The child follows OSS #1448 and its existing parents. Its final merge target is
OSS main; formal Cloud adoption uses the merged source and matching artifacts.
