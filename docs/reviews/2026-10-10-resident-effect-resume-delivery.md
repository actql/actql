# Original resident Effect resume delivery

The original retained holder now accepts a bounded common delivery body through
`NativeResidentEffectReview.prepare_remote_approved_row`. This feeds the existing
Resolution signature verification, approved-row Ledger and physical Provider
Owner. It does not grant execution from a transported claim or introduce another
resume ledger.

`prepare_remote_effect_resume_delivery` takes the original typed Checkpoint
report, the common Owner's verified approved Resolution, and the claimed resume
identity. Its canonical body binds the exact dispatch, report, Checkpoint,
Resolution, resume intent and claim generation/claimant. The dispatch CID already
binds the original Run, task attempt, input binding, Site generation and runtime.
No replacement Checkpoint, Run materials, Source read or execution attempt is
issued. The closed schema is registered with the existing Run protocol owner.

The receiving adapter requires the paired Store/journal original report and its
durable typed Accepted ACK. It re-admits the Resolution against that original
Checkpoint using independently installed Reviewer authentication, then verifies
the physical Host signature through the existing Native Resolution boundary.
The trusted current resume-observation port must separately confirm the delivered
claim, original identities and a current non-settlement fence. Delivered bytes
are never converted into that observation. The row retains this exact delivery
claim and fences it again during every subsequent send and reconciliation;
another envelope or an unfenced cached row cannot replace it.

Preparation performs no write. Current Reviewer/Provider authority, original
retained-input custody, lifetime, pending Ledger responsibility and saved-response
reconciliation remain with their existing Owners. Missing ACK, custody, authority
or current claim refuses preparation without making a new attempt or recording
cleanup completion. Unknown Effect outcomes remain reconciliation obligations.

The existing real Native retained-holder write fixture consumes this delivery
entry point. It retains its physical HTTPS/SQLite credential, exact saved response,
cleanup-pending and retry assertions. Additional counterexamples cover substituted
identity fields, a newer claim generation, a different claimant and settlement-only
observations before row creation. The portable protocol tests use independent
canonical inputs and syntax-only signature fixtures; they establish encoding and
common admission, not physical cryptographic authorization or Cloud acceptance.

The production Cloud resume handout and normal Site CLI review/Provider installation
are still separate connection work. This adapter is not a completed public Cloud
Effect path. Formal Cloud adoption requires merged OSS source and matching packages
and Native binary. Hosted CI and real Preview acceptance remain distinct evidence.
