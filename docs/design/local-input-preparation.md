# Local input preparation ownership

## Responsibility and scope

The Node Local preparation owner bounds construction before the ordinary SDK
snapshot and retains the resulting checked Program through dispatch retirement.
It is not a second evaluator, a Run permission, or a replacement Store budget.
The selected own-data numeric Values recipe invokes the existing parser,
normalizer, checker, lowering and installed sequence implementation.

Other frontends and input shapes must keep their existing semantics while
joining this ownership protocol. An inapplicable shape proof is not a language
restriction or permission to invent a resource grant. The presence of this
recipe does not establish complete funding coverage for every Local route.

## Inputs and outputs

An original input reference and the installed Local resource policy enter the
protocol. Work-authorized inspection produces checked extents, not authority.
The same preparation owns the SDK snapshot share, input document, parsed
indexed source, checked Program and retained sequence preparation. Read-only
capacity observations expose scalar counters only; no mutable Ledger escapes.

Installed contract originals contain validated immutable contract data. They
do not issue resources or permit dispatch. Request originals, installed
contracts and resource children are separate identities.

The installed sequence-contract original retains the registry wire, the three
extracted contract strings and their actual admission under the same runtime
and initial control. Host open borrows that complete original instead of
parsing the AoA asset and extracting those contracts again. The holder keeps
its current/runtime/control checks, and compiler manifests remain prepared
during installation. Later Request requirements reuse those strings without
issuing another admission or moving installation work into the first query.

The Environment composer retains its same-call body, exact wire and evidence
CID, runtime and actual checking original. Existing wire consumers and the
Host's private record projection use one constructor. Independently supplied
publications still require encoding, self-CID, size and semantic admission;
the composer's own newly encoded body does not need another parse or hash.
No path, CID or previous Host result selects a cached admission.

Host open uses that body while its complete input is unchanged. A changed
Model or Task result keeps its own document and evidence CID; changed Host
policy and Calendar metadata keep their original encoding rules. The final
graph/text/Calendar checker remains mandatory with its actual flags and law
CIDs. The startup body alias is cut before that check, without claiming a
physical release or changing failed-initialization custody. Same-call sorting
hashes each distinct member once, and needs no hash for zero or one member.

## Captured native Program input

The normal Node representation reader projects DATA from the SDK's detached
snapshot. Its own property descriptors never invoke a source getter again. All
JavaScript representation operations remain in the Node package; Source and
Program admission stay portable. This is an internal representation adapter,
not another connector authoring interface, Resource owner or admission proof.

The existing Source Owner constructs one source tree while measuring its byte,
node and depth bounds. It shares the original parser's Program-key decision,
including the root-anchored Effect literal-key exceptions. The raw DATA reader preserves literal keys by default; supplied Parameters
select the same existing Local admission key policy as textual Parameters. Each Number uses the existing scalar-domain conversion;
there is no second whole-input serializer or parser. In particular, the native
snapshot's rounded numeric value is used rather than an obsolete rawJSON token.
Native input has no authored textual coordinates; its spans are synthetic.

The Request parent adds one input-proportional Source/index expansion on its
original capacity before construction. Its bound comes from the same SDK
traversal's observed envelope, using the existing Source/index representation
recipes and shared tariff. The key inventory uses the observed envelope even
when a tighter node policy will reject, because enumerating an original object
retains all its keys. No policy-wide buffer, per-node current callback or second
Ledger is introduced. Fixed reader/call frames remain trusted Host overhead.

The existing Program controller retains that index and continues through its
ordinary structural decoder and checker. The original reservation, spent work,
input identity and cleanup remain with the same Request. A failed expansion or
typed admission is terminal for that preparation; cleanup does not recreate the
input or acknowledge unrelated physical children. This representation adapter
does not by itself enable every ordinary Node body/Parameters/options consumer
or establish complete work accounting or physical backing.

## Installation Source lifetime before Requests

Source configuration, runtime and schema material must enter their actual
initial owner before their constructors. A later Request or Row Run cannot
retroactively supply that initial overlap. The ordinary Host configuration and
cleanup registry, including `retainPreparation`, does not issue funded backing.
An installation-lifetime original borrowed by Requests must retain its actual
admitted lifetime, currentness and physical retirement, rather than a profile
flag or detached scalar credit. The Source Owner keeps its material recipe and
failed-construction/retirement duties; the initial admission and forwarding
must use the same existing accounting owner without a parallel Source Ledger.

The ordinary Effect loader uses that same initial material before reading its
profile and runtime identity, and passes its original configuration reader to
the installer. The awaited installation remains pending after the individual
file reads have physically closed. A reservation failure precedes opening the
profile; an installer failure retains the same initial cleanup responsibility.
This input-reader handoff does not replace the provider's declaration, Mapping,
Site or operation-construction obligations. Independent profile publication
and identity inspection retain their separate bounded-reader purpose.

An Effect installation keeps its declaration, generated Mappings and resulting
Check Environment on that same initial scope. The immutable checked write
declarations bound their complete coexisting construction before native Mapping
generation or Environment assembly. The existing Mapping generator still owns
its semantics; an equal copied context, Mapping list or Environment cannot
replace the retained original tuple. A failed construction does not retry on
that scope or refund its consumed work.

The selected Effect role defers Environment assembly until its Mappings exist,
so it constructs that Environment once. Published schema/facts and writes keep
their original text-reader and Common declaration/Mapping entrances; no native
view list is parsed or reserialized before the initial owner reserves it.

The RowEffect adapter retains this scope until the original Site's cleanup
completes. A rejected or false close leaves the same initial body outstanding.
The adapter and its loader projection forward the original managed Plan
preparer unchanged; a projection is not a second preparation or admission.

## Captured Parameter Values on the Request

value visits and combined key/Text units. Observing long Text does not invent
thousands of source nodes. Either actual envelope expansion grows the original

not invoke current again. These are conservative representation bounds, not
full work counts, allocated-byte measurements, physical backing or permissions.

## Native SDK snapshot handoff

The SDK remains the single owner of native JSON snapshot semantics. The Host
receives this call's frozen connection and original Request receipt before any
option, Parameter or input getter. Query convenience methods forward that same
connection rather than using the first connection attached to an installation.
The existing serializer observes its own native traversal; no pre-scan repeats
getters, `toJSON`, Proxy enumeration or boxed-number conversion.

An input-proportional data envelope grows geometrically on the same Request
reservation. Each actual expansion uses the shared representation tariff; an
individual field does not enter a Resource callback merely for being visited.
The native wire and detached JSON value overlap and remain covered together.
The original wire is retained from that serialization, before the detached
value is constructed, for the subsequent original-input handoff. VM-private
property enumeration and garbage collection are not physical reserved-memory
promises; regular input limits and the Host/process boundary remain required.

Only the SDK's one original captured value may proceed. A Host bridge cannot
skip the serializer, repeat it or substitute an equal-shaped copy. A failure
from the original Resource observer keeps its actual identity. A caller getter
or `toJSON` throwing an error with the same spelling remains an ordinary native
snapshot failure; an error code cannot certify Resource origin. Host lease
retirement retains the same receipt through failure and pending cleanup.

## Identity and currentness

Admission, ownership transfer, external callbacks, execution and retirement
check the original preparation and original input/child. Internal DATA access
does not require another external current callback merely because it crosses a
helper boundary. Checks around a callback that can reenter remain distinct.
Equal-shaped objects, copied records and a different installed runtime cannot
substitute for the original. The Common owner remains authoritative across
the SDK's derived request associations and the Node manager/handler/dispatch
holders. No serialized receipt recreates that authority.

### Request lookup within the existing producer owner

The installed manager indexes each original Request with a weak reference to
its producer. Its existing live producer inventory remains the cleanup owner.
Lookup checks that inventory membership, the same Request and the producer's
unfinished state after the normal Host current boundary. It also compares the
same Host's closing flags after callback reentry; it does not scan the other
live Requests or create a new current observation.

A bound Request cannot be rebound to another producer, including after its
original producer has finished. The weak-key association may retain that
minimal spent identity while the caller retains the Request, but its weak
value cannot retain a retired producer's payload. Clearing the original
request alias or removing the producer from the live inventory makes lookup
refuse immediately. Pending cleanup stays on the existing producer and Run
inventories; the index supplies no Resource, permission or physical ACK.

Stopping forbids new funded work and reservation growth. Cleanup may construct
its required wrappers and has a separate same-original check
that permits disposal after stopping while still rejecting an unavailable or
foreign child. A refusal, an exception, or a cleared JavaScript reference is
not evidence that the child's physical cleanup completed.

## State and lifetimes

The initial reservation precedes input inspection. Phase transitions resize
that same reservation before construction; they do not obtain a second pool.
Retained extents cover references that survive a phase. Temporary extents
cover the constructors that are actually live in that phase. Overlapping
owners are additive. Sequential phases may share capacity only when source
lifetimes prove that the earlier constructors returned and no temporary alias
escaped. This reuse applies to successful returned constructors; failure-owned
Issue, Cursor and raw-cause references remain funded while live.
Garbage-collection timing is never a refund witness.

The SDK may publish an immutable submission snapshot to its caller. The
publication receipt records that handoff; it does not revoke the caller's
value when the Host closes. Host-retained aliases remain funded until their
own cuts. Returning a consumed holder and retrying retirement must not return
the same accounting debit twice.

After adoption, the existing manager, handler and dispatch holders retain the
same preparation. A submission-journal failure before dispatch still requires
retirement of that original owner. Uncertain outcomes retain their existing
custody and retry identity rather than being converted into definitive refusal.

## Accounting granularity and ordinary adoption

Real files, FD/DB sessions, Store holdings, Buffer and transfer bytes, concurrent
operations and physical attempts retain their actual reservation, consumption
and retirement boundaries on the existing Ledger. Approval, currentness,
cancellation, Unknown and physical cleanup retain their independent meanings.
Neither an estimate nor a cleared language-level reference proves physical
capacity or retirement. Native arenas and Wasm linear memory that actually
reserve backing must continue to enforce that real capacity.

Input-proportional data and work use conservative, explainable estimates from
the original size, node, field, Stage, row and column counts and actual lifetime
overlap. Existing shared inventories and arithmetic remain the owners of these
calculations. Retain the original observed dimensions and quote once per
semantic phase or actual expansion; do not reparse, recheck, recompile or
reconstruct a Plan to recover them. Add simultaneous input/workspace/output
holdings, use maxima for sequential retired scratch, and avoid double charging
the same original backing.

Small fixed Records, Some/Result wrappers, tuples, closures, getters and call
frames are trusted Host/target overhead, not separate per-wrapper accounting
or proof obligations. Do not add an inventory, work receipt, external current
callback or phase solely for one such object. This overhead is internal policy;
callers and connectors cannot provide numbers to manufacture capacity authority.
Existing detailed control inventories are transitional implementation, not a
requirement to extend their census for each helper change. Their logical charges
do not certify V8 layout, operating-system allocation or RSS.

The implementation priority is the ordinary same-original
RequestPreparation -> CheckedProgram -> Plan -> Run -> Publication/cleanup
connection, preserving supported inputs and removing migrated fallbacks.
Missing fixed-wrapper census alone must not turn a valid feature into
Unsupported. Complete that path with real variable-data/resource bounds before
consolidating existing fixed accounting. This does not authorize bulk deletion,
changed caps, a second allocator/tariff or a replacement permission owner.

Acceptance uses one coherent source and matching artifacts: representative
normal/error/cancel/restore behavior, original parse/check/compile/Plan and
current/reserve/resize/FS/DB call counts, and separately qualified Node/Native/
Python latency and memory observations. Narrow component checks and formula
tables do not replace that ordinary acceptance.

## Remaining ordinary semantic check

After Catalog request admission, the same private registry can finish its
remaining Context, contracts, units and checked Program in one synchronous
semantic phase. It consumes the original registry once; it does not parse the
Program again or readmit the completed Catalog. The selected local checker and
its existing supported-domain refusals remain unchanged. This route does not
establish the separate Effect-checking or physical Host prelude connection.

Before entry, the owner caches an input-proportional collection estimate from
its admitted Program and schema-bearing Environment members. It uses the shared
container-growth estimate and representation policy, with fixed controls in
trusted Host overhead. The old Catalog/body backing remains borrowed. A refused
grow preserves the original and cached absolute quote; retrying does not repeat
the observation or semantic check. The estimate is conservative DATA, not a
schema verdict, permission, VM-layout proof or measured physical-memory bound.

Only the existing reservation boundary invokes external currentness. After that
callback returns, a cheap original-registry check prevents entry if reentry
consumed the original. The synchronous checker does not add callbacks at each
operation or helper. Its original success budget delta is recorded; a rejected
or incomplete check keeps an explicitly partial known-work observation because
some existing late-failure constructors do not commit their nested budget.
That partial observation must never be reported as complete failure accounting.

A synchronous take transfers the same outcome and work qualification, without a
second current callback or reservation release. The parent refuses retirement
of that successor. The later Plan/Run consumer must continue the same capacity;
clearing local DATA is neither physical cleanup nor a new authority witness.

The original synchronous compiler receives no new per-Stage callbacks. Its work
observation accumulates Usage only when each original lowerer returns. That

## Work and storage units

The existing representation policy supplies shared checked arithmetic for
variable containers, UTF-16 units and wire bytes. Its historical record-header,
reference-slot and scalar-word controls are subject to the granularity above;
they are not a model of every VM allocation. Opaque engine and selected
Host-service support must remain explicitly qualified.

Wire length, parser node support, retained values, publication metadata and
durable Store capacity are different quantities. For JSON value-node support,
UTF-8 wire extent provides a structural upper bound, subject to an explicitly
narrower installed policy; it is not an additional memory grant.

The Ledger exposes reserved retention/execution, held bytes and its stored
retention peak. A sequence of execution observations is a sampled maximum,
not a stored execution peak. Reports must identify the exact runtime/model
cohort and distinguish requested bounds, actual reservations and observations.

## Failure, cancellation and publication

Refused growth must leave the previous reservation intact. Cleanup preserves
original identity and requires witnesses for child cleanup, retained-alias cuts
and settlement of the same reservation. Their order follows custody: pre-adoption
alias cuts may precede child cleanup, whereas an adopted owner is fenced first.
A pending cleanup remains pending; a retry cannot grant
new execution or silently drop retained references.

Result publication and physical-stop observation are independent. A successful
Run can expose a Result before cleanup finishes. Tests must observe the actual
cleanup barrier and durable stop state rather than infer stop from an earlier
terminal-status snapshot. Current-version close/reopen must retain the exact
published result and identity; no old-runtime migration path is implied.

## Extension boundary

Additional shape recipes must enter the same original owner and use the same
units, checked arithmetic, holder transitions and cleanup witnesses. They must
not retain an obsolete evaluator or bypass a failed proof with an unowned
path. Source acquisition additionally needs its own native-session/resource
custody; a Compute quote cannot substitute for a Source owner.

## Verification boundary

Repository regressions cover exact and one-short budgets, foreign originals,
stopping versus growth, consumed-holder retries, concurrent failed submission,
caller snapshot handoff, actual public publication/readback/close/reopen and
streamed result count/value oracles. Source-runtime guards validate workspace
package realpaths, selected Core artifacts, canonical adapters and module
hashes. Separate calculators must match that complete model cohort before
their numbers are attributed to an executing runtime.

Source-only checks, diagnostic instrumentation, a different backend, and a
hosted distribution/CI gate are distinct evidence. None may silently stand in
for another.

reservation, plus its exact recorded bootstrap when present, may remain live.

reservation, with no remaining holding or delegation. Retired records and

retirement never resets or refunds that cumulative history. This is accounting
correspondence, still separate from physical stop and reader cleanup witnesses.
