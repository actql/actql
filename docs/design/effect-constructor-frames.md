# Effect constructor frames on the original control reservation

A fixed opaque-boundary footprint can declare a scratch-only member extent in
its existing immutable Effect Plan. The common MoonBit constructor quotes the
three borrowed scalar strings, bounded canonical JSON fragments and complete
UTF8 hash input, digest and frozen result. The fixed key/wrapper inventory is
bounded by 96 UTF16 units; escaped input uses at most six units per source
unit. It does not quote entries, response bodies or a reconstructed Catalog.

The Host passes only original member and operation coordinates. Core resolves
that same Plan's declared nonphysical, zero-transfer, unstaged member, requires
zero retained capacity, and selects its execution demand on the existing
control reservation. The original full control retention and idle-current
floor remain funded. The fixed selector method/context and coordinate vector
are included in that control inventory. No Grant, new child, permission or
currentness proof is created.

HubSpot declares this extent for its existing footprint callback. Its original
mapping selection and borrowed Catalog getter still run inside the funded
call. The subsequent Host footprint validation, normalization and identity
hash remain unchanged. Other callbacks and recipes, including legacy runtimes
without the selected entry, retain their complete generic construction demand.
The caller cannot substitute a host-supplied byte amount.

Entry and completion keep the original physical/current and reentry fences.
A successful completion returns only temporary scratch. A failed or pending
callback keeps its original frame until the existing cleanup completes; an
insufficient reservation never invokes the callback. This changes neither
identity bytes nor Account, capture, read, write or approval authority.

The existing Preview-input entry selects its frame from the complete geometry
of that exact producer-owned wire and the same Plan's original member input
limits. Its existing input quote owns the decoded forest and decoder scratch;
JSON parsing does not reconstruct metadata or run the entire recipe. The frame
therefore borrows that quoted scratch while the capacity combiner preserves
all control retention, the idle-current floor and the complete input execution
demand. Input refusal leaves both the original wire selection and usage
unchanged. A successful input is one-use, and only successful completion drops
its scratch; its returned forest remains retained. Later generic callbacks
still require the full original recipe construction demand.

Effect Ledger open has its own same-control frame. The logical-request-scope
owner supplies the exact existing hashing-writer/caller-validation inventory;
Common adds the original path conversions and its shared fixed Host-control
overhead. Fixed SQL/module strings stay borrowed and opening observes bounded
native scalar usage, not a JavaScript materialization of Ledger history. The
full existing retained, native/base/page demand and any already retained Preview
forest remain charged. This frame does not select the whole metadata/Receipt
parser maximum for an operation that does not run those parsers.

SQLite still acquires ordinary platform resources under its existing Store and
constructor owner. Its actual policy, schema/usage checks, transaction failures,
original primary and pending FD/native cleanup are unchanged. The quantity is
not a heap/RSS reservation or an exact stock-allocator guarantee; the separate
Host/Journal native service does not become an Effect allowance. Entry failure
never calls open, and callback failure keeps its same control frame until the
existing owner completes cleanup. A runtime without this entry retains the
complete original generic construction path.

Initial Ledger metadata is returned through a bounded SQL projection before
JavaScript text is constructed. The only accepted values remain the original
ASCII schema version and 71-unit authority CID; the native bound allows two
bytes per unit for UTF16 databases. Oversized values project to null and retain
the original authority-mismatch refusal. This changes no accepted metadata,
Store history limit, transaction or native cleanup outcome.
