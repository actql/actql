# Node Host observation boundary

The optional Node adapter is the initial O1/O2 implementation: metadata-only
Owner projections on public Embedded Local and HTTPS. It is not a new execution
Owner. Evaluation Evidence and empirical CBO have independent exits and controls.
Native, Workers and hosted multi-tenant export are not supported by this adapter.

## Owner facts and identities

| Observation | Existing source | Projection boundary |
| --- | --- | --- |
| Pre-Run check verdict | Common checker through `prepareSource` | After check returns; no invented Run or valid Program CID |
| Run admission | `client-request-journal.acceptDefinition` | After semantic admission commit; only a new admission initializes optional consumption |
| Task activation/completion | `strategy` activation and checked completion | Bounded internal hook after the confirmed operation; no output handle passed to exporters |
| Model physical attempt | MoonBit `model_execution` actual invoke / installed clock adapter | Paired physical facts around provider or preflight invoke; exact Owner attempt CID; no approval, capture, or replay time |
| Source acquisition interval | Existing selected Source adapter `open` | Inclusive acquisition time, including its validation/retention; not an inferred HTTP/DB request count or transport-only latency |
| Effect application | Common Set receipt / publication disposition through the installed Effect Site | Confirmed application fact with the original Run ref; interrupted adapters cannot supply a semantic outcome |
| Approval waiting | Dispatch owner with retained Checkpoint | Waiting event, not inferred permission or a long-lived span |
| Resolution | Installed Checkpoint owner | Committed resolution and original Run ref, not automatically resumed execution |
| Recovery | Existing journal/controller diagnostics and Run inspection | New finite ingress segment, saved caller link, actual observed state |
| Cancellation request | Installed cancellation owner | Accepted request is distinct from confirmed cancelled outcome |
| Run outcome / physical stop | Stable revision-checked `observeRun` | Copies Owner outcome/revision/physical close fact; no AbortSignal inference |
| Publication | Dispatch owner / committed Store index | `computed` maps to committed Result, not mere capture success |
| Cleanup | Dispatch `settleCleanup` | After retained execution/capture cleanup and required stop observation; distinct from semantic completion |

Task ordinals are not invented attempt IDs. Model attempts carry the existing
attempt identity. Other provider-specific attempt details are not inferred from
task ordering. Arbitrary Owner diagnostic details, resource usage objects,
locations and raw failures are discarded. Completed tasks reuse the existing
driver's measured elapsed time; ingress segments measure their own duration.
Discrete verified facts use correlated log records, including Model attempt
receipts. They do not create instant spans or duplicate Span Events. Only a
measured finite segment or task produces a duration span. Logical
work/accounting is not inferred from these clocks.
The selected `resources` measurement copies only the fixed six limits and ten
usage counters returned by the same nominal managed Run Ledger. Decimal strings
preserve the full integer range. The original Run and captured public-operation
context correlate that observation after actual row consumption. An unavailable
or retired reader and queue loss remain explicit; they do not become zero usage.
These logical counters exclude durable Store history, shared Host holdings and
JavaScript heap/RSS, and supply neither capacity nor a physical cleanup receipt.
Diagnostic-level `rows` observations copy only the selected request-Journal
reader's fixed owner, selection, kind, returned-row and unrelated-row counts.
The existing ingress context accumulates these scalars into one terminal record,
without a durable observation transaction per native read. Before acceptance,
it may retain bounded request-key and actual returned-row identity scalars under
the existing operation record limit. Only that same operation's successful
Journal acceptance can join matching authority/request keys to the original
Run. Actual returned identities are compared with that Run; an empty uniqueness
probe can join only its exact accepted Run CID. No additional read is performed.
Unknown unrelated-row classification and missing bindings stay absent when no
matching acceptance exists; an eventual or foreign Run is not a substitute.
Pending scalars retire with the existing context, and overflow makes coverage
unavailable. Contextless or late hooks never manufacture a new operation frame.
When accepted work outlives its ingress response, the installed dispatch and
continuation Owners retain that same optional context against their original
work Promises, including existing settlement callbacks. The physical-start
barrier is not the work-completion boundary. A retained observation neither
delays acceptance nor supplies a physical release ACK; failed resource cleanup
remains with the original Owner even after its work Promise settles.
An installed consumer may retain that same bounded context for its original
Promise or Result iterator continuation. Promise retention is idempotent for
the same original in that context, never awaits or replaces submission, and
releases on either settlement. Iterator steps and the original delivery cleanup
run under that captured context; the terminal row aggregate waits for those
original continuations. A failed cleanup retains its existing context until the
same close-only retry confirms. No successful usage is emitted for partial or
failed consumption. The existing segment and record limits still bound optional
retention, and disabled row observations acquire no continuation.
This lifetime is copied observation metadata, not Run authority or a physical
cleanup acknowledgement. Observation shutdown detaches it and records unavailable
unfinished coverage; it neither settles the retained work nor discharges its
original resource Owner. Contextless startup or sweep work cannot borrow it.
Their `selected-returned` coverage does not count database rows visited, hidden
aggregate work, other readers, parses or cache hits. A missing hook or lost record
is unavailable coverage, never an observed zero or a completeness certificate.
No row body, query, key or authentication material enters this projection.
The request Journal hooks its actual prepared `client_requests` gets, including
the two targeted reconciliation projections. Full-ref/full-row reads compare
the selected namespace, authority scope and Run identity. Request-key, CID-only
and partial-row reads retain their actual returned count but do not invent a
complete unrelated-Run classification. A failed native get emits no empty-row
fact. Startup aggregates, other Journal tables and Store/Checkpoint readers are
outside this selected-reader coverage.

Run ID correlation reuses only a positively resolved immutable identifier under
the complete namespace, authority-scope and Run-definition tuple in that same
operation and installation. The bounded holder contains copied identity values,
not permission, currentness, a prepared Run or a durable observation cache.
Missing and failed lookups are not positive facts; a new operation resolves its
own original. Excluded or already limited records do not perform this lookup.
The ending segment keeps the selected Run binding. Any real Journal read needed
to resolve its metadata is counted before the final row aggregate closes; the
aggregate emits with that private resolved fact rather than querying itself.
Retirement drops these identity aliases without acknowledging physical cleanup.

Measured Source/Model attempts use standard CLIENT span kind. Finite interval
boundaries do not duplicate lifecycle logs or spend the discrete-log allowance
merely because a caller polls status.
The Model clock hook receives only the common Owner's slot, attempt CID and
physical disposition. It is an installed internal adapter, not an application
processor, and cannot issue authority or replace the durable entry callback.
An observed returned response does not certify valid content, capture or
publication. Elapsed time does not fill unknown billable duration or usage.

The common projection copies fixed fields into a bounded queue and delivers
after `setImmediate`. The Host does not import an OTel SDK. SDK/HTTP propagation
is a syntax-checked transport header outside canonical requests and authority.
Delivery remains an application callback even on that later turn: it can overlap
another active public operation. The existing installed projection retains an
immutable callback-state identity, changed at callback entry and settlement,
with an active flag until the actual delivery Promise settles. Synchronous
application context callbacks also advance that identity. The same Host's Result
authorization consumes this captured projection to observe current Account
bytes after application reentry, or before a protected boundary while delivery
remains active. Unchanged Account bytes retain their original typed evaluation;
pure internal helpers, trusted reads and awaits do not advance callback state.
This state grants no permission and supplies no delivery or resource-close ACK.
The optional package uses private SDK providers and official protobuf serializers
with an explicitly bounded HTTP sender. Application-owned providers remain
application-owned and have the weaker contribution-only guarantee.

The observation projection's `actql-observation/0.1` version and private journal
`actql-client-observation-custody/0.1` marker do not change semantic preimages.
Configuration digest binds scope, limits, filters, correlation, sampler,
destinations and selected SDK revision. Destination URLs are not stored in the
journal. One observation connection is installed on one live Host at a time.

Selection and wire configuration remain observation-adapter concerns, not new
execution authority. The existing MoonBit Owners still decide admissibility,
attempt identity, accounting, cancellation, publication and cleanup. Operation,
measurement, correlation and attribute selectors only narrow copied facts.
Unavailable measurements stay unavailable; no exporter derives logical work or
usage from spans. Duration selection controls optional metric instruments, not
the truthful timestamps of the finite span being represented.

At the original Model acquired-evidence boundary, MoonBit may project a
technical failure kind from the same returned Result. The JS bridge forwards
that DATA with the already-read task, Unit and step through `dispatch_failed`;
it does not decode a compiler tag, repeat validation or observe current again.
Diagnostic selection may expose the code, phase and kind; task correlation
also enables the three ordinals. No body, Account, path or credential is part
of this projection. Missing or lost delivery remains unavailable, and neither
projection nor delivery failure replaces the original outcome or cleanup.

The optional Node package can explicitly select standard environment
configuration. It never overlays an application-owned provider. Generic
destinations enable traces only; signal-specific settings and exporter choices
resolve before SDK construction. Authentication headers are bounded transport
configuration, never observation fields. The managed Resource has a fixed
default and only three explicitly disclosed standard installation attributes
may replace or extend it. Read-only inspection reports keys and credential
presence, not their values. Unsupported configuration files, transports and
Hosts are explicitly reported instead of creating an implicit pipeline.

## Restart and missing observations

Optional custody is in the existing Client request database on a separate
SQLite connection/transaction. It references the original namespace, authority
scope, Run definition and caller request ID. Admission and telemetry are not a
mandatory atomic commit. Only a newly inserted Run may initialize consumption.
An idempotent submit, recovery or changed observation setting cannot replenish
it. Unconfirmed telemetry consumption disables further Run projection; Run
execution, capture, publication and cleanup continue under their existing Owners.
MoonBit defines equivalence of the already verified Run outcome, revision,
cleanup-pending and physical-stop facts. The optional SQLite custody keeps the
last bounded key atomically with consumed observation count/bytes. An unchanged
poll emits no new Owner event, including after restart or at an exhausted
allowance. Independent changes remain observable. Finite public request spans
still measure the actual requests. This diagnostic key is not a semantic CID.
An unavailable older optional custody layout or damaged cursor disables extra
observations; it is not migrated by resetting consumption. The semantic request
and Run records remain unchanged.

Caller SpanContext stores only fixed-size IDs and sampling flags. It is never
authority and contains no baggage/tracestate. Recovery starts a new finite
segment and links to that saved context. There is no durable span state or
promise. Loss counters identify unavailable budget, limit, queue overflow,
delivery failure and deadline discard. They are diagnostic, not completeness
certificates. Shutdown never reports physical settlement of a pending callback.
Physical observation-journal close is retained by the existing Host shutdown
owner. A failed close prevents retiring that Host generation; retry closes only
unfinished children, without repeating execution or successful closes.

The first profile is immutable and metadata-only. Explicit adapter close
revokes queued and not-yet-sent owned delivery and aborts outstanding sends;
already-delivered data cannot be recalled. Live disclosure reconfiguration, content redaction,
tenant routing, hosted export and recall of downstream buffers are not offered.
Application providers are not a way to extend the guaranteed managed boundary.

## Evaluation and bounded measurement proposal

Evidence capture remains independent of OTel enablement, sampling and exporter
success. O3 can later connect an authorized INFER capture to an external
evaluator using existing capture/Result access; this unit adds neither content
export nor evaluation replay authority. Missing observation does not imply
missing capture; a captured successful execution does not prove answer quality.

The [existing Relation benchmark](../../benchmarks/local-relation/README.md)
uses seven paired repeats, alternating candidates, with a fresh process and one
warmup per candidate. Its prepared measurement reports operation time separately
from warmup and E2E. It must not be relabeled as cold Host latency.

For a future, separately authorized OTel overhead diagnostic, use seven fixed
pairs (off/on), alternate order, and freeze source, workload, artifacts and
capture mode. **Cold** is a fresh process/Host/empty process-local cache and the
first request with no warmup; it does not imply an empty OS cache. **Warm** is
one unmeasured request followed by seven fresh logical requests on the same
Host, not retransmission of one idempotent request. Keep operation time, public
request-to-Result E2E, capture time, telemetry delivery and shutdown separate.
Do not run this measurement during builds or use it as an implemented gate.

An empirical estimate sidecar is applicable only to an immutable admitted
candidate set and pending request, with authorized bounded disclosure and its
own deadline/volume cap. Unknown estimates remain unknown. It cannot relax
admission, reorder approved calls or authorize dispatch/retry. This unit does
not implement that sidecar or any CBO sampling/training pipeline.
