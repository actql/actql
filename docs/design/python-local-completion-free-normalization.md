# Effect-free Local normalization evidence

The installed Local profile uses a distinct frozen catalog at
`spec/contracts/actql-effect-free-local-completion-free-catalog.json`. Its closed
schema and independently authored canonical preimages accompany the catalog.
The Resident Effect catalog, CID and applicability remain unchanged.

The original common checked Program performs a separate bounded audit of the
selected Source owners and typed operation/expression owners. The installed
slice covers one explicit Source or Values root, at most three stages, Filter,
Select and Derive, including ordinary typed add, subtract and multiply. It does
not install default or Invocation Binding completion, template
completion, implicit NULL, sole-view selection, other operations or additional
roots. Those paths remain explicitly refused for this publication profile;
ordinary checker success does not imply an empty completion inventory. Exhausted
audit work cannot issue evidence. These are bounded implementation applicability
limits, not new restrictions on language semantics or the overall Python Local
product's completion conditions.

The checked-expression extension uses one additional closed catalog,
`actql-effect-free-local-checked-expressions-completion-free-catalog.json`, for
the explicitly listed context-free operations already supported by the checked
lowering and execution owners. Fixed operation semantics, including ABS, are
execution semantics rather than source completions. The same catalog covers
their combinations with explicit casts and actually supplied Parameters; it is
not a family of catalogs for individual functions. Checked membership-list
auxiliaries are listed separately and their original children are still audited.
Run-bound query time, optional vector operations and unknown tags are not admitted
by this closed set. This is an implementation boundary, not a language ban.

The original traversal selects this identity only after encountering a listed
extension node and completing the entire audit. Programs using only the preceding
node sets keep their four original catalog and journal bytes. A new scalar does
not hide a default, template, implicit NULL or implicit Source selection below
it. Lazy execution does not exempt an unselected child from the preparation
inventory. Original binding origins, declaration and stage joins, single-root
and work limits remain unchanged. The inventory adds one retained Boolean; no
caller Boolean or successful type check can issue normalization custody.

The Group extension selects one further closed catalog for the existing count,
count-if and extrema reductions, including combinations with the checked scalar,
explicit-cast and actually supplied Parameter alternatives. It traverses every
original aggregate argument and filter, and charges each authored key and
aggregate against the same audit limit. COUNT retains its existing finite Number
result; this extension introduces no numeric conversion or reduction evaluator.

The original Group checker separately retains whether additional prefix keys
were supplied. Equal effective key sets cannot prove that those keys were authored.
Only the original ordinary Group with authored keys is installed here. Numeric
policy, ordered and collection reductions and WindowGroup keep their existing
completion, resource and execution obligations; their remaining connection is a
product implementation gap rather than a language restriction. The five earlier
catalogs and journals retain their exact bodies and identities for preparations
without Group. This catalog issues no Source, Account or execution authority.

SQL/Pipe CASE without ELSE keeps that field absent in the Common form. The
original parsed source distinguishes its synthetic END-anchored NULL from an
authored ELSE NULL. Preserving this distinction lets the existing Common
implicit-ELSE completion owner report the omission; lowering must not erase it
by manufacturing an explicit literal before the audit.

Explicitly supplied Parameters use a second closed catalog under the same Local
profile, `actql-effect-free-local-supplied-parameters-completion-free-catalog.json`.
The audit retains the original complete `BoundValues` owner and requires every
binding's actual origin to be `Supplied`, together with the same declaration
owner and original stage identities. It admits the existing typed `$param` node;
it does not insert a value or complete a declaration. Equal effective-value CIDs
cannot distinguish a default from a supplied value and therefore cannot select
this alternative. Existing unused-declaration refusal remains with the original
Program reference owner. Explicitly supplied nullable values remain NULL, and
Signed64 values retain their exact checked representation.

The parameter-free catalog and journal bytes remain unchanged. The supplied
alternative has its own complete catalog and journal identities, with the same
empty-entry journal shape, version and bounded audit. Restoration selects the
catalog from the retained nominal inventory; a saved CID or caller flag cannot
issue that inventory. The additional retained binding alias and audit traversal
remain part of the preparation lifetime and managed work, not physical cleanup
or execution authority.

An explicitly authored, checked `cast` is an execution operation, not a
normalization completion. The audit traverses its original child normally and
records its presence in the retained nominal inventory. It does not evaluate the
conversion or infer a target from a result value. Separate closed catalogs cover
explicit casts with no Parameters and with actually supplied Parameters. The two
previous catalogs and journals remain byte-identical when no cast is present.

Implicit NULL, template/default completion, implicit Source selection and
uninstalled relation operations remain refusals even beneath an explicit cast. A nullable
cast of an authored literal NULL retains that literal and checked target; it is
never an empty String or fabricated value. Execution failure, demand, bounds and
backend support continue to belong to the existing checked execution owners;
empty normalization evidence does not promise that an arbitrary conversion will
execute successfully.

Only the original Effect-free preparation can issue and retain the empty journal.
The nominal inventory retains the original checked owner; the cached projection
also retains the preparation owner. Copies and equal-input foreign preparations
cannot acquire its custody. The Local projection additionally validates the
original admission, compiled Plan and Run definition using the existing binding
Owner. No Program, Source material, authority or identity is rewritten.

Issuance and restoration are separate operations. Re-admission of saved bytes
requires the retained original projection, exact journal bytes and exact catalog;
it does not issue a new inventory or establish cross-process Run restoration.
Durable adoption must use the original material chain and existing restoration
Owners. A journal is not execution permission, a final Receipt or publication.
Effect-free completion remains one final Receipt, Captured Run and durable
publication, with original provenance and current authorization checked at their
existing boundaries.

Result publication consumes a live export pin from the exact captured Run. Equal
Result definitions or payload CIDs cannot substitute another Run. Source evidence,
observation, invocation, derivation, ordering and artifact issuance remain with
the existing portable publication Owners. Snapshot traversal uses their bounded
preparation and retains the original consumer pin; cancellation and cleanup do
not transfer responsibility to a new Owner.
