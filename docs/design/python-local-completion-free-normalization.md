# Effect-free Local normalization evidence

The installed Local profile uses a distinct frozen catalog at
`spec/contracts/actql-effect-free-local-completion-free-catalog.json`. Its closed
schema and independently authored canonical preimages accompany the catalog.
The Resident Effect catalog, CID and applicability remain unchanged.

The original common checked Program performs a separate bounded audit of the
selected Source owners and typed operation/expression owners. The installed
slice covers one explicit Source or Values root, at most three stages, Filter,
Select and Derive, including ordinary typed add, subtract and multiply. It does
not install parameter/default or Invocation Binding completion, template
completion, implicit NULL, sole-view selection, other operations or additional
roots. Those paths remain explicitly refused for this publication profile;
ordinary checker success does not imply an empty completion inventory. Exhausted
audit work cannot issue evidence. These are bounded implementation applicability
limits, not new restrictions on language semantics or the overall Python Local
product's completion conditions.

Only the original Effect-free preparation can issue and retain the empty journal.
The nominal inventory retains the original checked owner; the cached projection
also retains the preparation owner. Copies and equal-input foreign preparations
cannot acquire its custody. The Local projection additionally validates the
original admission, compiled Plan and Run definition using the existing binding
Owner. No Program, Source material, authority or identity is rewritten.

Issuance and restoration are separate operations. Re-admission of saved bytes
requires the retained original projection, exact journal bytes and exact catalog;
it does not issue a new inventory or establish cross-process Run restoration.
Durable adoption must use the original material chain and existing restoration
Owners. A journal is not execution permission, a final Receipt or publication.
Effect-free completion remains one final Receipt, Captured Run and durable
publication, with original provenance and current authorization checked at their
existing boundaries.

Result publication consumes a live export pin from the exact captured Run. Equal
Result definitions or payload CIDs cannot substitute another Run. Source evidence,
observation, invocation, derivation, ordering and artifact issuance remain with
the existing portable publication Owners. Snapshot traversal uses their bounded
preparation and retains the original consumer pin; cancellation and cleanup do
not transfer responsibility to a new Owner.
