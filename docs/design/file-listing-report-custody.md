# File-listing report custody

The completed listing requirements in [Source Evidence](../spec/protocols/run.md)
remain unchanged. Original five-field report correlation, the same captured
scan and funded lifetime are required for corrected report conformance. The
ordinary resolved listing path retains its original capability scope and
evidence bytes during corrected-writer activation. It does not satisfy those
report requirements, supply report authority or establish Model admission.
Missing original correlation cannot be relabelled as a completed empty report.

Only the dedicated accounted listing entry selects report backing after the
original Source Ledger reserves the supplementary envelope. The same Row
acquisition, capture and cleanup owner retains that backing and execution
allowance through evidence encoding. The explicit report-evidence issuer
refuses an ordinary resolved listing, including a genuinely empty one. Selecting
this path does not change the public seven-column input, Source permissions,
wire identities or the evidence writer's existing bounds.

The ordinary installed Host wiring does not yet provide the justified physical
report supplier or the Source-to-prefix dependency/debt handoff. Ordinary LIST
success must not be advertised as corrected report support. Report activation
requires those existing-owner connections and their physical lifetime checks;
neither a numeric declaration nor legacy Source evidence substitutes for them.
The existing closed-prefix guard remains required, and no new Owner, grant,
cleanup queue or Model funding profile follows from these primitives.
