# Published STORE target custody

The `published_store` Command selector resolves through the original checked
Mapping, Command and Catalog in the Check Environment. That static pair is not
a ResourceRef and does not authorize acquisition, preparation or dispatch.

The installed collection issuer receives that same opaque pair. It must check
its original installation, target, kind, scope and generation and retain its
currentness closure. Common accepts the issuer's original `CheckedValue`, not a
CID, selector string or a value reconstructed from the current configuration.
The Command input owner checks nominal pair identity, the non-null ResourceRef
kind and the original reference's current availability. It retains the checked
value so the existing bounded value encoder can emit the exact selector without
a second parser or a synthetic target field in the query schema.

The captured-input owner binds this projection to one original input set and
member. Proposal and Preview verification reuse the same captured Result rows;
neither creates a Result or repeats SET evaluation. Every row, finalization and
payload-proof use rechecks the original reference and input lifetime. A foreign
input set, even from the same Run, or an equal-definition foreign Run cannot
substitute its target. Retirement or issuer unavailability cannot turn a partial
proposal into a completed proof.

These projections add references to the original binding, checked reference,
captured input and proof. Their simultaneous lifetime remains part of the
existing Host/Run holding inventory; weak references, closed flags or successful
encoding do not prove physical release or provide free capacity. Field-target
Commands keep the existing row-only route and its encoding and work bounds.

The physical adapter must still retain and authenticate the installed issuer
and original saved materials across Preview, apply and restoration. Static
selection, projection and payload proof issue no permission, durable receipt,
restoration grant or replacement Run. Unknown, pending cleanup and nonresend
responsibilities remain with the existing execution and Store owners.

## Preparation, compilation and saved selection

The existing eight-field Effect target selection owner also admits checked
`command.target.published_store` occurrences. This deliberately extends its
previous UPDATE-only admission; it is not an interpretation that Commands were
already admitted. It adds no wire kind, field, identity domain, version or
second selection registry. Old UPDATE and absent-context instance bytes and
CIDs remain unchanged. Normative scope and document pins change with this
acceptance extension even though the closed structural schema remains identical.

Preparation joins the same installed publication to the checked occurrence's
original Mapping/StoreCommand/Catalog in the same nominal Environment. The
candidate retains that actual checked pair for capture. The eight fields carry
the concrete occurrence and installation evidence through the existing
Executable Plan, Compiled Plan, Run Definition and saved-material owners.
Restoration matches the saved header and checked pair from the saved Program
and Environment; it never resolves today's aliases or rebuilds selection from
current configuration. A saved CID alone cannot replace any opaque original.

One checked Program may contain both UPDATE and published-STORE entries.
Canonical ordering and occurrence uniqueness apply across both purposes; the
original header supplies the distinction without adding a discriminator field.
Cross-purpose or foreign occurrence substitution refuses. Field-target Commands
and canonical relation STORE keep their prior admission and omission behavior.
Physical installation generation/currentness, actual reference issuance and
current approval/send checks remain separate from static selection and saved
DATA admission.

The existing private current-facts projection distinguishes the actual
installation's `update` and `store` support observations. Its required purpose
comes from the original checked header, not a caller-provided selector kind.
Only the matching purpose is checked for each occurrence; a genuinely shared
installation may report both. This does not add a field to the eight-field
selection or change the existing installation canonical body. A Source-only
installation cannot manufacture a row-effect owner or claim `update:true` to
stand in for STORE. Missing original installation/current facts remain refused.

## Local file bytes and publication

Local STORE borrows Content through the same Run's original input binding.
The generated or captured Content owner selects its already issued reference
and consumes its own retained Store holding. A holding CID, equal wire or copied
input cannot choose a different Store or substitute for the current original.
The original reader remains under that owner's cleanup duty during callbacks
and after a failed physical close.

A source-free Values producer keeps its checked input and explicit original Host
data policy through compilation, Run admission and restoration. It does not
fabricate a captured Source or borrow Source capacity to open the Content family.
The existing registered-family selector covers the original enclosing Run; the
policy and completed generation still prove no permission to apply the Command.

The Local file child acquires descriptor-relative staging only after the
approved Effect caller has retained it. It streams bounded original byte pieces
without a text conversion. Publication occurs only after the Store has confirmed
the complete hash, version and original read FD close, and the same input and
authorization are still current. A delivered prefix never permits publication.
The existing create-only or explicit replacement rule applies at the atomic
rename; a partial or uncertain publication is not retried as another send.
Reader and writer physical duties survive cancellation or currentness refusal
until their own acknowledgements. These physical facts do not issue an Effect
receipt, Account grant or replacement Run.

## Saved Command Content

Cold continuation uses the saved original Program, Environment, compiled Run,
Run Definition, private Preview and captured member. The Command input owner
checks its declared Content field against that Preview's exact intended row,
not a newly evaluated SET expression or an expanded before row. The captured
generation supplies the original node, barrier, task, input, policy and quantity
correspondence. A Model call scope is not a substitute for this Command binding.

The installing Content owner re-admits the original Reference envelope under
its existing installation and validity, then the same Store confirms the
captured byte holding and all three private generation proofs. Its actual
issued Reference, not the envelope or a holding CID, enters the Common input
binding. Foreign Run, member, input, generation, Store or issued-reference
substitution refuses. Current Account, installation and original availability
checks remain separate from the immutable capture and are repeated before use.

The existing recovery parent retains each child before its first awaited Store
confirmation. That child keeps the same issued original and failed reader-close
duties through refusal, interruption or partial preparation. Physical write and
read children must retire before the parent closes its Effect Ledger. Alias
release does not retire durable Content or acknowledge another owner's cleanup.
The restored view deliberately provides no reconstructed live Compute pin or
shared-workspace loan. It cannot generate bytes, replay Source/Model work,
replace a Run, bypass explicit approval or resend an uncertain publication.

Unselected recovery preserves its existing synchronous validation path. Only
the selected Content consumer awaits physical restoration, and it does so under
the already retained original recovery parent rather than a detached callback.
