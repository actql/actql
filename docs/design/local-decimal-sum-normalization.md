# Original Decimal sums in Local normalization

The public aggregate domain already includes exact Decimal sum. A checked
Decimal sum derives Decimal(38, input scale); its exact coefficient accumulation,
NULL exclusion, distinctness, contributor filtering, final-domain failure and
workspace limits remain with the existing Group and execution owners. The Local
normalization audit must not classify those fixed operation laws as missing
Source completion.

The bounded relation capability admits `sum` only when the original checked
aggregate has a Decimal result. That result follows from the original Decimal
input admission. A Number value that happens to be integral is insufficient.
Binary64 sum and average still require their actual numeric-observation owner;
an empty or false-filtered contributor set does not remove that requirement.
This connection introduces no new arithmetic, evaluator, Source journal rule,
input conversion or execution authority.

The existing audit visits every original Group key and aggregate under the same
work limit. A private exact-sum marker retains the completed original audit,
including its Parameter origins, schema/operation ownership and other capability
flags. It does not repeat traversal or replace pending execution obligations.
Both completion-free and actual Sort/projection-completion paths select the
extended catalogue only when this marker is present. Programs without Decimal
sum retain their previously selected catalogue and journal bytes.

The complete preceding catalogue, closed schema and empty-journal fixture stay
available. The new catalogue changes only exact-sum applicability; its actual
Source/Sort/projection rules are unchanged. Real completion entries remain
required and retain their authored path, canonical body and original operation.
An empty journal for a fixed aggregate law cannot discharge unrelated completion.

The marker and its retained original audit remain live with the original checked
Program. Existing sequence, value, accumulator and output lifetimes are not
shortened by normalization. Successful audit issuance does not prove physical
execution, current authorization, cleanup, recovery availability or release.
