# Typed publication resource handoff

## Scope and responsibility

The active ordinary numeric Closed Values route carries the existing preparation
capacity into publication. It does not introduce another semantic executor or a
second resource manager. Common owns the nominal construction, snapshot and
validation handles; the fixed Node adapter projects them and the existing Store
owns durable commit and physical cleanup. This is a Draft-stage boundary, not a
claim that every Source, Effect, Content, static or restored route has migrated.

## Inputs and outputs

The installed manager exposes compilation and publication preparation only for
its exact request and prepared original. Result snapshots are obtained from the
original completed output and occurrence. Capture takes those snapshots and the
original contracts; validation consumes the same nominal constituent contracts.
Reopened Store inputs are admitted originals, not a retained in-memory capture
substitute. Small metadata limits, logical row-wire limits and physical Store
limits remain distinct; one large wire allowance cannot replace all three.

## Original identity

The original Run definition and invocation bind the publication holder. Equal
CIDs, equal JSON, copied wrappers or another concurrent Run are not ownership
proofs. A retained validation optimization requires the original matcher and
current issuer custody; a mismatch cannot silently select a larger validation
path under a metadata-only reservation. Store-loaded originals use their own
admission and validation path. No historical Run rewrite or compatibility
migration is implied.

Validating a restored Definition against a live compiled Run performs the full
existing binding check. When the restored contract has the same CID, successful
validation preserves the issued Definition and its original binding. The restored
contract does not become the live publication original. A compiler with no
binding can retain its admitted Definition, and an explicitly issued different
Definition follows the existing replacement path.

## Ownership and handoff

Existing manager and dispatch holders preserve the preparation while publication
borrows it. Typed snapshot, capture and validation continuations keep their exact
originals until finish or cancellation cuts those aliases. A returned contract
is not evidence that every temporary constructor has retired. Store content
groups, selected prepared handles, commit pins and durable references retain
their separate established duties; this resource handoff does not transfer them
by CID alone.

The publication constructor selects the existing managed Run and its private
preparation body role. The caller forwards that original Run and Prepared,
without supplying a second holder or retaining the input-construction owner.
Definition and invocation are issued once on the same Run; its retirement clears
the publication continuations before returning its body role. An independent
manager borrower can still keep the original reservation pending afterwards.

Reading that body's reserved extents observes only its own reservation token.
It neither exports total Ledger usage nor invokes an external current callback.
Publication growth remains the existing Resource boundary, followed by original
correspondence checks after any reentrant callback. These checks do not repeat
the external observation or grant capacity from another live borrower.

## Synchronization and currentness

Growth precedes the covered construction and uses the same reservation. Imported
provider calls are reentrancy boundaries: the fixed owner is checked again after
an imported call and before starting the next operation. Awaited validation and
Store work must preserve the original currentness checks. Refusal, late close or
a replacement request cannot mint a fresh permission from an old handle.

## Failure and uncertainty

A refused growth preserves the previous reservation. An invalid or unavailable
original fails closed; it does not cause recompilation or an unowned fallback.
Unknown journal, Store or cleanup outcomes keep their original receipt and retry
identity. They are not absence and do not authorize another write, another Run
or release of another owner's capacity.

## Cancellation and retirement

Cancellation follows the existing continuation and cleanup receipt. It severs
only aliases actually relinquished by that original operation and retries the
same cleanup when necessary. Result readiness and physical-stop confirmation
are distinct observations. Close/reopen tests must wait for the actual cleanup
barrier, not infer it from a terminal Run status or a cleared JavaScript field.

## Resources and scratch cut

### Live occupation, identity and spent budgets

The same Ledger distinguishes pending attempt allowance and current reservation,
delegation and holding occupation from consumed attempts, work, transfer and
uncertain usage. Trusted Start consumes the original reserved attempt once,
including a zero-byte operation. Returning unused allowance or confirming
cleanup can decrease occupation; it cannot refund consumed or uncertain work.
Byte-only preparation and read capacity do not establish a physical attempt.

Task registration is likewise preparation. The installed driver consumes the
same task's pending attempt immediately before its first possible physical
use. Later bounded advances use that original debit; an empty result does not
make the execution free. Repeated notifications after currentness reentry
preserve the first immutable completion, including its unreclaimed scratch.

Reservation and holding identities advance independently of reusable inventory
slots. The same owner's builtin ordered Map indexes original serials; removal
still compares the actual token reference, so an equal key authenticates nothing.
The scalar ordinal view is rebuilt only when a later indexed reader needs it.
Appending or retiring tokens neither searches occupied slots nor shifts the
remaining inventory. The last-holder count indexes only actual live holdings;
consumed attempts, work and uncertainty never enter that count. Removing an
expired record clears its actual reference; the index is neither a new identity
nor another grant. A closed reservation remains
in the live inventory while a retained output still needs its original binding.
The last holding's retirement can remove that record, while the issuance cursor
continues to exclude stale identities and fresh-prefix reuse.

An imported current observation may synchronously reenter the same Ledger.
Final open/live, quota and bound checks therefore follow that observation.
The subsequent debit and any internal component mutations invoke no second
external callback between validation and mutation. Copies, closed originals
and another Ledger remain invalid.

A handed-off Model Read observes its existing input lifetime rather than
readmitting the whole Run. The same registered byte-only capacity reservation
may grow through the existing checked preparation/publication entrance while
its immutable body remains borrowed. Its original Ledger and opaque token must
still match the inventory, its original minimum extents must remain covered,
and all non-extent snapshot fields must stay unchanged. A serial only selects
the inventory slot; equal serials or equal extents do not authenticate a
replacement token. This continuation rule excludes regular attempt
reservations, shrunk or closed capacity, changed charges/quantities, and
uncertain or pending cleanup. The original bootstrap and Read snapshots,
initial admission, current callbacks, Source/Model provenance and cleanup
fences retain their existing checks.

Private snapshots carry issuance cursors, pending allowance and live counters
separately from spent totals. Backed-child DATA distinguishes current occupation
from the actual last observed final census: a later domain-stop acknowledgement
does not rewrite that earlier observation. All original bootstrap envelopes must
fund reusable control backing, scalar indices, snapshots and overlapping read
controls before use. Bounded slots alone establish neither those coefficients,
physical backing, process RSS nor coverage of another backend.

### Effect durable Store usage

The SQLite Effect Store keeps a connection-local TEMP projection of the original
entry, physical response, batch member and outcome counts and encoded bytes.
Each existing writer transaction checks the unchanged Store limits and advances
this projection by the exact inserted rows and bytes. The business mutation,
totals and external-version stamp share the same commit or rollback; there is
no JavaScript post-commit usage cache and no additional persistent Store format.
A lost commit reply retains the existing unknown/connection-usability outcome.

Opening a connection admits the full original durable inventory. Within each
later writer transaction, an external main-database commit detected through
[SQLite data_version](https://www.sqlite.org/pragma.html#pragma_data_version)
requires that same full observation again before a quota decision. The version
is meaningful only on its original connection and is stored with the TEMP
projection, so a refused mutation cannot leave a newer version stamped over old
totals. Concurrent connections keep their independent observation boundaries;
this mechanism does not claim to remove full observation after external writes.
The projection advances text totals with SQLite's original native-encoding
`LENGTH(CAST(... AS BLOB))`, while each preflight retains its original UTF8 input
increment. Existing UTF16 databases therefore keep the original quota decisions;
JavaScript does not substitute a different storage-byte model.

Stored entry/outcome text and response bytes are bounded in their original SQL
row projection, before oversized columns cross into Node. A rejected column
remains a present row with a null field, preserving the original integrity
refusal instead of becoming a missing record. UTF8 databases use the existing
byte ceiling; UTF16 databases use the corresponding native text-backing ceiling
so valid ASCII and Unicode are preserved. The original exact UTF8 check and
physical digest admission remain after projection. Paged metadata uses that
same native per-entry ceiling; its separate aggregate page budget retains the
existing native-column byte metric. Physical digests, canonical
admission, claim/CAS, reply-loss recovery and the original database close owner
remain independent obligations.

### Checked Local demand

The installed Local preparation retains one checked sequence inventory for both
its capacity quote and actual dispatch. A closed row bound is independent of
the cell domain. Number, Boolean and Text cells have a separate JSON-leaf node
proof; text byte admission, evaluator work/depth and schema metadata retain
their own bounds. Numeric fixed-width wire proofs are not applied to Text.
Nullable leaves need no extra value nodes, while nested/opaque domains retain
the general node policy until their recursive bound is proved. Copied demand
facts or another sequence inventory cannot replace the retained original.

The plan's additional holders and temporary proof carriers are included in the
existing preparation representation inventory. Neither a lower logical quote
nor this control inventory establishes a heap, RSS or latency saving.

The selected logical tariff prices record headers, references, scalar words,
UTF-16 storage and wire bytes; it is not RSS or an allocator guarantee. Snapshot
and capture constructors are funded before construction by the original
publication owner. Retained output and metadata remain charged while reachable.

Completed-output finalization may require multiple bounded disposal steps. Its
original progress witness must confirm that Values and completion scratch have
been severed before their execution reservation is cut. Cleanup accounting moves
through the existing imported child Ledger; clearing a slot, reporting success
or observing GC is not a refund witness. Publication then grows the same owner
for its own constructors rather than retaining the previous scratch peak forever.

## JS representation

The existing generated binding readers decode the actual MoonBit ABI, including
boxed generic Option values. Fixed Node projections validate arity and scalar
shape, preserve nominal tokens and keep cancellation in the same finally path.
The JS representation facet documents this translation only; it does not replace
the functional owner's identity, Store, currentness or resource obligations.

## Extension and pending work

Generic Source/Content/Effect construction plans and backend API removal are a
separate staged successor. They are not active-plain funding evidence. Their
additional measured metadata fields, copied inventories, earlier retained
canonical Effect plans and generic checker families must be charged before
activation. The plain recipe must not silently fund those routes merely because
they share a type. Preparation/execution generalization and complete cross-backend
migration remain explicit completion work; valid existing routes must not be
rejected just to make an obsolete-path count reach zero.

## Logical Result selection across physical graph views

A Result transformation retains its original checked Program and Result
occurrence. A retained-input graph view can change physical targets and input
slots while preserving those originals. Selection checks the same checked
Program, the original Result occurrence and the exact Result index. Equal CIDs
or another occurrence do not establish that correspondence.

This check grants no execution or output custody. The existing captured Result
borrow, managed completion, live re-admission bridge, output occurrence, limits
and retirement checks still apply before an export can proceed.

A whole Source input can supply a physical graph view with new target and
input-slot vectors. Those vectors supply neither a fallback export nor another
publication owner.

## Verification

Registered tests cover nominal snapshot/validation custody, foreign originals,
imported-call reentrancy, refusal/cancellation, public close during validation,
actual publication/readback/close/reopen, and bounded completion-scratch disposal.
The focused source/interface projection checks syntax, hashes and reference
anchors; it is not semantic, installed-artifact, CI or full-distribution evidence.
A sparse checkout missing unrelated interface tooling or declared artifacts must
report that limitation rather than fabricate references or mark the full gate
successful. Runtime evidence must identify its exact source/model cohort.
