# Original Local update normalization applicability

The Local update slice extends the existing Checker and preparation-owned
normalization material Owner. It certifies applicability of a distinct catalog;
it grants neither observation nor write authority. The mapped-create catalog,
journal identities and restoration contract remain unchanged.

## Original owners and finite audit

The existing static Effect closure retains `CompletionFreeAudit` for update.
It combines the original computation audit with the original checked header,
Result bindings, Mapping rule/permission selection and admitted change literals.
All those projections belong to the same checked computation and static closure.
`LocalUpdateCompletionFreeInventory` retains that exact closure, rather than an
equal Program CID or a freshly checked copy.

The installed slice accepts one explicit Source or Values root, at most two
stages, Filter/Select/Values and the listed ordinary expression nodes. It accepts
one mapped update with an `id` Result-field selector, direct field changes or
authored scalar literals, and no Mapping conversions. The original computation
audit work, existing static closure work and the additional ownership/field walk
share a 10,000-work ceiling. This optional audit does not enlarge checking,
physical execution, Store or time limits. Exhaustion means `ProfileNotInstalled`.

The resolver's sole-view selection and typed template/implicit-null completion
remain `CompletionObserved`. Omitted writes cannot certify an empty inventory.
Other selectors, nested change literals, converters and unaudited operations
are outside this finite profile; their valid Programs are not language errors.
A path with actual completion needs its genuine journal or an explicit refusal.
Successful checking and a missing journal are never proofs of zero completion.

## Typed issue and readback

`issue_prepared_client_effect_local_update_normalization` extends the existing
preparation-owned issuer with a typed Local-update inventory. The same cached
`ClientEffectNormalization` has a closed private create/update inventory sum.
Each issuer refuses the other profile. Catalog selection derives from this
nominal original projection, never a caller boolean or transported JSON field.

Evidence extraction and readback require the exact preparation, static closure,
cached projection, catalog and saved wire. Readback neither checks another
Program nor issues replacement evidence. Foreign/copy projections and a journal
substituted across profiles refuse without altering the original proof.

The compiler and durable materials must separately bind this profile to the
original physical compilation, invocation, Run and request. The existing
mapped-create compiler/material inverse refuses update evidence; this
applicability proof cannot select that create Template. No alternate compiler,
grant, journal, execution Owner or recovery mechanism is introduced. Native
observation, approval, physical execution and cross-process custody remain
separate obligations of the Local delivery connection.
