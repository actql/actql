# Original installed row reader custody

The provider-neutral installed row adapter may select a supplemental ordinary
reader envelope in its existing trusted installation. Its private
`providerReader` contains the original Common `ExecutionCapacity` declaration
and one synchronous, I/O-free `prepare` method. Both are snapshotted once;
neither a submitted Run packet nor current configuration can replace them.
This declaration is DATA, not a reservation, adequate physical measurement,
permission or normal numerical profile.

The existing Common installed-capture planner seals the same acquisition and
declaration. The Host passes that projection into the original Run Ledger's
planning path. The same declaration then reaches the original accounted
RowRun start. Common checks the additions and reserves them before the reader
factory, request encoding, physical read or its child work. Missing capacity,
foreign preparation and unsupported listing/keyed profile combinations refuse;
there is no unaccounted fallback or JavaScript byte arithmetic.

After the RowRun enters Reading, the Host binds its one original response
borrow and cleanup observation before entering the reader factory. The factory
receives the original request, authorization/current callbacks, acquisition,
Run and nonce. It returns one original reader with `read`, `requestStop` and
`observe` methods. The Host captures their original receiver and functions
once and rechecks current read authority after preparation and before read.
Failure of the factory, method access or current check retains the original
RowRun and its reservation; it never retries preparation to reconstruct them.

The reader's `observe().cleanupConfirmed === true` must represent actual
retirement of that same reader and all escaped custody. It is not inferred
from method return, Promise settlement, cancellation acceptance, credential
Site close, frozen arrays, raw EOF or capture completion. The Host also keeps
its own pending read and stop Promises unsettled until their original
settlement. A pending or failed cleanup stays with the original RowRun's
existing recovery path. No replacement reader, request, Run, Ledger or send
is issued. Rejections are handled without turning them into a successful read.

Supplemental provider retention and workspace remain reserved through capture
and any Store, diagnostics, callback or raw-response alias overlap. Captured
logical rows can have their own downstream custody without retiring provider
raw history. A driver that still exposes success/error response aliases and
cannot observe their retirement must keep `cleanupConfirmed` false. It cannot
enable normal retirement merely by supplying a finite byte declaration.

The original Host/Run inventory includes the retained declaration and planner
pair, preparer and receiver, reader and three method references, request and
current callbacks, response borrow and its cleanup closure, pending read/stop
Promises and handlers, and any original failure. Their simultaneous target
layout and lifetime are part of the same selected envelope, not free control
bytes. Only after original Core close and capture cleanup succeed may the
Host sever its reader/method backreferences. This reference retirement is not
GC or a physical release acknowledgement of another Owner's resources.
## Installation publication storage association

The existing publication Owner has a separate closed storage-association DATA
codec for `installation_publication`. It retains the exact selected Local Store
contract, Store authority, actual private-key generation and
`publication-private` namespace without borrowing a Model/Run evidence purpose.
Its outer canonical bytes have a complete-byte CID; the embedded Store contract
keeps its existing serialization rather than being lexically rewritten.

The installing Host must obtain these facts from the exact admitted Store
instance while retaining that instance's read, currentness and failed-close
duties. Preparing or reading this DATA does not perform that operational
admission. In particular a private path, file mode, supplied key bytes or matching
CID cannot authenticate an original metadata acquisition.

The complete installation publication still needs its original publication
request, provider-owned observation/declaration membership, selected generation,
configuration/Site/Account/runtime correspondence and actual durable holding.
Cold reconstruction may create new local Catalog originals only after that
independent custody admission, without provider rediscovery. None of these
remaining facts is inferred from the storage-association codec or its limits.
The original Host/Store budgets cover retained source/fields, canonical writer,
hash frames, read tree and escaped wire aliases simultaneously; a codec ceiling
does not issue capacity or acknowledge physical retirement.
