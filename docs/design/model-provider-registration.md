# Exclusive Model Provider registration

## Project declarations and installed originals

The public `actql-model-tasks/0.1` registry is project DATA. The existing
Common project reader retains its exact original text and bounded, ordered
task-file and provider declarations, including the optional selected default.
It checks every entry, not only a task used by one Program. A provider type is
not an implementation allowlist, and an environment-variable name is not a
credential or permission to read one. An unresolved default is refused rather
than replaced with an ambient provider.

This read-only snapshot does not admit the referenced task definitions,
construct a CheckEnvironment, register a physical Provider, authorize a Run or
fund any holding. Consumers must resolve files against the original registry,
retain the actual selected installation and current configuration, and use
the existing task/environment and physical registration Owners. A later
registry with the same task name cannot replace a retained original. Nonempty
project declarations cannot fall back to the source-free/no-model profile.

The private Node assembly captures the two already admitted declaration handles
with the exact runtime that read them and retains the original supplied text.
Its runtime check does not establish file selection or physical identity. A
selected registry must be supplied, and an unselected registry cannot be grafted
onto a plain project. The capture has no constructor for caller-created Core
handles, does not parse JSON itself and does not issue new permission.
Its record, callback and original runtime/handle/String references remain part
of the existing Host metadata lifetime; capturing or garbage-collecting them
does not acknowledge physical cleanup or prove a funded envelope. Filesystem
acquisition, generation/current checks, saved-material admission and the
complete startup reservation are independently required before public use.

The private installed Host acquisition stage searches the selected directory
and its parents for `actql.config.json`. Only an acknowledged missing open
advances the search. A malformed nearer file, failed read or pending close
cannot select a parent's configuration. Each selected original is bounded to
65,536 UTF-8 bytes before Common admission; invalid UTF-8 refuses without
replacement characters or implicit BOM removal. The same admitted configuration
selects the registry file and state-directory locator, relative to that original
configuration file. It is not parsed a second time after the registry await.
The captured Common callbacks retain their original runtime receiver across I/O.

The existing bounded Reader owns the same file descriptor through read and
close. It captures the original close function and receiver before beginning
intake and retains them through pending close; replacing the method later
cannot retire that FD. If setup cannot observe a close function, the same FD
stays pending without intake. Only its close-only retry may repeat that
uncompleted observation, and a successful capture is never replaced.
The callback, receiver and capture closure remain part of the original holding
until acknowledged close, separately from escaped input and parsed records.
Pending or failed close returns its original retry/status handle, not
the text or a substitute project. A pending read remains pending; caller
abandonment does not acknowledge close. Configuration and registry acquisition
are sequential, not an atomic filesystem snapshot or an installation-current
proof. The returned paths and admitted handles are DATA/original references,
not task elaboration, a Provider registration, a resource loan or permission.

The acquisition envelope includes the current read backing, lookahead byte,
concatenated input and strict UTF-8 decoder workspace, then the original String
and Common parsed/admitted handles. Configuration originals remain retained
while the registry is read and admitted. Records, paths, fixed reader callbacks,
the returned runtime-check closure and any unresolved cleanup handle also
remain in the same Host inventory. A byte intake ceiling does not reserve this
overlap; the original startup/Run funding supplier must cover it separately.

## Original generation profiles and public Task normalization

The original installed Provider configuration may explicitly select a closed
`model_defaults` subrecord: an ordered `models` array of `{model,
generation_config}` and an optional `default_model` that names one entry.
Generation uses the existing Task reader's finite settings and safe integer
rules. Every entry, including unused models, is checked. The containing
configuration's own contract still has to admit the subrecord; this grammar is
not permission to extend an arbitrary closed Provider configuration.

Common's private-constructor profile is configuration DATA, not a registered
Provider or authority. Its resolution retains the exact profile original;
projecting selected generation with a separately read equal-wire profile is
refused. Byte, node and work usage is reported even when defaults are absent.
The transient configuration cursor is not retained by that profile; Host wire,
revision, contract, registration and currentness remain the original Host's
responsibility. This does not claim GC, physical release or a funded envelope.

An explicit public provider/model pair is atomic. Omission selects the original
registry default provider and only that actual registration's explicit default
model. Temperature/top-p/seed come from its applicable profile, never an SDK
default. An explicit Task token count replaces a default, even if larger;
independent hard ceilings still belong to original bound execution admission.
Current settings do not rewrite canonical Task identity or saved Run settings.

The existing bounded Run-materials codec retains the normalized Task inside
its original Environment and the original selected INFER execution contract.
The dedicated installed-INFER reader checks that same saved Program and
parameters, reconstructs the ordinary installed graph, and re-admits its saved
prepared invocation, authorization and complete Run definition CID. It does not
consult a current project registry or repeat default selection. The existing
single installed, non-serialized INFER form retains its exact wire representation.
A complete composed inventory uses the optional `infer_execution_contracts_json`
field, mutually exclusive with the single-contract pair. Each ordered entry
binds the saved execution to its checked task, stage and step. Distinct
occurrences may share the same Task and execution contract; omitting, duplicating
or reordering an occurrence refuses. Every projected graph must match the
ordinary installed inverse, and custom dependency graphs refuse before emitting
an unrestorable bundle. Other compositions retain their distinct original-material
paths; this is not a language restriction or permission to discard them.

A keyed entry additionally retains its original `native_read_profile` contract
JSON paired with its closed `native_read_profile_kind`. Only the original
`native_file_content_read` or `declared_file_content_read` kind is admitted;
missing halves, unknown kinds and kind/wire mismatches refuse. Node declared-file
profiles are never read through the distinct Native contract entrance. Projection
reissues the graph with the same retained acquisition/profile
and still compares the complete original wire. Restoration admits the bounded
contract and reconstructs the exact checked stage/input/join before the existing
issuer checks Source/schema/catalog correspondence. A profile cannot move to a
different Model occurrence. Entries without this optional field keep the prior
representation; absence supplies no default native profile. Removing a profile
changes the compiled graph and remains subject to the complete saved Plan/Run
identity fences. This material transfer grants no currentness, read or send.

A single keyed file-reading Effect Model also retains its original selected
`native_file_content_read` contract in `infer_native_read_profile_json`.
Restoration admits that exact contract and binds it to the same checked
Source/acquisition before rebuilding the existing keyed Model Graph. It does
not select a current installation or fabricate a default read profile. The
saved Template, compiled Plan, Request, Run and canonical material checks
remain mandatory; missing, malformed or foreign profile input cannot become
read or execution authority. Non-keyed material bytes remain unchanged.

The single-Model field keeps its existing wire representation for both original
file implementations. Its shared bounded reader selects only the original
Native or declared-file version and passes that same parsed value through the
ordinary complete contract/identity/nested-reference admission. Plural entries
also require their retained kind to match this admitted original kind. Neither
path tries multiple schemas, reparses for kind discovery or supplies a default.

When restoring pending Native approval, static Source Request values must keep
their original policy meaning in the rebuilt Plan. The trusted installed Host
verifies Core's exact reconstructed subjects before Graph/compiler construction,
using the same Source/view and literal/parameter-origin verifier as first use.
Saved policy CIDs do not supply this verification. The existing nominal binder
and policy-only continuation retain the checked Program and Parameters; neither
parsing/checking the Program again nor selecting a different Model is required.
An absent or declined proof stays Unknown and cannot bypass the original Plan,
Request or Run checks. This preparation grants no Source read or Effect apply.

Subject hashing/origins and measured descriptor/verifier output use the same
constructor inventory as ordinary Request preparation, backed before allocation
by the original restoration business entry. The complete existing subject work
phase covers inspection, measurement/rendering and each binder's logical bound;
restoration enforces it cumulatively without refilling per subject. Ordinary
Request callers retain their existing cumulative Resource receipt and the
policy-only continuation retains its distinct selected work bound. Partial
subjects retire on failure, while the original review owns outstanding physical
cleanup and its independent current/custody recheck.

The reconstructed preparation and graph are a new in-process nominal pair
which must be used together. A caller cannot graft the old graph onto the new
preparation, use an equal CID as physical custody, or adopt these materials as
current authority. The original request/restrictions, provider registration,
Store and Journal custody, resource admission, fixed input and current dispatch
gates remain mandatory at the physical consumer. This codec supplies none of
those permissions or cleanup acknowledgements. Ordinary Values and Source
readers keep their previous INFER-field refusal and absent-field encoding.

The private Node binding projects the Program from the actual compiled owner
and admits the retained check Environment and supplied Parameter Values through
that same codec. Its first-admission ticket is local to the existing runtime
control; copied DATA, another control or another preparation cannot supply it.
It captures the same opaque original request after Common checks both Program
and Parameter Values. Another request, even with those same two CIDs, cannot
consume this first-admission ticket.
The request Journal stores the material bytes and original Result data policy
in its existing admission-evidence row, atomically with the same Run and custody
commit. Duplicate acceptance requires identical originals; a legacy missing
original is not backfilled. The existing aggregate evidence bound also covers
these bytes, rather than assigning a separate uncharged allowance.

Reading those saved originals reconstructs the preparation, graph, compiled
admission and original Run as one pair and separately re-admits the saved Result
policy, checking Program and Parameter Values against the request re-admitted
from the same original journal row. The reader never selects current Task defaults or issues a replacement
authorization. That returned pair is not itself Host restoration: the physical
caller must still bind its original submitted intent, fixed input/Store/Journal
custody and independently current installation, authority and resource gates.
The existing stop, Unknown and cleanup obligations are unchanged.

Projection and admission overlap the retained Environment/Program/parameters,
execution-contract text, codec output, parsed cursors, checked compilation and
original admission evidence. Rechecking the installed graph is bounded work,
not free planning. Those holdings and decode/compile workspace belong to the
existing Host/Run phase inventory; a material CID supplies no numerical lease.
The Node ticket, its WeakMap entry, saved material/Result-policy Strings, journal
JSON/UTF-8 and SQLite copies, parsed saved input, restored compilation, returned
pair and concurrent original/reader workspace belong to that same inventory.
Freezing the returned DATA or forgetting a local ticket is not physical release.

The public input/output field maps normalize through the existing ValueContract
Owner. Their checked schema, not the shorthand text, supplies schema identity.
Neither normalization path manufactures missing data-handling policy, a prompt,
an installed Provider, a request reservation or mock answers. Candidate DATA can
precede actual Host registration where the original factory needs the resulting
Task identity, but the existing original registration and Task admission must
then bind the same captured configuration/revision, not a replacement.

The private Host may prepare configuration defaults before it registers a
Task-specific physical assembler. This stage captures the same three original
configuration records and runtime and uses the existing Common reader once.
It has no Provider or invocation callback. Its project Task view exposes checked
candidate materials, but not an installed check-Environment projection.

The later physical registration must explicitly adopt that exact frozen
configuration snapshot through the same preparation. Copied or equal-wire
records, another runtime/provider and a second installation are refused before
creating a Core Provider. The installed project view retains the same Task,
selection, normalization and Common defaults rather than rereading files or
reissuing their canonical identities. It projects the ordinary Environment only
after checking the actual installed Provider map and that original adoption.
Both the initial configuration-current predicate and the actual registration's
new-borrow/current predicate remain required. The latter must retain the exact
initial Host predicate, not another closure with apparently equivalent checks.
Ordinary legacy registration and
its single-attempt defaults reader retain their existing behaviour.

These preparation records, WeakMap associations, retained configuration Strings,
reader callbacks, Task views and binding closures belong to the same Host
inventory. Candidate and installed views may overlap; their aliases and the
original decode/normalization workspace must be included together. A spent
registration cannot move the candidate to another installation after failure.
This connection neither acquires Model input nor issues startup, capacity,
handling truth, egress, a resource loan, send authority or cleanup acknowledgment.

Records, per-model generation values, selection references, bounded parser and
decoder workspace, temporary name index, normalized wire and checked Contract
holdings remain in the existing Host/Run phase inventory. The default profile
does not define prices or supply a numerical lease. Physical preflight, Store
custody, Journal settlement, current authority and final send remain separate.

## Exclusive invocation mode

The retained private Node registration can resolve candidate Task defaults only
through its original record receiver and existing Provider map/current closure.
It captures the actual registration callback's runtime and Core readers, retains
the same three nonsecret binding originals, and attempts its profile read at most once.
The existing binding issuer and profile reader share one private Common DATA
record, so projecting generation with a separately admitted equal configuration
refuses. Missing runtime support/originals remains unavailable; legacy explicit
registrations do not acquire a default. New Task preparation checks the existing
new-Host predicate without cancelling an already borrowed Run on Host closing.

Reader ceilings are explicitly supplied, closed, finite DATA and snapshotted
before use. A cached original cannot be reused under changed reader ceilings.
The first attempt retains its bounds even on refusal, and a failed reader keeps
its exact original throwable instead of parsing again or accepting a larger
limit. Its bounded failure carrier/cause remains with that installation;
dropping a managed reference is not physical release. Reader ceilings are not
a reservation or the simultaneous holding envelope. Profile usage
reports its own parser/decoder work even without a selected default; the
existing binding's three canonical-original traversals, encoding and evidence
record remain a separate Host workspace responsibility, not free work.

The Common DATA record, profile/model/generation references, original binding,
reader-bound snapshot, four captured Core callbacks and record method remain
with that existing installation. Resolution adds its original-bound candidate
and a small usage/binding view; explicit token replacement may add one generation
copy. Current refusal retains the already read original rather than reparsing
new configuration. This synchronous candidate path performs no I/O and issues
no Task/Environment, restored Run, authority, resource loan, send or cleanup ACK.

The existing ModelProvider Owner distinguishes a synchronous fixture callback
from an asynchronous installed physical Provider. The variants are exclusive:
async registration retains no dummy synchronous callback and has no synchronous
fallback. A physical preflight plan must match its registered variant before
Entry preparation or transport. Existing synchronous fixtures retain their
original callback semantics.

The private Node installation chooses async by `entryPersistence: 'async'` and
omits `invoke` entirely. It must supply physical preflight, finite quantity
capacity, original provider binding bodies and the trusted raw-capture selection.
Missing originals or an unavailable async runtime refuse during registration,
without provider I/O. Common separately checks the response profile, Task and
installation binding, durable Entry requirement and finite request/response
limits before adopting the original async physical plan. Registration does not
prove current authorization, raw-capture permission or resource funding.

The original Entry, final send gate, raw-response custody, response decoder,
attempt settlement and cleanup owners remain authoritative. The same registered
Provider cannot silently switch invocation kind during preflight. In particular,
async startup without its durable preflight and quantity envelope refuses before
acquiring Model input uses or constructing a Model Ledger. Unsupported Decision transport
continues to refuse; neither variant supplies fabricated generation settings.

This representation does not advertise normal numerical startup, an installable
public Provider package or live Model support. Host-specific layout and all
simultaneous holdings still require the original resource supplier. Public
execution and package acceptance remain separate from private registration.

### Per-request raw persistence binding

The original Common execution prepares its finite request/cursor inventory
before issuing the complete prepared CallSet. A selected raw SDK cursor retains
one synchronous callback during its own preflight constructor; one execution
can therefore retain several such callbacks. The installed continuation binds
all of them once to its same original raw registration and selected Store. A
private nominal factory is consumed during that synchronous binding and gives
each request a distinct existing single-Call persistence port. Each port still
checks its actual Call against Common's registration and refuses another Call
or raw object. This is adapter projection, not another slot scheduler, send
gate, registration or Call. A directly supplied legacy persistence function
keeps its single-Call semantics.

The original preparation envelope must cover the callback-reference array and
per-preflight setter/cell overlap before preparation. It also covers the
one-shot factory descriptor and constructor workspace, each child port and
every retained holding reference: the count is the complete prepared inventory,
not the active window. The factory drops its original captures after the
synchronous attempt; escaped constructor callbacks cannot mint more ports.
Each child keeps its own raw/Store/read cleanup, and an unstarted or retired
child cannot retire a sibling. The parent keeps all original holding aliases
until Common confirms the entire operation's cleanup; dropping these aliases
is not Store data deletion, GC, capacity release or a physical ACK. Neither the
later CallSet nor a successful binding supplies that funding. Copied/foreign persistence
still refuses before any callback. A partial binding failure is one-shot: it
cannot retry already bound children, and unbound cursors remain with Common's
same cleanup census. The auxiliary callbacks are dropped after the binding
attempt or original cleanup, without claiming raw, SDK, Store or physical
retirement. A directly supplied legacy callback retains its exclusive route;
it cannot mix with deferred per-request callbacks.

## Public Task originals and applicable handling

Public Task admission retains the original decoded document, exact identifier,
instructions and checked input/output contracts. Its internal version is that
same identifier String; it does not parse a suffix or change legacy explicit
Task versions. The original project registry must name the same Task. Selection
uses either the complete authored provider/model pair or the same registry's
default provider and its actual registration's original model default.

The original installed configuration may supply an explicit `data_handling`
Envelope in each model profile. The existing contract-envelope identity reader
checks its original body/CID, and the existing Task handling constraints check
no-training, classifications, regions and retention. Every supplied profile is
checked, including unused policies. The containing actual configuration contract
must explicitly admit this extension and cover that model/endpoint. Integrity
and applicability are separate: canonical bytes alone do not establish policy
provenance, current installation, geographic processing or permission.

No policy is inferred from a provider type, SDK default or another model.
Missing applicable policy remains unavailable for public normalization; legacy
generation-only DATA stays valid without acquiring a policy. Mock must supply
its own original fixture policy, not a physical provider grant. Preparation and
saved Run materials retain the selected original policy/configuration and Task;
current replacements cannot rewrite the original Task identity. Existing Account,
egress, capability, reservation, Unknown and cleanup checks remain independent.

The installed project acquisition retains the exact issued project/runtime pair
in a private membership index. A copied project object or a different runtime
cannot supply that pair to the Task-file stage. The stage captures the original
Common readers and their receiver before sequential file I/O, reads each named
file with the existing bounded strict-UTF8/FD cleanup owner, and rechecks the
same installation currentness after the awaited read and close. A file declaring
another registered Task cannot replace the original named occurrence, including
when two registry entries name the same path. Common owns the declaration,
selection, applicable configuration/policy and normalized material identities;
the adapter neither computes a Task CID nor supplies an opaque constructor.

The finite Task count and per-document bounds limit acquisition and traversal;
they are not a simultaneous retained/workspace envelope or a numerical lease.
The existing installation must account for the project membership record,
captured callbacks, bounds, task inventory, raw UTF8 text, checked declaration,
selection, original Provider/default references, normalized Task/prompt material,
the checked-material name projection and current read/decode/hash workspace.
Previously loaded entries coexist with the next read. A pending close keeps the
same original FD/error cleanup handle; current refusal does not acknowledge
cleanup, substitute a Provider, or reread replacement configuration. The retained
Task material is not by itself an installed Environment, saved Run, execution
contract, physical supplier, permission or send admission. Those existing Host
assembly and Run owners must consume the same originals and retain them until
their original duties retire; recovery never regenerates them from current files.
