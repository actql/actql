# Managed checked-view preservation plan

This increment prepares finite column preservation along the actual checked
receiving path. It does not certify that kernels executed, create an output
receipt, or establish an output material binding. Production executor integration
and the final new-profile performance comparison remain incomplete.

The plan composes projection/rename, snapshot additions, ordered derive copies
and shadowing, filter, take, and sort. Computed columns have no inherited source
column. Ordered prior-slot references follow their checked value version, not
the final spelling of an overwritten field. Unsupported kernels require a
separate output-validation path; they do not acquire preservation evidence.

Selection preserves universal value bounds and established absence of NULLs,
but not exact source totals or the source maximum as an exact selected maximum.
Permutation preserves exact column measurements, not the original logical row
order or Result CID. No identity is manufactured by this plan.

Metadata composition has cumulative work and UTF-8 name budgets and a column
ceiling, including defensive expression-view copies. Kernels must belong to the
exact receiving owner and follow consecutive actual input targets. Matching a
schema alone is insufficient. Plan facts become unavailable when the input is
revoked; they confer neither authorization nor retention rights.

Independent expectations cover ordered copy chains and shadowing, a composed
select/filter/derive/sort/take path, nonempty permutation, selected versus exact
column measurements, metadata limits, skipped/foreign paths, distinct use sites,
revocation, and unsupported grouping. The initial failing test used forbidden
snapshot-map shadowing; it was corrected to the existing ordered-array syntax,
without changing language acceptance.

Next integration must bind these conditional facts to the adopted executor's
actual row correspondence, new-column validation, selected measurements and
exact retained output. Passing these preparation tests is not evidence that
consumer output rescans have already been removed.

Verification: execution_relation passed 430 tests on each of JS, Wasm and
Native; documentation and formatting checks passed. These are preparation and
regression checks, not a new-profile throughput measurement. No normative
preimage, contract pin, baseline or performance threshold changed.
