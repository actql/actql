# Exact resident value evidence reuse

Date: 2026-09-16. This increment preserves the existing CID-required contract;
it is not the new profile's CID-optional completion implementation.

## Implemented path

The common execution scan can now discharge full stored-value admission from an
exact, live, trusted immutable representation and its established receipt.
Admission usage is charged to the new consumer. When consumer value measurement
is attached, its exact ordered-view summary must also satisfy the current
ceilings and remaining budgets. Measurement charges commit through the existing
finish boundary, which rechecks representation availability.

Insufficient summaries leave the scan unchanged for ordinary ordered validation.
No violation or first-failure position is inferred from an insufficient bound.
New join validation prevents this shortcut. The DuckDB adapter also prohibits
it when a new comparison demand is attached. These obligations still run.

The installed resident Host attempts this path after acquiring its exact resident
read evidence. On success it issues no validation SELECT and does not transfer,
decode or remeasure those input cells in the Host. This does not skip the actual
consumer query. Fresh imports, changed views and newly created outputs without
the required measurement summary retain their existing paths.

Diagnostics distinguish `reusedInputValues` from `directInputScans`; a skipped
scan is not reported as executed physical work. Logical consumer accounting is
unchanged.

## Independent runtime acceptance

The real DuckDB standard-Host test uses the checked DAG and retained acquisition:
two count consumers read the same three-row captured input, then a filter reads
the first count result. Expected counts are literals, not generated by product
output.

- `reusedInputValues`: `[0, 1, 0]`.
- `directInputScans`: `[1, 0, 1]`.
- All three output CIDs equal the independently hashed `[{"id":3}]`.
- The final filter's demand work remains; cleanup is confirmed.

That test passed. Common execution tests additionally check both budget totals,
no retained row scratch, insufficient-budget fallback and revocation before
finish. The new path does not introduce a raw-data completion constructor.
The `execution_relation` package passed 407 tests on each of JS, Wasm and native.

## Paired component measurement

Reproduce with the pinned MoonBit toolchain:

```sh
ACTQL_RETAINED_VALUES_DIAGNOSTIC=1 moon test src/execution_relation --target js --filter '*values reuse paired diagnostic*' --deny-warn
```

Eight alternating-order pairs, first pair excluded as warmup; 10,000 receiving
scans of the same two-row immutable fixture per leg. Both legs already reuse
logical identity and successful canonical-value measurement. The difference is
whether stored values are traversed again. Each iteration asserts equal consumer
measurement charges.

| Pair | Existing scan (ms) | Whole-value reuse (ms) |
| --- | ---: | ---: |
| 1 | 13.238292 | 7.790625 |
| 2 | 13.101833 | 7.618500 |
| 3 | 12.590375 | 7.748833 |
| 4 | 12.275334 | 7.671167 |
| 5 | 12.004125 | 7.812792 |
| 6 | 12.001542 | 7.590500 |
| 7 | 12.004416 | 7.941708 |

Median: 12.275334 ms versus 7.748833 ms (about 36.9% less time).
This is a small warm JS component diagnostic, not DuckDB total latency, a large
case speed ratio, or the formal 1 GiB / 27-case acceptance measurement. No new
profile performance claim follows from it.

## Remaining scope

This exact-view path does not yet establish finite transform evidence propagation
for filter/take/sort/derive, direct native output admission, or complete
CID-optional managed execution. The registered large-case comparator and full
new-profile conformance remain separate required work.
