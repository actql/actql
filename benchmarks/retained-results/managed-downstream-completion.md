# Managed input to independent downstream completion

The connection after `6d9e5097` takes the actual native count output through
initial typed value admission, physical retention and common managed completion.
It is not a legacy Artifact and does not manufacture logical content identities.

## Product boundary

`ManagedInputDuckDBCompletion` accepts the exact managed query and owned common
completion preparation. Input measurement consumes retained column statistics;
output admission takes the remaining same ledger, once. Completion checks that
the output receipt carries that exact ledger identity and matches the exact
retained material. Another preparation of the same query is not interchangeable.

This connection currently admits the compiler's CountGroup realization, whose
existing direct demand rule requires row counts rather than predicate values.
At this increment FilterSelect did not yet qualify. The subsequent
[finite scalar-comparison demand connection](managed-filter-demand.md) adds that
path without rescanning the input column. General expression/transform support
remains unfinished adapter work, not a restriction of the agreed new profile.

Installed Host callbacks cover native execution correspondence and the separate
admitted identity/policy/resource obligations. They are trusted wiring, not
Program-provided evidence. Core validates binding, receipt scope, profile and
current material availability; it does not independently rerun DuckDB. Production
requirement derivation, physical representation registration and selected-attempt
dispatch are not completed by supplying these callbacks in a conformance fixture.

The completion port is one-use. Failed transport verification, policy denial,
cancellation and reentrant cancellation cannot later revive it. Input liveness
is rechecked after callback boundaries, including final authorization. A completed
independent material retains historical input bindings, not a live ancestor pin.

## Native evidence

The real native fixture covers empty and Unicode/NULL/duplicate input. Its count
output is initially validated and stored in a separate physical body. The combined
logical input/output ledger is respectively `[2, 1, 1]` and `[8, 27, 4]` for work,
value bytes and nodes. These are logical charges, not repeated physical scans.

After completion, the upstream material is revoked and its Store cleanup awaited.
The remaining byte reservation equals only the downstream body size. Two new
checked read consumers still read that independent count output, with real Store
pins released after each read. Final downstream revocation and Store cleanup are
also confirmed. Failed additional completion attempts do not undo that result.
Revoking the input from the final authorization callback rejects publication;
the completed port cannot be retried after that failure.

The Node test previously passed the `Result` wrapper from `managedFileProfile`
instead of its admitted payload. That fixture ABI mistake has been corrected.
Both upstream and downstream completions now explicitly assert the independent
fixed profile CID, so absent profile identities cannot pass by comparing two
undefined fields. Earlier native-test evidence should not be read as having
independently verified profile identity propagation; this test now covers it.
