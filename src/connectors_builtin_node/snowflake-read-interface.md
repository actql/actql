# Same-runtime Snowflake response bridge

- Responsibility: expose the existing Common acquisition/response borrower and
  Snowflake description, original statement protocol and value admission.
- Inputs and outputs: original opaque Core values plus bounded physical bytes
  return the same Owners' typed values/refusals, material or read-only usage.
- Identity: every handle stays inside this exact Core instance; JSON/CIDs,
  independently prepared contracts and other runtimes cannot replace it.
- Ownership: the original Host owns Run finish/capture/close, and the existing
  physical scope supplies its own cleanup observation before statement I/O.
- Synchronization: one-shot borrow/request/charge/cleanup bindings remain Core
  checked. Generated RelA wrappers consume the same source declarations.
- Failure: typed refusals are retained. The two recording wrappers return Unit
  only for the expected original decoder refusal/response loss; Unit is never
  successful Source admission, durable completion or a transport ACK.
- Cancellation: interruption only stops admission. Confirmed transport cleanup
  and original Host root retirement remain separate existing operations.
- Resources: these wrappers reserve no new Ledger/Run and change no limit;
  original transfer/retention/workspace and bounded bytes remain with Core.
- Extension: normal connector assembly generates imports/mirrors. Provider HTTP,
  decompression, current authorization and physical cleanup stay outside Core.
- Verification: actual Common borrower cases and same-runtime JS/loopback TLS
  exercise these wrappers. Other-target type checking is not execution; normal
  installed release and Python Local remain separate acceptance scopes.
