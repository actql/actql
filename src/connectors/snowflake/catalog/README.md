# Snowflake SQL API result material

This pure Connector projection consumes bounded SQL API JSON bytes through the
existing preserving source parser, decode cursor and value-admission Owner.
It does not submit SQL, access a credential, issue a Source grant, publish a
Result or mark an Acquisition/Effect/Run complete.

The first response supplies its statement handle, ordered column metadata,
partition row counts and first data partition. Later data-only partitions
remain bound to that original metadata by nominal identity. Each actual row
count must agree with its declared partition; declared byte sizes never expand
caller limits. A complete partition is not evidence that the other partitions
were received.

`FIXED` uses the Common exact decimal normalizer and decimal contract, including
precision 38; it is not relabelled binary64 or int64. SQL NULL, text `"null"`
and VARIANT JSON null remain distinct. Boolean/float/JSON cells use their
provider string transport and existing Common value admission. Row width,
column uniqueness, nullability and caller budgets are checked explicitly.

The initial read material supports TEXT, FIXED, finite REAL/FLOAT, BOOLEAN,
VARIANT, OBJECT and ARRAY. Other provider types currently return a named
`UnsupportedColumn`; this is unfinished coverage against the full approved
Snowflake profile, not a restriction of that profile. Source/catalog admission,
current credential/use, pushdown, temporal/binary carriers, acquisition cleanup,
SQL API submit/status/cancel, original request/handle reconciliation and every
write operation remain separate integration work. No live service acceptance
is established here.

Provider references:

- [SQL API reference](https://docs.snowflake.com/en/developer-guide/sql-api/reference)
- [Handling responses](https://docs.snowflake.com/en/developer-guide/sql-api/handling-responses)

Independent fixtures use the documented JSON envelope and string transport;
expectations are not generated by this Connector's output.
