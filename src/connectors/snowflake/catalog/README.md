# Snowflake SQL API result material

This pure Connector projection consumes bounded SQL API JSON bytes through the
existing preserving source parser, decode cursor and value-admission Owner.
It does not submit SQL, access a credential, issue a Source grant, publish a
Result or mark an Acquisition/Effect/Run complete.

The first response supplies its statement handle, ordered column metadata,
partition row counts and first data partition. Later data-only partitions
remain bound to that original metadata by nominal identity. Each actual row
count must agree with its declared partition; declared byte sizes never expand
caller limits. A complete partition is not evidence that the other partitions
were received.

`FIXED` uses the Common exact decimal normalizer and decimal contract, including
precision 38; it is not relabelled binary64 or int64. SQL NULL, text `"null"`
and VARIANT JSON null remain distinct. Boolean/float/JSON cells use their
provider string transport and existing Common value admission. Row width,
column uniqueness, nullability and caller budgets are checked explicitly.

The initial read material supports TEXT, FIXED, finite REAL/FLOAT, BOOLEAN,
VARIANT, OBJECT, ARRAY, DATE and UTC TIMESTAMP_LTZ. DATE uses the selected
`YYYY-MM-DD` representation. LTZ accepts the selected fixed nine-digit UTC
representation, checks its observed scale and delegates canonicalization to the
existing exact Common Timestamp Owner. Values retain at least three fractional
digits; only extra trailing zeros are removed, without binary64 or Host Date.
Civil TIME/TIMESTAMP_NTZ, retained-offset TIMESTAMP_TZ and binary carriers remain
unfinished. Other provider types currently return a named
`UnsupportedColumn`; this is unfinished coverage against the full approved
Snowflake profile, not a restriction of that profile. Source/catalog admission,
current credential/use, pushdown, unfinished temporal/binary carriers, acquisition cleanup,
SQL API submit/status/cancel, original request/handle reconciliation and every
write operation remain separate integration work. No live service acceptance
is established here.

Provider references:

- [SQL API reference](https://docs.snowflake.com/en/developer-guide/sql-api/reference)
- [Handling responses](https://docs.snowflake.com/en/developer-guide/sql-api/handling-responses)

Independent fixtures use the documented JSON envelope and string transport;
expectations are not generated by this Connector's output.

`project_result_set_with_contracts` additionally validates every observed column
name, type and nullable flag against supplied original Common contracts before
admitting raw cells into those exact contracts. Equal separately constructed
contracts do not relabel existing CheckedValues. Later partitions retain the
same original contracts. Contract mismatch and comparison-budget exhaustion
remain distinct refusals.

`project_running_statement` admits only a bounded pending-query handle with the
SQL API pending code and no result rows, metadata or multi-statement handles.
It supplies lookup material only; its status URL is not an installation target
and it issues no retry, completion, cancellation or cleanup authority.

## Interface responsibilities

- Responsibility: provider response spelling and bounded page projection belong
  to this Connector; Common owns contracts and value admission.
- Inputs and outputs: exact bounded SQL API bodies and optional original input
  contracts produce an immutable ResultSet/Partition or a closed ResponseIssue.
- Identity: partitions borrow the nominal original ResultSet. Supplied original
  contracts retain their physical identity through raw-cell admission.
- Ownership: material stays with the receiving Host/RowRun; decoding issues no
  Source permission, transport receipt, publication or durable ACK.
- Synchronization: synchronous projection; this module starts no physical I/O.
- Failure: malformed metadata, mismatched contracts, budget exhaustion, invalid
  values and unsupported types are named refusals, never successful coercions.
- Cancellation: no asynchronous request is started; the original transport/Run
  Owner retains interruption, cancellation and cleanup responsibility.
- Resources: byte/node/depth/column/row/partition and per-comparison work bounds
  remain explicit; provider sizes do not expand them or fund unrelated domains.
- Extension: unsupported temporal/binary types require the existing Common and
  provider codec Owners; there is no string/JSON or stock fallback.
- Verification: independent envelope/string-transport vectors cover exact
  decimal38, NULL, malformed input, partitions, bounds and nominal contracts.
