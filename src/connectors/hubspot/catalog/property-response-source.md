# Same-response Source staging

- Responsibility: Reuse the existing Source parser before and after the same
  Reader's capacity reservation. Geometry is sizing DATA, never grammar,
  Catalog/current, permission or physical-cleanup evidence.
- Inputs and outputs: Strict bounded UTF8 bytes, exact request path, object
  type and original property limits produce a retained preparation Result.
  Successful preparation exposes twelve numeric Source geometry fields; after
  reservation the same cursor produces the original full property projection.
- Identity: Consumption requires the same physical Bytes, path and complete
  SHA256. The cursor transfers once. Copies, changed bytes, foreign paths,
  repeated consumption and retired inputs fail without reparsing a replacement.
  The original projector still computes its complete final Catalog digest.
- Ownership: Only the existing per-read provider sequence retains this logical
  view. The shared Catalog carries no per-Run state. Opaque provider cursors
  never enter the independently installed Common runtime. Common receives only
  sizing DATA. No new Resource, Ledger, physical owner or global cache exists.
- Synchronization: Preparation and continuation are synchronous. Preparation
  failure remains a Result until the original accepted/status check; it cannot
  replace an HTTP refusal. The existing original current, charge, cancellation
  and post-reservation fences remain with the generic Reader.
- Failure: Failed growth retains the unconsumed preparation on the same Reader.
  Invalid UTF8, malformed JSON, normalized duplicate keys, numbers, full unknown
  fields, node/depth and property constraints retain the original decoder.
  Missing geometry uses the full quantity envelope, not a semantic fallback.
- Cancellation: The original provider retirement cancels the same pending
  Source cursor before releasing the view. This logical disposal is idempotent
  and does not acknowledge transport close, response debit or physical cleanup.
- Resources: The generic Reader already funds bounded decoded text/preflight.
  The existing capacity recipe additionally names the staged view, Result/cells,
  scalar geometry vectors and complete digest scratch before the first body.
  Observed raw geometry bounds the current grammar/index and native projection;
  configured limits still reject the original parser. Previous/failed prefix
  peaks and raw bodies remain held; later unknown-role responses keep the full
  metadata/page envelope. No Ledger tariff or budget is increased.
- Extension: This internal sizing vector is not a public wire, authority tuple
  or transport API. New parser families must preserve same-input transfer,
  normalizing HubSpot mode and explicitly fund their actual representations.
- Verification: The staged Source tests cover identity/once-only, unknown
  fields, Unicode/duplicates, BOM/numbers, original limits and cancellation.
  The Common component uses a real Ledger and original reservation growth;
  portable provider caller cases cover reservation failure, HTTP priority and
  mutation/cancellation. These components do not qualify normal installation,
  real account execution, physical cleanup ACK, memory use or ordinary latency.
