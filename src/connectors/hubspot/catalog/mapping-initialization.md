# Original HubSpot Mapping initialization

- Responsibility: the existing HubSpot Catalog/Mapping producer derives an
  UPDATE candidate from positively writable original property metadata. Common
  owns its declaration, Environment, complete Program admission and initial
  Resource. This connection creates no new Owner or authority.
- Inputs and outputs: captured field/source counts, original input text units
  and unchanged constructor bounds select a typed construction quote in the
  same Common runtime. The provider's Catalog and native Mapping stay in the
  provider runtime. Only their complete canonical Mapping DATA crosses back.
- Identity: use the actual retained Common declaration's manifest entry CID.
  The Host accepts only native projections funded by that same initialization
  and the exact original declared holder. Canonical bodies, mapping references
  and CIDs remain the existing native producer's outputs; they are not current
  authorization or permission to send.
- Ownership: `prepareNativeInput` retains each original quote and output. The
  existing successful-construction transition selects retained-only quantity;
  throwing or incomplete construction retains its full peak. The same Source
  context retains Mapping carriers and constructs its Environment through the
  existing measured helper, keeping real dependencies after workspace ends.
- Synchronization: capture actual issuer/producer methods before the original
  reserve/current callback. Reserve before native construction; reject foreign
  declarations, scopes, copied outputs, repeated Mapping selection and reentry.
  Later Program/current/approval and Effect dispatch fences remain mandatory.
- Failure: an actual Ledger refusal prevents the native constructor. A native
  refusal preserves its typed cause and does not publish a partial Environment.
  Capacity DATA is not validation success; original byte/node/depth/property
  bounds and full writable-field/type checks still refuse invalid mappings.
- Cancellation: this constructor is synchronous and pure. It creates no
  physical child, timeout exemption or cancellation/cleanup acknowledgement.
  Existing initialization retirement continues to own all physical duties.
- Resources: retain final document/name/source/control representations and
  borrow the original Catalog. Separately cover overlapping schema, row-map,
  identity, preimage and final writers, hashing/UTF-8 and checked contracts.
  The bounded supported property shapes constrain demand before allocation;
  wider unused output limits do not enlarge a tiny selected Mapping. Execution
  includes retention; the two quantities are never added as exclusive usage.
- Extension: use the same native producer and Common issuer/initial Resource.
  Do not forward provider-runtime opaque capacities or declarations into Common,
  derive writable support from readable fields, raise budgets, cache Allow or
  bypass complete external/Program validation.
- Verification: the selected native quote tests cover actual Decimal/Array
  Mapping construction, retained versus peak, unused maxima and strict bounds.
  The Common tests use the real Ledger for same-original reservation, successful
  shrink, foreign input and refusal before projection. Installer contract doubles
  cover original-method binding and failure/accessor handling only. These tests
  do not qualify a standard installed Effect, provider send, approval, Saved,
  physical close, ordinary latency or a released package.
