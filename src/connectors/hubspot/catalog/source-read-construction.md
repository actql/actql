# Managed response construction capacity

The existing managed HubSpot sequence receives Account details, then Properties,
then object pages, and finally rechecks Properties. Its original Reader retains
and charges every received body before projection. Capacity is quantity DATA;
it grants no access and does not replace current, schema or cleanup checks.

The first two positions have closed metadata constructors. Account reuses the
existing account projection/export inventory. Properties reuses the same native
PropertyMetadata/option projection extent as initialization, its retained Catalog
inventory, and the original-catalog recheck Map. Neither position constructs a
row ValueNode forest, a row-wire writer or a Host row JSON.parse tree. Those row
policy maxima therefore do not contribute to the first two response capacities.

The byte-length prefix does not identify the final Properties position when the
page count varies. Positions after the first two retain the existing conservative
metadata/page envelope. No input role, interface, permission or payload is inferred
from a byte length. Every earlier and failed constructor prefix remains charged
until the same Reader's actual retirement; returning from a projection does not
acknowledge its cleanup or discard the received body.

The shared Ledger equations, tariffs and configured retention/execution limits
are unchanged. Metadata still uses its complete byte/node/depth/property bounds.
Refining those bounds from actual structural geometry is a separate question;
removing a wrong-role row term alone does not establish that a full workflow fits.

## Sequential key-normalization scratch

The Properties recheck completes the original normalizing byte parser before
indexed admission and native `PropertyMetadata` projection. The canonical
normalizer returns only its String; its private scalar arrays, ordering/builder
backing and text scratch do not escape that synchronous call. The existing
`nfc_lf_construction_scratch_extent` excludes the returned String.

Quote the maximum of the complete parser phase and the later metadata phase,
removing only that named scratch from the latter. Conservatively keep the full
Source tree, normalized-key output, indexed admission, Catalog, recheck and hash
envelopes in both phases. Both malformed-prefix and metadata-failure envelopes
remain funded. Earlier response maxima still accumulate until the same Reader
retires; this change performs no successful-return refund or physical cleanup.

The later metadata/page envelope has the same sequential boundary: its
normalizing parser returns before native cell projection, row emission and
Host row construction. It uses the same private phase helper as the fixed
Properties recheck. The complete parser peak remains one alternative; the
later alternative removes only canonical scratch, retaining all returned
tree/key/index data beside every existing Value, writer and Host-row bound.
The complete maximum of each response still accumulates through retirement.
No response role is inferred, no configured limit is increased, and a failed
or unretired constructor is never refunded by this pre-construction quote.

Object-page selection is an earlier, distinct live role. The selected tuple
Array, seen Map and per-column derived contracts exist before parsing and
remain referenced during key normalization. Their explicit column-bound
inventory is fixed in both alternatives, independently of the later cell-node
budget. The existing full post-parse Value envelope is retained separately;
it is not used to justify omitting selection when few cells are permitted.

The configured node/depth ceilings remain rejection bounds. Parser and decoder
arrays grow from observed elements rather than preallocating every allowed
slot, but this byte-length-only quote has no current-body geometry. A Catalog's
property count cannot bound raw unknown fields or a later replacement body.
No count-only reduction, second parse/fetch or transport API is introduced.

## Same-reader observed Source input

The installed caller now stages its first fixed Properties response through the
existing `JsonSourcePreflight` and transfers that same parser after reservation.
The normalizing mode, full byte input/unknown fields, decoder and final Catalog
hash remain intact. See [same-response staging](property-response-source.md).

## Borrowed byte input and decoded source

Both Source recheck and Effect Property projection borrow the original response
Bytes. `sha256.hex` absorbs those Bytes into its fixed block state; it creates
no full-size wire copy or text preimage. The original UTF8 decode creates one
source String, retained through parsing. Parser tree text, scalar builders,
canonical scratch/output, indexed admission and the returned Catalog have
their own unchanged inventories. The shared quote therefore adds one bounded
decoded source String and the fixed hash/digest family, without charging three
additional source-sized Strings and another body-sized wire allocation that
these constructors do not create. It does not retire the original body or any
earlier/failed prefix, and does not reduce a configured rejection bound.

Physical Effect admission combines receive, original secret and metadata on
the complete child, beside the same Ledger's other coheld reservations. Initial
preflight/staging, grammar/projection and successful workspace return remain
distinct existing cuts. A metadata-only fit does not prove that full admission.
The old byte-only API retains its full envelope. The observed API adds named
finite staging/digest controls before receiving a body and uses geometry only as
sizing DATA. It does not retire an earlier prefix, infer currentness or narrow
the final Properties/row superset from an unknown response role.
