# Ordinary retained Local task execution

- Responsibility: the existing Local adapter advances the checked DAG and its
  installed managed operations. The source-free entrance retains its zero-Source
  guard; the captured entrance accepts exactly one original Row Query capture.
  The single-task Whole entrance instead requires the same retained managed
  Plan, Prepared, Request and configured DAG with its original complete input.
- Inputs and outputs: the captured entrance consumes the configured retained
  Host, its exact checked requirements, the original RowSourceCapture and finite
  finalization limits. It returns the existing LocalValuesExecution or the same
  failure-cleanup handle. It does not admit, claim or publish a Run.
- Identity: the requirements retain the exact prepared graph. The Row owner
  compares the DAG's original opaque capture and its own live Ledger/holding
  after Source verifier callbacks. Equal bytes, another Ledger or a copied
  source wrapper cannot substitute for these originals.
- Ownership: Source custody stays with its RowRun. Compute begins at task one,
  retains real managed outputs for later checked edges and leaves task zero
  without a fabricated managed completion. Close dependent execution/results
  before closing the captured Source owner.
- Synchronization: currentness callbacks remain Host-supplied lifetime checks,
  not Account authorization. The original Host must already have admitted and
  started work. The adapter rechecks currentness at the existing boundaries and
  refreshes the captured Host's original adaptive selection before each task.
- Failure: unsupported profiles, unavailable originals, dispatch, adaptive
  selection and bounded finalization failures retain their typed outcomes.
  A failed Run is stopped; cleanup retries cannot reselect or restart Compute.
- Cancellation: the same operations are closed in reverse order, the same DAG
  is stopped and original outputs are retired before cleanup is acknowledged.
  Source cleanup remains a separate caller-owned obligation.
- Resources: every selected task, bridge and retained output uses the existing
  DAG Ledger and provider reservations. No replacement Ledger or free imported
  Source is constructed. The Row custody observer allocates no inventory and
  issues no capacity, token, ownership or cleanup acknowledgement.
- Extension: extra Sources, Model and Effect work are outside this entrance.
  Captured inputs without existing cell access and Carrier
  snapshots are not reconstructed here. Native Account/Journal orchestration,
  actual file capture, publication and CLI admission stay with their owners;
  this Common bridge does not wire or enable a product command.
- Verification: captured_tasks_wbtest exercises real Row/Common owners, a
  downstream managed edge, exact-identity refusals, verifier reentry, sticky
  failure and Source-preserving cleanup. Source-free task/requirements and
  whole-input Result tests remain consuming regression checks.

The Whole entrance executes its original root through the existing single-task
executor. It does not assert that a supplied Source is source-free or relax the
ordinary task-loop predicate. A copied managed Run, a missing bound DAG or an
equal Graph cannot supply this entry. The same original execution retains its
Source borrow, typed failure and cleanup; no compilation, admission, resource
reservation, currentness closure or Run is created by this projection. The
caller keeps the Source owner alive until execution and dependent Result
cleanup finish. Multi-task Whole execution remains outside this single-task
entry. The existing retained Effect continuation separately requires its
original captured Effect Run; it cannot enter the ordinary Whole projection.

## Captured suffix capacity

The captured requirements return a conservative simultaneous Compute quote
separately from unchanged maximum admission limits. Selection uses the exact
original graph and its validated Source offset, including each task's actual
selected step or prefix. The existing provider recipe includes its children
and scratch. Existing input-port imports, retained output and metadata remain
in the upper envelope, even when an original captured cell view avoids an
import at runtime. No successful sample substitutes for that inventory.

The Source acquisition, provider, capture and transport footprint is not part
of this Compute sum. Its original owner must quote and compose the still-live
Source footprint before admission. A requirement exceeding the existing
maximum remains a requirement, not a ceiling increase or permission to run.
The quote retains no physical Source and grants no Ledger, custody or capacity.
The captured capacity tests exercise linear and mixed-provider branched tails
on one nominal test Ledger, separately composed with original Row demand. They
do not establish Native backing, Account/Journal admission or CLI acceptance.

## Captured entry control constructors

The captured entry adds exactly two currentness closure environments. Each
retains four borrowed references: its caller callback, the original DAG,
RowSourceCapture and checked requirements. The optional live callback's Some
wrapper adds one header, one reference and one scalar tag. The fixed maximum
is therefore 3 headers, 9 references and 1 scalar word, or 128 retained bytes
and 128 execution bytes under the central preparation representation tariff.
There are no copied strings, wire bytes, captured tuple or separate original
currentness closure. The Row custody observer returns Bool without allocating
a result wrapper. Source callbacks still retain their own implementation owner.

`captured_local_tasks_control_capacity` is pure DATA. The original outer Host
must compose it exactly once into its fixed control reservation before calling
`execute_captured_local_tasks_guarded`, and keep that reservation live until
all execution/failure cleanup acknowledges retirement of the guarded aliases.
This is a public entry precondition, not a caller-supplied permission or a new
Common reservation, attempt or Ledger. It is separate from Source backing and
per-task provider/output capacity; no downstream task multiplies this quote.
A failed reservation must prevent entry and callback construction.

The source-free entry retains its existing current/live closure shape. Managed
RelationOutput wrappers already belonged to the existing dispatch conversion;
passing its explicit output union moves those same constructors, while the
zero-payload captured-input tag adds no record. No generic metadata slack or
JS output-cleanup inventory substitutes for the new captured-entry inventory.
The independent census, exact/one-byte-short reservation and optional-live
execution tests cover this component; actual Native Work composition is a
separate consuming boundary and must reserve before constructing these guards.

## Verifier reentry and Source port lifetime

The original Source availability verifier can retire the DAG's captured port
without closing its independently owned RowRun. The strategy owner checks the
same original Source reference and port lifetime again after that callback.
A stopped DAG still exposes an unretired original capture for identity checks;
stop alone is not port retirement. A retired port fences the Common observer
and cannot advance a Compute attempt. Downstream cleanup and caller-owned
Source cleanup retain their existing order and separate responsibilities.
