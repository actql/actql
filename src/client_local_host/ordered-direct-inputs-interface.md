# Ordered original Direct inputs

- Responsibility: The existing Request, prepared Pure or Effect Plan and managed
  Run select and retain Direct acquisition occurrences. Node and RelA bridges
  forward exact checked coordinates; they do not resolve another source.
- Inputs and outputs: Selection consumes the original checked program and a
  bounded work allowance, returning an opaque task-ordered occurrence inventory.
  Plan construction consumes that inventory, original declarations and query
  requirements. SourceReadAt consumes stage, input and task, returning the same
  Run's single original Source read for that occurrence.
- Identity: Each CarrierResponse must be Direct and bind the exact original
  request mode, request, stage pipeline and captured task. Missing, duplicate,
  swapped, foreign-owner or unsupported capture shapes refuse. Effect selection
  retains the original Effect owner, never a caller-selected Pure equivalent.
  Source read attachment checks the same retained tuple and acquisition.
- Ownership: Request preparation owns constructor funding. The existing Plan
  retains the inventory; the existing managed Run owns reads and its Ledger.
  Selectors and bridge projections issue no completion, permission or resources.
  Whole-input plans retain their separate existing path rather than claiming
  a query-capture occurrence.
- Synchronization: Selection occurs once under funded preparation, before Run
  adoption. Read opening uses the retained inventory without reconstructing
  queries. Existing original-current callbacks and final same-Run checks remain
  in place. Failed or duplicate opening cannot replace a recorded read.
- Failure: Work limits, owner or tuple mismatch, malformed cardinality,
  unsupported whole-input use of SourceReadAt, and repeated or retired reads
  refuse. Failed preparation remains attached to its original Request cleanup.
  Legacy ordinal APIs retain their existing narrower contract.
- Cancellation: Closing a Run invalidates new reads. Source and provider cleanup
  remain with their existing owners, including pending failures. Retained Plan
  inputs are not evidence that physical cleanup has completed.
- Resources: Original Request plan quotes include retained selector containers,
  Plan fields, coordinate tuples and temporary selection arrays/control overlap
  before construction. Runtime Plan demand retains the same inventory cost.
  Read lookup does not allocate a replacement selector or fund another Run.
- Extension: Additional supported acquisition shapes must have exact original
  graph mapping and construction demand. Counts, authored source order, port zero
  defaults and equal wire identities are not substitutes for that mapping.
- Verification: client_direct_acquisition_occurrences_wbtest.mbt checks original
  Pure/Effect ownership, exact tuples, foreign checks and bounded refusal.
  installed_direct_occurrences_js_wbtest.mbt checks wrong coordinates, duplicate
  and retired reads, same Run/Ledger and representation growth. These checks do
  not establish full keyed Content/Model/Effect composition or artifact acceptance.

The Effect Source Plan also accepts inert installed Row or DuckDB descriptions
in this same checked occurrence order. It prepares each original Query once,
retaining either the existing Row acquisition or the existing pending DuckDB
capacity. Native descriptions bind the exact checked Source reference and the
three original acquisition/evidence/receipt contracts; they select neither a
Native/Broad realization nor permission. The native getter crosses original
current once and returns that same requirement/capacity without a Row read.
Row declarations/acquisitions stay compact in their original relative order;
read slots and capture capacities retain the full checked task order. Existing
all-Row indexes and public Plan signatures are unchanged. Mixed plans keep the
complete simultaneous Compute/capture envelope; the Row-provider-only phase
reduction applies only when every capture has that original provider recipe.
Focused Effect native/Row tests additionally cover both mixed orders, original
Ledger/capacity identity, foreign and absent inputs, exhaustion without attempts,
and synchronous current reentry. These are Core/source checks, not an installed
DuckDB/Model/Effect execution or physical cleanup acknowledgement.

Managed Source frame correspondence retains the same current read, Ledger and
physical issuer frame without issuing capacity. The issuer performs its physical
current observation before the callback-free final retained fence checks local
stop, park and read lifetime. A nonmanaged read must retain that exact child,
not merely a present child with a stale Ledger reference. Existing Source
currentness paths inline their post-callback identity guards and keep their
original Result construction shape; they do not call another Result-returning
helper. The new opaque observation and its control/error wrappers require
already funded enclosing capacity and do not certify installed Source funding.
