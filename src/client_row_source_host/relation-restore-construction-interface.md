# Full Relation restore construction DATA

- Responsibility: quote the existing complete saved Relation declaration reader
  and its native DeclarationJson export. This is the multi-view constructor's
  own inventory, not the older single-view/default-request recipe multiplied by
  a view ceiling. It creates no declaration, contract identity, permission,
  Source, resource reservation or second lifetime owner.
- Inputs and outputs: the exact borrowed saved outer wire and its immutable
  parallel descriptor arrays contain resource/kind/schema and explicitly absent
  or present request, facts, acquisition and resource-identity wires. Scalar
  scans establish UTF-8, punctuation and depth bounds without parsing, decoding
  nested strings, canonicalizing, hashing or allocating contract structures.
  The result is existing PreparationRepresentationUnits, or its existing opaque
  ExecutionCapacity projection at the builtin bridge.
- Identity: quoting is not admission and does not certify that the parallel
  descriptors correspond to the outer wire. The installing pure producer must
  use the same retained originals for quote and restore. Only the unchanged
  native restore checks canonical schemas and expected Catalog identity.
- Ownership: input Strings and descriptor arrays remain borrowed from the
  already-funded metadata producer. New quote geometry/parts arrays and controls,
  every native parser/canonical/schema/assembly output and exported String are
  co-counted conservatively. No successful or failed temporary is assumed to
  have been collected merely because a later constructor runs.
- Synchronization: the original SourceInitialization reserves the opaque native
  quantity before invoking restore or export. Initial, final and physical
  declarations are separate actual invocations and their inventories are added
  while their outputs remain live. Quoting alone cannot execute a callback.
- Failure: inconsistent arrays, unsupported size geometry and overflow refuse
  before the expensive producer. Invalid JSON can still have a finite quote;
  it remains invalid at the original reader. Inventories include refusal prefixes
  and assembly that occurs before a bounded writer fails.
- Cancellation: this synchronous DATA operation has no cancellation protocol.
  The existing initialization parent retains its construction demand through
  failed callbacks and normal retirement; no new cleanup acknowledgement exists.
- Resources: named independent families include the outer normalized Source
  parser/index and stdlib reconstruction; schema publication verification;
  per-view Source/index, raw and canonical forests, checked Contract and Schema
  construction; optional request/facts/acquisition/identity construction; five
  envelopes per view, acquisition re-admission and its actual generated whole
  SourceView rule plus shared validation frame; each present resource identity
  has another independent rule/frame invocation; sealed SourceViews, one complete
  Catalog and manifest; per-view evidence and the distinct stdlib export writer.
  Shared decode, normalization, collection and writer inventories retain their
  existing tariffs. This is logical constructor geometry, not physical heap,
  raw transfer allowance or resource authority.
- Extension: arbitrary full declared nested contracts and optional acquisition
  and identity bodies contribute their original bounded syntax. No scenario,
  provider field, fixture row or cached sample is recognized. Original catalog
  admission, JS entry parsing/canonicalization/hash, derived File facts, physical
  descriptor creation, Environment construction and Mapping continuation remain
  separate actual constructors requiring their own demand before execution.
- Verification: focused source tests cover multiple simultaneous views, optional
  nested bodies, Unicode, failed prefixes, inconsistent arrays and an actual
  native multi-view restore. A builtin test executes its real restore/export
  boundary. These tests do not establish complete installed initialization,
  cross-target physical layout, whole-pipeline funding or release acceptance.
