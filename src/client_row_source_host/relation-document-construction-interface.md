# Relation document construction demand

- Responsibility: The existing relation codec describes bounded constructor
  demand for one raw document and all simultaneously retained typed projections.
- Inputs and outputs: Inventory functions consume original checked Contracts,
  bounded raw geometry, path depths and writable-field counts, returning
  representation DATA. The separate projection-contract operation reconstructs
  the exact original declaration mapping under an already funded metadata phase.
- Identity: A checked Contract is not re-created while quoting payload demand.
  Metadata extraction retains the original declaration/resource/identity binding.
  Equal row contents or cached models do not replace current raw file input.
- Ownership: The existing preparation owner funds metadata extraction; the
  existing Source or Effect owner funds raw admission and projections before I/O.
  No inventory function creates a reservation, receipt, permission or new owner.
- Synchronization: Derive scalar bounds before allocation. Fund metadata before
  extracting its Contract, then compose raw-once and the sum of projection peaks
  before opening the physical source. Actual usage remains a separate observation.
- Failure: Invalid or overflowing geometry and unsupported Json, Vector or
  reference Contracts refuse demand. Integer overflow refusal includes the full
  original token text, not only the successful scalar spelling. Failed constructor
  prefixes and canonical/schema reconstruction overlap remain in the quote.
- Cancellation: These synchronous DATA operations acknowledge no physical stop.
  The existing read/Effect operation must retain its reservation and copied raw
  original until its own cleanup completes, including every retained projection.
- Resources: The raw byte copy, preserving parse/index, cumulative metadata reads,
  canonical writers, schema contracts, projection arrays, typed values and actual
  synchronous rechecks are counted by their constructor families. Raw backing is
  counted once; distinct projections and their retained mapping work are summed,
  not replaced by the largest one or by transfer-byte charging.
- Extension: Unsupported contracts require their actual typed constructors and
  refusal peaks to be described before admission, not an arbitrary byte factor.
  Native restore and Host JSON projection are separate constructors with their
  own existing-owner funding; this inventory does not implicitly cover them.
- Verification: relation_document_construction_wbtest.mbt checks exact summed
  composition, unsupported nested contracts, invalid/overflowing bounds,
  cumulative mapping geometry, long integer refusal and original metadata
  correspondence. These checks alone do not establish Host funding integration.
