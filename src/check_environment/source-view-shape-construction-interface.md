# Original SourceView shape-validation construction

- Responsibility: expose the existing generated SourceView-rule and validator
  frame construction inventory for one acquisition or resource-identity shape
  check. The whole-view observer uses the exact same extracted frame recipe.
- Inputs and outputs: bounded node, maximum object-field/array-item and outer
  ancestry-depth geometry produces existing CollectionConstructionExtent DATA.
  No input cursor is walked, grammar evaluated or value admitted to quote it.
- Identity: selected subrules still construct the complete generated SourceView
  rule. Its inventory comes from the original generated constructor recipe,
  never a hand-maintained substitute or a second grammar.
- Ownership: literal rule Strings and input cursor backing remain borrowed.
  Fresh rule records/arrays, pending frames, indexed child/field carriers,
  stack backing, seen Maps and failure ancestry belong to this invocation.
- Synchronization: each actual acquisition or identity check requires one
  invocation's inventory. Sequential calls do not implicitly retire retained
  originals. The existing whole-view observer retains its prior frame geometry.
- Failure: invalid geometry returns absence. The actual shape interpreter still
  owns grammar rejection; the shared frame includes its typed refusal path.
- Cancellation: this synchronous quantity projection has no independent cleanup
  or cancellation owner and acknowledges no physical retirement.
- Resources: shared collection construction prices the generated rule and the
  exact former view_construction shape_frame formula. Their inventories add;
  caller allocations, source parsing, decoded backing and authority are excluded.
- Extension: grammar changes continue through the existing generated rule and
  its generated constructor recipe. This helper creates no rule/schema registry
  and has no provider-specific shape or capacity tariff.
- Verification: focused tests assert the fixed independently counted complete
  generated rule, two-invocation addition, invalid geometry and equality to the
  previous whole-view frame recipe over fixed inputs. They are not proof of a
  caller's complete allocation inventory or installed resource acceptance.
