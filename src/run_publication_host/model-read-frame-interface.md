# Original Model Read frame correspondence

- Responsibility: the existing Model Read Scope owner checks that a physical supplier enters through the same original Request frame and checked Run/Plan. The Native caller retains its entered frame across both current observations.
- Inputs and outputs: opaque existing Model Scope, compiled Run, Definition, Infer Plan and imported frame produce only Unit or a typed original refusal. No Ledger getter, descriptor, Model execution or grant is produced.
- Identity: exact scope Ledger must match the original imported frame. The checked Run and Plan remain nominal; the Definition retains its existing identity contract. Grouped scopes must remain members of their exact original group.
- Ownership: every input is borrowed. The same Resource and Model owners keep admission, preparation, publication and retirement. No additional persistent holder or cleanup obligation is introduced.
- Synchronization: the first Resource current callback may reenter. The Native caller then re-observes the same entered frame. Only callback-free Model and Resource predicates follow that final physical callback. Busy, closing, closed and finished group members cannot reenter.
- Failure: foreign Run/Plan, finished or retired Scope, foreign/copied/stopped/parked frame and physical current refusal remain typed failures. Equal limits, equal strings or another Request cannot repair correspondence.
- Cancellation: this check cannot cancel, retire, report, acknowledge or settle any owner. Original shutdown makes later supplier entry unavailable while its existing cleanup route retains custody.
- Resources: the caller must already fund Result/issue carriers and enclosing validation. This API reserves nothing and is not evidence for complete Native Model constructor funding, provider installation, dispatch or output publication. Existing Scope record inventories are unchanged.
- Extension: use the existing imported Resource frame and Model scope. New caller-provided grants, Ledgers, generic callbacks or alternative issuer paths are outside this interface.
- Verification: focused portable cases execute Model scope identity and real grouped close. Native public-frame cases exercise the actual original Request/Ledger, positive and foreign frames, shutdown after physical observation followed by the retained fence, and parked refusal. The parked case retains pending cleanup without an invalidation receipt; process exit is not an ACK. The shutdown case does not inject shutdown inside Native's fixed current closure. Complete constructor funding, Model execution and installed supplier acceptance remain separate.
