# Project metadata admission construction DATA

- Responsibility: quote the existing explicit Catalog and Connections native
  admission constructors before they encode, parse or index an original wire.
  This is not read transport, metadata selection, installation or authority.
- Inputs and outputs: an already retained exact original String is scanned for
  UTF-8 size and conservative syntax bounds without parsing or copying bytes.
  Separate Catalog and Connections functions return existing logical
  PreparationRepresentationUnits. Builtin bridges project those units through
  the existing opaque ExecutionCapacity constructor.
- Identity: the installing producer must use the same original String for quote
  and admission. A quote certifies neither valid JSON nor correspondence with a
  connection, schema, profile or installed Source.
- Ownership: the caller's original String stays borrowed. Admission's actual
  UTF-8 byte copy, preserving parser, indexed decoder, entry tuple/array and
  decoded original entry-span Strings are independent charged outputs. Names
  and connector Strings borrow their original admitted tree backing, which is
  conservatively retained rather than assumed collected after projection.
- Synchronization: the same initialization parent reserves each actual native
  quote before invoking its admission. Catalog and Connections inventories add
  while outputs overlap; neither one substitutes for the other's construction.
- Failure: original readers still reject malformed, duplicate, foreign or open
  envelopes. The quote includes those bounded failure prefixes and refuses
  oversized original Strings before the expensive native constructor runs.
- Cancellation: quoting is synchronous DATA without its own cancellation or
  cleanup owner. Existing initialization failure and retirement rules apply.
- Resources: the original preserving-parser/index inventory supplies its own
  logical collection tariff. The quote adds encoded Bytes, disjoint immediate
  entry-span output text, byte/subarray views, decoder result and tuple carriers,
  and output array growth. Raw input transfer funding does not fund this parse.
  This is logical JS construction inventory, not physical allocator proof.
- Extension: Catalog tuples contain name/original-entry text; Connections tuples
  additionally retain the original connector String. No provider names, business
  fields or data file contents are recognized. JS entry projection, scope hashes,
  full Relation restore/export and generated facts require separate demand.
- Verification: focused tests execute both original readers, preserve Unicode
  and original entry whitespace, exercise failed prefixes and check cumulative
  independent inventory. They do not establish complete installed startup,
  cross-target physical layout or release acceptance.
