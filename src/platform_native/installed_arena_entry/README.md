# Regular Native control emission entry

This private regular executable entry retains the non-test control functions
through closed FuncRef callbacks. It has no test driver, fixture original,
numerical profile, argument parser or Local CLI. Main registers code references;
it does not acquire a mapping, create a Root/Run, load a VM or launch a worker.
The callback set carries the original typed reply and Host, with separate
operation/issue projections. No raw Ledger, nominal pointer wire or Python
decision about accepted/committed state is introduced.

The eight-argument C registration symbol is intentionally not implemented by a
guessed stub. Matching pinned C emission must supply its exact declaration and
calling/reference ownership before the private shim is linked. The preparation
is not a link-ready executable/library: ordinary linking currently lacks that
symbol. No partial link failure or compile-only result can become acceptance.
The original Source675 whitebox C and binary are signature evidence only; this
entry must be emitted anew from its own immutable source closure.

The selected Native backend's unsupported automatic foreign-library linking is
not used as an installed packaging fallback. A separately reviewed finite
two-stage recipe must emit this regular entry's C, bind the derived private
registration declaration, and link its matching runtime/stub objects into the
selected control component. A public caller does not build source or specify
internal libraries. The existing control runtime trust and unknown numerical
domains are unchanged; native emission, private library initialization,
physical funding and normal installed wheel are separate unverified boundaries.

Production links exactly one original C capacity/TLS provider. A later private
Wasmtime component imports that provider instead of compiling a second copy.
Registering callbacks does not adopt a runtime fork, grant VM capacity, authorize
external I/O or acknowledge cleanup. This Source preparation executes nothing.

The FD acquisition callback uses the matching emitted `Host*, int32_t` ABI.
The private shim writes the owned typed reply into the caller's persistent slot
before returning. It neither duplicates nor closes the borrowed descriptor.
Python retains the original one-shot descriptor carrier through acquisition and
cleanup; a lost response preserves the same Host, reply and FD responsibility
without another acquire or close. A copied descriptor or closed/unknown-close
carrier is rejected before the call. This port supplies only the original arena
domain, not worker overhead, VM funding, Run admission or publication authority.

The original domain callback set transports a closed operation tag, typed issue
family and actual Host/partial domain handles. It reuses the same Host's original
allocation/region/child/view/domain Owners. Preparing an error reply registers
all published partial custody before C/Python can inspect it. Current observation
uses the existing domain-current check; a nonempty handle is not success. The
Host retains bounded records from its original control envelope until their same
cleanup succeeds. Close callbacks require the existing caller's scoped-stop
and independent borrower-retirement facts; they do not infer either from exit.
Regular matching emission must establish the C ABI before linking this new set.

The domain material registration adds the existing typed projection and bounded
getters. Its exact private C copy accepts only ProjectDomain/Ok for the retained
original Host/domain, forty lowercase source units, thirty-two recipe bytes and
fifteen Int64 fields. The C header is derived from Sourceaf23's actual regular
emission (a4d4095a...), not a generated struct layout. Returned String/Bytes
references are released after copying; the original reply/domain stay owned by
Python until the existing data-drop path succeeds. No FD or pointer is encoded.

The Python material call rechecks the original domain after copying and returns
only immutable DATA. Known Owner refusal returns no material; response loss,
malformed data or a lost data-drop retains sticky Unknown with the same original
slots and descriptor, without another request or cleanup attempt. Ordinary
worker startup, complete funding, VM and installed wheel acceptance are separate.

The derived read callback registration and `domain_read_shim` consume the
matching regular Source7d6df1e6 C emission (SHA256
`b50d84954b4085485e022c0c94bcbee406759c2f559d3c00e7ccdcd34b75931c`).
Its six callbacks borrow the same Host/domain and return an owned immutable
original reply. The shim stores that reply in the caller's persistent empty slot
before returning. Existing typed getters/drop checks apply; transport zero is
not read success or cleanup acknowledgment. Read-close never invokes the full
CloseDomain data-drop helper. All runtime/header/provider objects must use the
same derived allocator selection; stock objects are not a fallback.

The private Python `_OriginalDomainReadFunctions` and existing domain custody
project those same operations. Lost replies retain the same original slots and
become sticky Unknown, without another prepare, close or direct C retirement.
Whole managed scope exit uses original leave even when its body fails. No
context pointer, new quota/Run/cleanup controller or public factory is added.
`domain_read_conformance.c` is a private 64-page diagnostic helper, excluded from
product linking; it is not a trusted installed supplier. Engine/worker/ordinary
wheel and public Python acceptance remain separate.
