# Original Native relation-file Work

The relation-file backend has a narrow `NativeClientRelationFileWork` projection.
It uses the existing first-start, Journal, Account, StoreOperation and Source
owners; it does not create another Run, lifecycle or Ledger. The
existing Resident `NativeClientSourceWork` representation is unchanged. The original Host
coordinator must retain its adopted configuration and exact checked declaration,
requirement, acquisition, file selection and Common requirements. The prepared
entry retains bounded selection DATA and immutable limits; Work opening takes
no second selection, and a caller-array mutation cannot replace its path snapshot. Its actual
`NativeLocalStoreOperation` exchanges the same entered business execution with
that operation's original Host Read and SQLite phases.

`open_original_relation_file_source_work` supports one declared finite relation
Source followed by a non-Model, non-Effect Common suffix and one Named Result.
The entry validates the accepted original Run, checks simultaneous Source and
Compute requirements against the retained execution's original Ledger, then
reserves dispatch and claims physical start once. A lost, cancelled or already
claimed start cannot reopen the Source. Each physical capture advancement and
Compute boundary checks the same first-start original again.

Run authority uses the retained control connection. Independent Source authority
uses `RowDeclaration.connector_id` and the declared resource returned by
`row_source_target` for the original acquisition, never the Run connection or a
source-ref string used as a grant. The fixed private original-access variant
preserves Values behavior when no Source is selected.

The file backend retains the actual Row capture while Common executes tasks
1 through N on the same Ledger and exports the actual final result. This first
unit exposes no invocation, publication, persistence or Saved Result delivery
capability. It does not issue local normalization: that issuer's original cache
retirement and the publication constructor inventory are separate prerequisites.
The normal mock/project and installed-profile guards remain unchanged.

Failures retain their first issue and exact cleanup children. Close the Common
execution and export bridge before the Source. A failed original Read return
may require the coordinator to enter the same execution's cleanup scope before
retrying; cleanup never reacquires a Run, Source or business domain. The
coordinator must retire escaped Work, capture, failure and Read-allocated aliases
before requesting physical execution/domain/arena retirement.

This is a trusted internal assembly boundary, not an immutable Source installer
or a CLI profile. The normal mock/project admission guards remain unchanged.
An operational fixture needs an actual Source-capable runtime member set, exact
generic adopted Account/environment/configuration, original Read/SQLite/Crypto
and business owners, and an independently declared physical envelope. A bundled
empty-Source runtime combined with a separate Row environment cannot establish
that evidence.

`NativeRelationFileSelection` is plain trusted-Host data. It identifies selected
path components and a declared resource; it is not an opaque installation
original, permission or proof of immutable project/profile binding. Nominal
identity checks apply to the actual acquired declaration, requirement,
acquisition, Run, Account and retained execution.

The original Values access record retains its existing six references. A
Row-only wrapper owns the declaration/requirement/acquisition projection; the
Source-free current and publication-fence branches retain their original
closure capture shapes. Compute's captured-entry control quote is composed
exactly once with the Native Work control inventory, not once per output.

The [prepared entry contract](relation_file_entry_contract.md) separates the
original Read constructor inventory, business control token and outer physical
cleanup. Logical Work close does not settle the control: the same execution
owner must first observe actual C retirement, then settle that exact token before
its existing report and parent return.

The entry is closed to non-Model, single-Run executions. Requiring a pristine
business Ledger is an invariant of this entry, not a new global Source rule.
Actual control-token identity, full Source metadata/provider overlap and the
Common suffix must fit before the original durable first-start claim.
