# Same-domain Native live-child accounting

`prepare_backed_live_child` retains the existing domain, child, ticket and
Common read-use before issuing the Resource Owner's one-shot live access.
Its opaque carrier keeps the same original runtime slot `R`, access and admitted
projection, including partial preparation. Foreign/copy identities and repeated
issuance/admission are rejected. No scalar description, cold Resource DATA,
fresh Ledger, quota or second byte reservation supplies this entrance.

The original C provider refuses a process borrow while a parent physical read
context exists. A live child's accounting use is therefore acquired without
creating that parent context. Local Root/Reader preparation keeps its existing
physical path. Accounting-only carriers cannot enter a local read/cleanup frame.
Closing an unattempted parent context observes only that no parent context was
created; it does not acknowledge the child's context, aliases, VM or channel.

The installed physical issuer must bind the actual channel/VM/FD/domain to `R`
before calling admission. This package does not supply that missing issuer or
adopt a numerical profile. Its limits projection is DATA only. Cumulative usage
returns to the original parent ticket; logical stop rejects new work while
original cleanup can still report. Lost replies preserve this carrier and do
not permit reissuance, readmission or a usage reset.

The same physical issuer retires live references only after the actual runtime,
channel and escaped projections retire. That operation breaks the carrier's
backreferences but returns no borrow, capacity, FD, Store custody or quota.
The existing Common pending fence keeps the read-use outstanding until then.
Domain/view cleanup and confirmed-stop loan settlement remain separate under
their original Owners. Partial access refusal also retains its original domain
borrow until those same explicit cleanup steps complete.

All new managed records, reference overlap and original `R` storage belong in
the selected initial control inventory. VM, process, transport, FD and other
independent overhead still require their own original funding. Unknown is not
zero; ordinary startup remains refused while its full supplier is incomplete.
