# Native initialization assembly

An initialization uses the existing `NativeBackedLiveChild` physical owner,
with a fresh Initialization purpose selected before any imported frame starts.
The installed caller retains the exact input and the original partial live
child acquisition. A Read-purpose child cannot be converted or reused.

`initialize_backed_preparation` retains the input-bound admission and its frame
before its single start/take. It charges the installed bootstrap quote against
the original child Ledger and registers its census before the shared Host
initializer can reserve anything. The finite initial slice has one working
reservation and no holdings or delegated children. Source material must be
quoted against the same working reservation before allocation; an unrelated
recipe requiring additional resource tokens needs its own complete inventory.
Neither the quote nor this census establishes a normal Source funding profile.

The Native client Host entry `begin_native_host_initialization_preparation`
connects that assembly to the existing shared initializer. It supplies no raw
Ledger, numeric limits, Node admission or cleanup callback. The shared Host
body verifies its original policy limits and consumes the same admission once.
The caller retains the returned Host owner, takes its original input/capacity
once, and constructs or continues only that selected input. Bootstrap controls
are allocated outside every child scope; variable material uses the existing
Native domain and must retire its actual aliases and failed partial children.

Cleanup does not use the shared Host close as a probe. First the selected
constructor or Source retires its working capacity after its actual children
unwind. `close_backed_preparation` logically stops the retained original frame,
relocates its stopped accounting DATA in the existing outer control scope, and
observes the actual original C-context close ACK. Only then can it finish the
census, settle bootstrap capacity, check Core's complete logical quiescence,
report that frame's actual usage, retire the
same live access, and clean the backed admission. The caller subsequently
closes the retained shared Host owner. Parent domain/view/loan/FD cleanup is a
separate duty.

A failed step retains the same partial fields and does not restart admission.
A published Ledger whose original take refused remains pending: this owner
does not retry take, reconstruct that Ledger, invent a zero report or claim a
physical ACK. A lost report retains the original report outcome. Physical
retirement, successful accounting report and final Common read-use return are
separate observations, and each successful stage is latched before another
fallible cleanup step.

Cancellation and a refused constructor retain the same cleanup duty; neither
proves physical retirement or authorizes a new input. Verification must
distinguish nominal input identity, original one-use transitions, actual
currentness, child-alias retirement, logical quiescence, usage reporting and
final parent custody. A type-correct assembly alone proves none of the
physical acknowledgements or the adequacy of a normal installed profile.
