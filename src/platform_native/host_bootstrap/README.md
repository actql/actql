# Original installed arena bootstrap

This private Native package implements the initial **selected arena** slice of
the Host bootstrap direction. It is not a public Python factory, worker funding
supplier, numerical product profile or VM allocator adoption.

The trusted installed physical supplier is the sole acquisition entry. Its
original Host reference, source, Darwin-arm64 backend, recipe and generation are
retained by `NativeInstalledArenaSupplier`. `prepare_installed_arena_supplier`
only prepares that installed intent; shape validation or matching metadata does
not authorize installation, execution, publication or recovery. SDK input cannot
supply this port. Ordinary Python Local remains unavailable until the installed
supplier and every selected bootstrap domain are actually accepted.

The initial control runtime is the explicitly trusted finite bootstrap envelope
in `host-bootstrap-disposition.md`. It includes the MoonBit runtime/Resource
objects, fixed external wrapper records and bounded custody arrays for the Host
lifetime. `control_envelope_bytes` is an installer declaration, not a Resource
grant, a measured VM bound or retrospective funding. No numerical product value
is selected in this source unit. The Native conformance fixture's declarations
and disposable 64-page arena are fixture inputs only.

## Original call order

1. The installed supplier consumes its acquisition intent once. Within the
   trusted initial control envelope, it obtains the original Resource Ledger
   and calls `reserve_shared_capacity(N)` **before** physical acquisition.
2. `bootstrap_stub.c` includes the existing `owned_capacity.c` implementation.
   It obtains one actual anonymous N-byte mapping, or `acquire_fd` maps the
   trusted caller's exact-sized original FD using the same provider. The FD is
   borrowed: its original caller retains descriptor custody and separate
   funding. Neither matching FD metadata nor this mapping supplies that grant.
   Mapping/control/child pages
   belong to the same lease. No alternate allocator or implicit growth is used.
3. `Acquired` carries the original Host; `Pending` carries that same partial
   Host, reservation and primary error. Pending acquisition is not successful
   funding. Physical close results are never ignored.
4. `claim` checks the original Host/source/recipe/generation, then consumes the
   original lease transfer once. A copied Host reference shares consumed state.
5. Child allocations reserve page-rounded `SharedAllocation` capacity before
   actual allocation. The original Host registers each physical extent before
   interpreting success. Controls and child copies suballocate the outer N;
   they do not charge that physical backing twice. Physical readers use original
   `SharedBorrow` tokens, and retirement refuses until the same readers stop.
6. Child physical retirement succeeds before Common capacity release. Failed
   physical allocation/retirement remains under this same Host. Final `munmap`
   succeeds before releasing control suballocation and settling outer capacity.
   Retries retain the original lease; successful steps are not repeated.

`acquire_fd` uses the same original intent, Ledger/reservation and partial Host
as anonymous acquisition. Invalid input or foreign nominal original is refused
before consumption or FD access. Once physical acquisition begins, failure
retains the same reservation and partial carrier. Host mapping cleanup never
acknowledges FD close, process stop or settlement of independent FD overhead.
The initial control declaration does not fund an unadopted worker or VM.

Only `physical_resources` makes accounting decisions. The wrapper forwards
cumulative delegation reports and conservative unknown-final settlement. The original logical-only delegation entry
continues to reject retained/execution byte envelopes. The backed-region entry
uses the existing Common Owner to suballocate byte limits within the SAME
rounded allocation; it does not reserve those backing bytes again. It cannot fund a
separate MAP_PRIVATE worker, stock Wasmtime, Python heap, loader or unrelated
Native Root/Reader allocation. Their quantities remain Unknown. There is no
public raw Ledger/pointer export and no Boolean stop or durable-ACK API.

## Build and acceptance boundary

`host-bootstrap-source.json` lists the exact package/C inputs, including the
canonical included C/header. `scripts/python_host_bootstrap_source.py` compares
the committed source blobs, working inputs and their digests before a Native
recipe consumes them. A selected build must additionally bind the exact
MoonBit/clang/SDK/runtime inputs and generated artifact digest. The source
manifest is not an installed runtime manifest or a fallback build recipe.

## Original FD-backed region adapter

The private Native adapter binds the Common backed-region/delegation to the
original Host, rounded allocation, child original and same-provider physical
range loan. Logical reservation precedes physical lending. Post-reservation
failure retains the same typed pending carrier, Common borrow and physical
record. A caller must supply an entered original backing scope; the C provider
checks the actual page window and FD backing independently of Core data.

The existing trusted physical caller may return only after that child's scoped
stop and mapped-view/FD-borrower cleanup. This API does not observe either fact
and is not a worker startup port. Physical range return precedes original Common
settlement; failure keeps the same loan for cleanup. Unknown final usage remains
conservative. Region close returns the original accounting borrow only after
children settle; allocation retirement and Host mapping close remain separate.
Independent overhead requires a separately backed selected domain and is still
unavailable in this arena-only supplier. No ordinary worker or numerical
whole-VM profile is enabled.

The bounded extent projection separates the actual FD identity, generation,
recipe and absolute page window from the original Common payload offset/length.
The immutable DATA does not carry child or loan custody. Each original loan
captures at most one projection and attempts at most one view mapping. Physical
failure preserves its same partial view; cleanup can retry that view and is
idempotent after success. Pending mapped-view retirement prevents range return
and Core settlement. Region closing refuses new mapping and cached projection
reuse, while same-view cleanup remains available. No caller FD is closed here.

The region conformance executable consumes one caller-owned private 64-page FD.
It tests live range/view custody before worker dispatch. It does not execute a
worker/VM or independently cover the mapping/FD/process/control overhead of an
ordinary product profile. The original selected funding boundaries are unchanged.
