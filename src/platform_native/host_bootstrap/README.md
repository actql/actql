# Original installed arena bootstrap

This private Native package implements the initial **selected arena** slice of
the Host bootstrap direction. It is not a public Python factory, worker funding
supplier, numerical product profile or VM allocator adoption.

The trusted installed physical supplier is the sole acquisition entry. Its
original Host reference, source, Darwin-arm64 backend, recipe and generation are
retained by `NativeInstalledArenaSupplier`. `prepare_installed_arena_supplier`
only prepares that installed intent; shape validation or matching metadata does
not authorize installation, execution, publication or recovery. SDK input cannot
supply this port. Ordinary Python Local remains unavailable until the installed
supplier and every selected bootstrap domain are actually accepted.

The initial control runtime is the explicitly trusted finite bootstrap envelope
in `host-bootstrap-disposition.md`. It includes the MoonBit runtime/Resource
objects, fixed external wrapper records and bounded custody arrays for the Host
lifetime. `control_envelope_bytes` is an installer declaration, not a Resource
grant, a measured VM bound or retrospective funding. No numerical product value
is selected in this source unit. The Native conformance fixture's declarations
and disposable 64-page arena are fixture inputs only.

## Original call order

1. The installed supplier consumes its acquisition intent once. Within the
   trusted initial control envelope, it obtains the original Resource Ledger
   and calls `reserve_shared_capacity(N)` **before** physical acquisition.
2. `bootstrap_stub.c` includes the existing `owned_capacity.c` implementation.
   It obtains one actual anonymous N-byte mapping, or `acquire_fd` maps the
   trusted caller's exact-sized original FD using the same provider. The FD is
   borrowed: its original caller retains descriptor custody and separate
   funding. Neither matching FD metadata nor this mapping supplies that grant.
   Mapping/control/child pages
   belong to the same lease. No alternate allocator or implicit growth is used.
3. `Acquired` carries the original Host; `Pending` carries that same partial
   Host, reservation and primary error. Pending acquisition is not successful
   funding. Physical close results are never ignored.
4. `claim` checks the original Host/source/recipe/generation, then consumes the
   original lease transfer once. A copied Host reference shares consumed state.
5. Child allocations reserve page-rounded `SharedAllocation` capacity before
   actual allocation. The original Host registers each physical extent before
   interpreting success. Controls and child copies suballocate the outer N;
   they do not charge that physical backing twice. Physical readers use original
   `SharedBorrow` tokens, and retirement refuses until the same readers stop.
6. Child physical retirement succeeds before Common capacity release. Failed
   physical allocation/retirement remains under this same Host. Final `munmap`
   succeeds before releasing control suballocation and settling outer capacity.
   Retries retain the original lease; successful steps are not repeated.

`acquire_fd` uses the same original intent, Ledger/reservation and partial Host
as anonymous acquisition. Invalid input or foreign nominal original is refused
before consumption or FD access. Once physical acquisition begins, failure
retains the same reservation and partial carrier. Host mapping cleanup never
acknowledges FD close, process stop or settlement of independent FD overhead.
The initial control declaration does not fund an unadopted worker or VM.

Only `physical_resources` makes accounting decisions. The wrapper forwards
cumulative delegation reports and conservative unknown-final settlement. The original logical-only delegation entry
continues to reject retained/execution byte envelopes. The backed-region entry
uses the existing Common Owner to suballocate byte limits within the SAME
rounded allocation; it does not reserve those backing bytes again. It cannot fund a
separate MAP_PRIVATE worker, stock Wasmtime, Python heap, loader or unrelated
Native Root/Reader allocation. Their quantities remain Unknown. There is no
public raw Ledger/pointer export and no Boolean stop or durable-ACK API.

## Original FD-backed region adapter

The private Native adapter binds the Common backed-region/delegation to the
original Host, rounded allocation, child original and same-provider physical
range loan. Logical reservation precedes physical lending. Post-reservation
failure retains the same typed pending carrier, Common borrow and physical
record. A caller must supply an entered original backing scope; the C provider
checks the actual page window and FD backing independently of Core data.

The existing trusted physical caller may return only after that child's scoped
stop and mapped-view/FD-borrower cleanup. This API does not observe either fact
and is not a worker startup port. Physical range return precedes original Common
settlement; failure keeps the same loan for cleanup. Unknown final usage remains
conservative. Region close returns the original accounting borrow only after
children settle; allocation retirement and Host mapping close remain separate.
Independent overhead requires a separately backed selected domain and is still
unavailable in this arena-only supplier. No ordinary worker or numerical
whole-VM profile is enabled.

The bounded extent projection separates the actual FD identity, generation,
recipe and absolute page window from the original Common payload offset/length.
The immutable DATA does not carry child or loan custody. Each original loan
captures at most one projection and attempts at most one view mapping. Physical
failure preserves its same partial view; cleanup can retry that view and is
idempotent after success. Pending mapped-view retirement prevents range return
and Core settlement. Region closing refuses new mapping and cached projection
reuse, while same-view cleanup remains available. No caller FD is closed here.

The region conformance executable consumes one caller-owned private 64-page FD.
It tests live range/view custody before worker dispatch. It does not execute a
worker/VM or independently cover the mapping/FD/process/control overhead of an
ordinary product profile. The original selected funding boundaries are unchanged.

The domain custody port retains the same Native Host/child/view through physical
acquisition, one-shot transfer, scoped use and original cleanup. A pending
domain prevents outer-view cleanup even when acquisition failed; it first
returns through its same typed cleanup carrier. Scope leave and cleanup remain
available after parent closing. Closing the domain does not release the view,
FD, parent range or logical quota. Successful domain cleanup removes the
view's backreference; successful parent settlement removes the loan's view
backreference. Closed aliases are idempotent only after the original Host and
child identity checks. No new Run/Recovery Owner or Python success inference.

## Request preparation custody

The fresh Request purpose uses the existing live-child issuer and original
domain. It retains the input-bound frame before Common starts the child.
Common alone creates its pristine preparation inventory and transfers that
same admission and body custody to Run. Initialization's started bootstrap
inventory is not reused for a Request.

Request controls must be constructed outside child allocator scopes. Scope
absence is only a lifetime requirement: the installed caller must separately
fund the exact outer constructor/control inventory before using this seam in
an ordinary command. A positive control-envelope declaration is not that
proof, and this adapter does not supply an ordinary CLI resource policy.

After Common unwinds the original body and borrowers, Native observes the
retained frame, closes the actual allocator context, reports its original
usage and acknowledges the same live access. Transferring to Run does not
require taking the old admission again. A published-but-untaken Ledger or a
lost usage report remains pending. A failed start with no published Ledger
requires physical cleanup but no fabricated usage report. A refused live
access retains its original domain identity through read-use return; absence
of that already-returned use is never itself a physical retirement proof.

## Prepared original worker material

`project_prepared_domain` checks the same current Host, region, original child,
Core ticket, view and transferred domain. It delegates logical limits to the
existing `backed_execution_delegation_description` and physical bounds to the
existing `project_backed_extent`. The result contains only immutable extent and
limits DATA. It does not expose a Ledger, nominal pointer, FD, permit or ACK.
Untransferred, foreign, closing or retired originals cannot return material,
including when an earlier extent projection was cached. Reading the material
reserves nothing and does not mark the child started or free its original loan.

The installed control forwards the same domain record rather than constructing
limits from SDK fields. A future trusted worker bootstrap must still validate
its durable original launch facts, complete independent pre-spawn funding and
current authorization before mapping or runtime work. This projection alone
cannot supply those missing facts or enable ordinary factory startup.

## Pre-spawn original channel capture

`prepare_backed_live_channel_before_spawn` retains the original transferred
Host/domain/ticket and the caller's actual already-created borrowed pipe pair
before process creation. It issues the existing Common live access once under
that same original channel record. It opens no descriptors, reserves no second
backing, and does not fund independent process, Python, loader, FD or control
domains. Complete bootstrap funding and durable provisioning remain separate.

The actual process caller later uses `bind_backed_live_channel_child` once on
that same record. A failed or lost binding response cannot select another child.
The original physical provider checks pipe identity/current and refuses copied,
foreign-process, replaced or retired records. A PID binding alone is not proof
of inherited memory, VM admission, stop, descriptor close or loan return. The
existing child-borrow/span check still precedes VM admission. The post-spawn
entry keeps its existing signature and composes the same physical phases.

Partial preparation is registered in the original domain before fallible capture
or Common access issuance. Cleanup retains that same carrier and requires the
existing physical caller's separate ACKs. Metadata retirement closes no pipe or
process and returns no reservation. This private seam does not create a
production `OriginalWorkerFunding` supplier or a normal numerical profile;
remaining connections cannot use scalar DATA or an unbound holding as authority.

## Same-channel original child resource frame

`prepare_backed_original_channel_ledger` delegates to the existing Common
`admit_backed_execution_live_child` and
`prepare_backed_original_child_ledger` on that same prepared channel, original
read use, ticket, domain and runtime reference. It issues no scalar root or
second parent reservation. The channel marks the attempt before issuance and
retains the returned frame before physical/current postchecks and the reply.
Lost replies retain this original carrier and cannot issue another frame.

The existing imported-child start/take/report/stop rules own first-use checks,
inherited limits, cumulative snapshots, conservative Unknown accounting and
retirement of escaped frames. This branch seeds no fixed VM/Host capacities.
The original physical caller must still supply complete independent process,
FD and control funding and check current physical custody for every physical
operation. Pure resource preparation is not a VM, launch or Account grant.

VM admission remains a separate one-shot step after the original child's actual
span and borrower observation. A resource projection cannot make state/limits
report a VM admission; when the frame was prepared, the later VM step checks
that same existing logical projection instead of issuing it again. Only the
original physical Owner's separate stop/alias/descriptor ACK permits retirement
of the frame callbacks. Dropping a frame or closing an Engine does not prove
process-static Rust/Mach resources retired. Normal supplier/profile and the
Python worker/VM/final physical and wheel gates remain incomplete.

## Original channel preparation transport

The installed control entry roots code callbacks for the existing before-spawn
channel and imported child frame. The private C shim preserves borrowed inputs,
owned reply/getter references and persistent empty output slots. These callbacks
are not a permission registry or a second Resource owner. A resource-frame reply
can retain the same partial frame even when preparation returns a typed refusal.

The Python physical caller prepares the original process descriptors once,
retains the same channel before foreign capture, and binds only the actual PID
returned by that process's original spawn. A lost spawn or binding response
cannot select a different child. Both descriptor preparation and spawn reject
reentry before the first supplier/current callback. The original supplier still
has to fund independent process, FD, control and VM domains before launch.

The frame's start, bootstrap reservation, current checks, immutable limits,
cumulative reports and logical stop execute in the existing Native/Common
owners. Python neither creates a Ledger nor computes usage or coverage from
limits. Logical stop and immutable DATA are not physical retirement evidence.
After the caller confirms the same original scoped stop, Host/Store cleanup and
parent-descriptor closes, it retains the successful frame bootstrap-retirement
and channel-retirement replies together before releasing extra managed aliases.
A lost release response remains Unknown even if the C output slots were cleared.
# Local C build inputs

The split implementation bodies use package-local `.h` files. The pinned Moon
build discovers those files as C-stub inputs; `.inc` files are not discovered.
Keeping these bodies as tracked headers makes an include-only edit rebuild the
original stub object and archive through the ordinary incremental build. This
does not change C contents, optimization flags or runtime ownership. Imported
provider sources still require their existing separate producer correspondence;
local header discovery does not establish that external input closure.
