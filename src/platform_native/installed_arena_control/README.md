# Non-test installed arena anchor

This private Source unit prepares a non-generic `InstalledArenaHost` entry for
the selected Native control component. The Host itself is the original anchor
passed to the existing generic NativeHostBootstrap; no BootstrapTestOriginal,
dummy Source or copied MoonBit ABI layout is used by the implementation.

`prepare_installed_arena_host` is a trusted installed physical supplier intent.
Its metadata is neither an authenticated installation nor a capacity grant.
`acquire` must obtain actual original arena backing through the existing
reserve-before-acquire Owner path, store its same partial carrier before claim,
and retain the primary issue on failure. A copied reference shares acquisition
state. Preparing another metadata record cannot consume a foreign allocation.
The normal Python factory still rejects missing complete installed funding.

Allocations, borrowers and delegations contain only their original existing
tokens plus the same Host. Accounting and byte-domain refusals remain in the
Resource/NativeBootstrap Owners. Closing can return the original physical reader
and retry the same cleanup, but cannot reopen or reset failed acquisition.
Host/supplier/backing references break only after the full original close ACK.
No new lifetime queue, ledger, Run controller or durable-recovery claim exists.

The added `NativeHostBootstrap.require_current` projects only original mutable
arena availability after claim. It is not Run, VM, publisher or worker permission.
Unrelated loader/VM/Python domains remain unknown; numeric profile adoption,
ordinary SDK entry, runtime/wheel and product E2E remain incomplete.

The five Native cases passed at exact Source
`67573de5536cda80a86578bc8815f6d78c0994eb`, run-L9cTwr, with the pinned C
backend: jobs1, child50s, outer60s/TERM5, non-Heavy. Actual generated C contains
the non-test InstalledArenaHost specialization and its prepare/acquire/current/

The private C preparation entry builds LedgerLimits from primitive arguments in
MoonBit and delegates to the same typed original constructor. This avoids C
manufacturing MoonBit object layouts. That additional entry remains uncompiled;
the original Native5 result does not prove a later Source HEAD or C shim.
Result ownership/projection, non-test emission and actual embedding remain to
close. No raw Ledger or nominal pointer is serialized on wire. API/info, VM,
Wasmtime, worker, runtime wheel and public product acceptance are not added by
this entry. Production linkage must use one original C capacity/TLS provider;
the Wasmtime artifact must not silently compile a second physical provider.

The additional C reply surface preserves the original Host and exact typed issue
in an immutable projection, alongside Prepare/Acquire/Current/Close. Prepare
success is only an intent. A zero physical-error payload still has the Physical
issue family; descriptions never determine success. Each operation invokes the
existing Host method again. A reply is a historical observation, not current
permission, a re-execution token or cleanup authority. C callers must use the
generated typed accessors rather than inspecting Result/option/struct layouts.
Four metadata-only reply cases are prepared and unexecuted. The reply helpers
and primitive entry are not covered by the earlier Source675 Native5 result.

The private backing-loan reply surface delegates borrow, current and return to
the existing Host/NativeBootstrap/SharedBorrow paths. Refusal during a foreign
target call retains the actual loan and its true original Host. Returning that
loan does not acknowledge physical stop, Host cleanup, Run cancellation or
Store commit. Existing typed issue classification is reused; no message or
Python boolean determines success. Three Native reply cases are prepared only.

The new entry roots these functions and typed accessors as noncapturing FuncRef
callbacks. Its C registration helper is intentionally not implemented from a
guessed prototype. Matching regular C emission, ownership inspection and the
subsequent thin C/Python borrower are still required before linking or using
this new entry. The prior Source4650 mixed-DLL four-case result uses the older
Sourcea312 regular C and Sourceede objects; it does not exercise these callbacks
or establish backing-loan, VM, worker or installed-product acceptance.

## Original backed read caller

The existing `InstalledArenaHost`/`InstalledArenaDomain` expose
`prepare_domain_read`, `require_domain_read_current`, `enter_domain_read`,
`leave_domain_read`, `enter_domain_read_cleanup` and `close_domain_read`.
They delegate to the original Native bootstrap domain and its existing Common
read-use borrow. There is no new wrapper, scalar funding decision or Root claim.
Normal entry checks current Host/domain; original cleanup remains available
after logical closing, without reopening or changing the original child.

Private immutable domain replies add operation tags8 through13 in that order.
The original Host/domain and typed issue stay in the reply; these tags are not
success, read permission or an ACK. Cleanup returns the extra Common borrow only
after the original C context/user/alias retirement. Whole domain close remains
child-first. Matching generated C must establish callback prototypes and RC
before adding these methods to the private C/Python transport; the existing
registered callback ABI is unchanged by this source unit. Normal supplier/profile,
F's actual caller and installed/public Python execution remain separate.
# Original live-child channel transport

The private installed entry registers typed callbacks for the same Host,
domain and `NativeBackedLiveChannel`. Preparation retains both successful and
pending channel carriers in the original domain. Immutable replies retain the
actual original Host, domain and channel even when a foreign target or a later
operation is refused. They project existing Owner results, never reconstruct
funding or permission from PID, FD, nonce, relative extent or scalar limits.

VM binding, admission, current state, limits, cumulative usage, logical stop
and metadata retirement delegate to the existing bootstrap/resource Owners.
Tags are closed: report has its own typed callback, and unknown operation tags
are refused. Missing state/limits have explicit negative sentinels. A failed
capture or binding is not retried as a new channel. Closing permits original
cleanup without admitting new work.

The trusted physical caller must retain and validate its original process,
private pipes and child Memory observation around these callbacks. Metadata
retirement requires that caller's separate physical acknowledgements; it does
not acknowledge process stop, Store cleanup, descriptor close or loan return.
The domain retains its original backing until its independent cleanup succeeds.

`installed_live_channel_conformance` consumes a disposable 64-page FD and tests
invalid-pipe partial custody through the installed public Native API. It launches
no worker or VM. Regular generated C must establish callback prototypes and
managed reference ownership before a transport shim is linked. The complete
pre-spawn supplier, numerical profile, actual VM and installed Python product
acceptance remain separate; this entry does not bypass their refusals.
