# X02: original checked Effect declarations

This component reads declaration metadata from the original
`PreparedClientEffectComputation` and `ClientEffectCompilation`. It is not a
public Effectful Plan response or an execution/approval permit.

## Existing Owner connection

`client_effect_static_declarations` verifies physical compilation ownership
and projects the existing `client_effect_member_descriptor`. Formal member
ordinal, Stage coordinate, declaration name, kind, source Result/Table input,
contract reference/CID, and declared target come from that checked inventory.
Mapping targets and Command Resource kinds have distinct alternatives.
The snapshot carries the original Program/parameter-values, compiled Plan,
Check Environment and unit identities. Those are not a complete Client
request/Invocation fingerprint, RunRef, authority scope or disclosure grant.

The Mapping's declared approval minimum comes from the same original checked
Mapping shape's `mapping_shape_member` and `member_body`. `none` and `required`
have distinct typed values. A Command's unrepresented Mapping minimum is a
third value, not an inferred `none`. Actual current permission, Checkpoint,
approval, resolved row target/change and sealed Preview are separate facts.

No current environment is substituted for the original. A separately prepared
equal Program, including one with another contract minimum, cannot be used
with the original compilation. A caller may alter its detached display array;
the next projection still reads the original checked inventory. A later
canonical wire issuer must receive the original Owners, never accept a copied
display snapshot as custody.

## Finite projection work

The existing Effect-checkpoint projection profile remains at most 64 members
and 10,000 metadata-work units. This is a readonly traversal bound, not logical
Compute work or a Ledger reservation measurement.

Before allocating snapshots, charge a conservative bound for the complete
descriptor scans, the Mapping-minimum scans, and fixed original-body reads
across all members. Do not restart that total allowance for each member.
Check subtraction before addition/division to prevent integer overflow.
Insufficient member/work limits refuse the whole inventory; no truncated array
is labelled complete. String values remain the original Owner's values.

The one-member fixture needs seven units of this conservative bound. The
two-member fixture needs twenty: four descriptor scan units, two minimum-scan
units, three original-body reads and one outer read per member. Independent
exact-minus-one cases refuse. Neither check raises a product limit.
