# Original finite policy acceptance packet

This dependent unit connects exact original metadata to the existing Native
acceptance transaction and adds a current adopted-Host accept/read seam. The
ordinary CLI, new-install selection and public legacy upgrade remain unfinished.
The genuine parent is finite-profile #1711, source
548e66c8c343229f16f02a554d80b346941ea17e.

The private closed `actql-local-run-policy-original/0.1` record binds the actual
original Host adoption and read-selection CIDs, exact finite profile bytes,
original SubmissionReference/request bytes, Run Definition CID, first issuance
time and already issued retention Policy bytes. The existing bounded Local
original codec preserves raw nested string bytes, rejecting missing, duplicate,
extra, noncanonical and over-budget material. The schema describes only shape;
a shape or copied CID cannot prove authenticated custody or current permission.

The binder requires original Submission/request correspondence and the supplied
Run's first created_at/valid_until to match the unchanged 24h finite Policy.
Deletion remains 48h and metadata remains 7d. The reader admits the saved Policy
through its existing Owner and validates the saved issuance time and references.
It neither samples a new clock nor issues a replacement Policy.

The existing Run row writer has an optional private original-policy packet.
Absent-field legacy bytes and the old ClientRunJournalEncoding type remain
unchanged. The old reader refuses the new role; an additive tuple projection
returns the old fields plus raw packet bytes for the Native Owner's subsequent
readmission. This raw projection is deliberately not nested policy admission.
The 131072-byte/32-node/4-depth Run row and 8192-byte/64-node/4-depth original
codec limits are unchanged; packet string bytes are limited to 8192.

The Native binding retains the actual selected profile/run/read/retention/store
files and their original physical generations. It admits the profile against
the actual selected Result Policy and dependency bodies. New acceptance checks
the current Account's run submit, publish and read tuples separately; lookup
checks current run read without acquiring submit/publish authority. The existing
opaque preparation and authenticated epoch checks remain in place. Native saves
Run, packet and submitted intent in the same existing acceptance transaction. Existing accepted
or merely pre-existing Runs with missing packets cannot receive late backfill.
Exact saved bytes may be reused; changed/foreign bytes refuse. Unknown COMMIT or
lost ACK cannot issue another Policy, create a new Run or imply retry permission.

Original Result retention, current read permissions, stdout purpose and grant
issuance remain separate. A packet does not convert an old absolute read policy
into rolling egress. Explicit new-install profile selection and the public legacy
upgrade append, including current authorization, original custody, response loss,
restart and ordinary installed Darwin consumption, remain mandatory #1701 work.
No actual Native execution/transaction, public/installed next-day E2E, new
producer, Heavy, Hosted CI or Provider operation is claimed by this packet unit.

The three Native transaction definitions cover same-byte repeat/reopen, missing
accepted-packet backfill refusal, and current-fence loss with rollback. Until a
matching physical diagnostic executes them they are compiler evidence only.
The caller still must look up the original request before issuing a new Policy;
neither the binding nor its lookup samples a clock or invokes the Policy issuer.
