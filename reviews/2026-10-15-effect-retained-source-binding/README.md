# Retained Effect Source installation binding

This child of the mixed installed-capacity connection retains the existing row
Source owner's `ordinaryRecoveryBinding` in its original Effect source scope.
The closed installation-binding shape and validation remain in the existing
ordinary Source binding module. The continuation does not dispatch a provider,
rebuild an original target from current configuration, or issue a new grant.

A newly bound continuation uses the distinct Host-private
`actql-acquired-effect-bound-continuation/0.1` form. The original
`actql-acquired-effect-continuation/0.1` shape and all-DuckDB legacy bytes are
unchanged. Each issuing adapter's original preparation is used once; a mixed
scope may contain one existing DuckDB scope and one installed row scope. Exact
Source/occurrence/target/evidence comparisons and the existing current authority,
Ledger, encrypted Store and cleanup owners are retained.

Recovery compares the saved binding against the current installed owner's
binding as part of the entire original scope. Missing capability or changed
connector, registration, revision, binding CID, physical target or saved capture
scope refuses before restoring the capture. A historical row scope without a
retained binding is not upgraded from today's configuration. It remains an
insufficient original input and its Run/Unknown/custody is preserved.

Thirteen independent pure Node controls use explicit in-memory checkpoint and
opaque capture doubles. They cover correct mixed scope retention, exact binding
changes, missing/extra fields, owner loss, target/capture-scope changes, malformed
issuer output, unchanged legacy bytes and refusal to promote an unbound row
scope. The original preimage yielded 2 passing and 11 failing controls before
the connection. It is retained separately and never becomes a public PASS.

`prepared-checks.mjs <clean-source-sha>` runs those controls, existing acquired
Effect and ordinary Source binding controls through the nonzero Node wrapper,
60-second outer / 30-second child / five-second TERM budget. These tests do not
perform Source I/O, Host/Run/DB operations or actual encrypted restoration.
The real DuckDB + metadata-only GCS + separately approved Local Iceberg write
and different-process recovery still require one normal installed cohort.
