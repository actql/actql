# Grouped String PIVOT buckets: independent Frontend connection

Baseline: `fdd0c76c7975905740078e93c735f910135bafd1`, tree
`589cdee3addd986868f2a33661b75f71d4d613cf`. This is a separate small unit
following the completed multi-column UNPIVOT acceptance. It does not reopen
that cohort, the nullable-contract gap or the untyped NULL set-context control.

## Counterexample and selected meaning

```sql
FROM orders
|> PIVOT(COUNT(amount) FOR status IN ((('open')) AS opened, ('closed')))
```

At the baseline, `QueryParser::pivot_clause` requires the expression root to be
`StringLiteral`. Parentheses produce a `Parenthesized` root, so the same static
String bucket cannot reach the existing common PIVOT operation. This is a
source-inspected counterexample, not a claimed executed pre-fix refusal.

The pinned GoogleSQL reference `d82db99a923a46571f543a13899dc791a7b6f743`
requires a constant PIVOT value (`docs/query-syntax.md`, rules for value).
`googlesql/analyzer/resolver_query.cc::ResolvePivotInClause` resolves the value
expression and checks `IsConstantExpression`; it does not require a literal AST
root. The [official PIVOT reference](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/query-syntax#pivot_operator)
also distinguishes constants from unsupported variables/query parameters.
This change connects transparent parentheses around the already adopted String
literal subset. It does not claim support for every constant expression or
numeric PIVOT, and it adds no evaluator, Owner, casts or fallback.

## Implementation and independent obligations

- Unwrap only `Parenthesized` nodes in the shared PIVOT parser. Both Pipe and
  FROM-postfix callers use it. Existing parsing node/depth/work limits remain.
- Preserve decoded String bytes, IN order, explicit aliases and all aggregate
  and axis arguments. Keep parameters, numeric/NULL and computed bucket values
  refused by the same selected-profile diagnostic even when parenthesized.
- Compare Pipe and FROM lowering with the independently written complete
  ordinary Programs in their existing MoonBit tests; then invoke the common
  checker. Expected Programs are not generated by compiling the text.
- Add two normal and four refusal cases to the existing PIVOT public fixture
  and normal corpus. Independent duplicate/NULL input produces
  `[{product: "kale", second: 0, first: 2}]`, in that column order. COUNT ignores
  the NULL sales value; two duplicate Q1 rows count twice. The String bound is
  four UTF-8 bytes; both count fields are non-NULL Number.
- `pre-pivot-grouped-string-values-identities.json` preserves the complete
  baseline grammar and Values Run preimages. The grammar/rules change only
  grammar-bound Template/Executable/Compiled/Run identities, not the Values
  Unit, proof, ResultPlan, Program or semantic Program identity. Current expected
  identities use the independent hand-assembled vector, never a product CID.
- The public inventory is independently enumerated from authored registration
  data: 3,888 registered occurrences, not 3,888 executed cases. Previous fixtures
  and their expected values are unchanged. No new public selector is added.
