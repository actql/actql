# Exact hexadecimal query integer literals

Baseline: `599f487bbb0be365320706ad28eab972448ed75d`. This is an independent Frontend unit; submitted #1453/#1458/#1461 heads are unchanged.

## Counterexample and selected contract

`SELECT 0x10 AS value` cannot reach the ordinary numeric literal `16` on the baseline: source inspection finds that the decimal scanner consumes `0`, then rejects the identifier-start `x`. This is a source-derived counterexample; B has not executed a baseline compiler/runtime reproduction in this unit. The authored tests must fail before the change and execute after it in an independently authorized bounded review worktree.

[GoogleSQL integer literals](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/lexical#integer_literals) permit decimal digits and `0x`/`0X` hexadecimal digits, with optional unary signs. The selected ActQL value contract still admits finite binary64 `number`, with integer magnitude at most 2^53-1. This patch connects the exact subset and refuses larger integers before floating conversion. It does not implement full INT64 or silently round it. Existing negative-zero refusal remains.
