## Cancellation and cleanup custody

One existing long-name two-child chain reaches real input preparation and a
nested producer-read cursor. A test-only delayed child uses the existing owner
with false, error, then successful cleanup. The fixture issues parent cancel,
observes its stopped poll, and checks that the same child, completed output,
completed Array, preparation and read cursor survive both pending cleanup calls.
Successful cleanup clears the owning state and cancels the nested preparation;
repeated cleanup does not call the child a fourth time or restart Compute.
These are Native finite correspondence checks. The fixture itself keeps explicit
references to inspect the values after cleanup: state release is not physical
reclamation, a Ledger holding generation, or last-consumer destruction evidence.
