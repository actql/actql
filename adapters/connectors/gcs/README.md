# GCS provider ownership

The portable `connectors/gcs/catalog` package owns exact object metadata,
conditional physical request material, logical metadata projection and request
identity. `connectors/gcs/host_node` is a typed compiler bridge, not another
interpreter. The existing installed Source/Effect, Credential, Store and Run
owners continue to own admission, approval, durable claims, response capture,
reconciliation and cleanup. A private function's existence does not publish a
capability or make an installation available.

## Original object request

`ObjectMetadata` retains the admitted physical fields and digest of the actual
input bytes. Its private projection emits generation, metageneration and size
directly as exact decimal text from Int64; this control DTO is not a public
String-typed Source schema. A public exact-number Source must use the matching
existing value contract and retain the provider's original range checks.

`ObjectMutationRequest` retains its original binding, metadata, exact body and
path, request CID, canonical authored changes and intended logical after-state.
The request identity still hashes the same original physical preimage. Neither
the body nor the authored value is regenerated by the Node adapter. Its
before/after view is intended Preview data, not an observed resulting version.

The exact `actql-request` reservation and logical/physical distinction are
normative in [the Connector/Mapping contract owner](../../../docs/spec/protocols/contracts.md#gcs-private-request-metadata).
The logical projection excludes that one key only. Empty user-map replacement
explicitly removes old user keys and assigns the current marker. This finite
request profile refuses explicit NULL maps/values and unsupported clear
representations; it never substitutes empty for NULL or claims complete Mapping
null support. It preserves all other keys and text without normalization.

## Same binding and transport

The private Node projection retains the real MoonBit handle through its
language-lifetime association. A copied JS object, equal body/CID, or copied
permission binding cannot substitute the original handle. This association is
not a new resource owner, permission, durable claim or physical cleanup ACK.
Its backing and escaped borrowers remain in the existing preparation inventory.

`sendOwnedGcsObjectRequest` borrows that original physical projection and calls
the existing scoped Credential invocation exactly once. It requires the exact
operation and origin, forwards the original authorization and finite physical
clamps, and leaves content framing to the existing HTTP owner. The caller must
already hold the existing Effect owner's fresh durable dispatch claim. This
function does not issue that claim, retry, reconcile, or classify apply.

The returned response retains the original body backing and headers. Rejected
responses remain observations; thrown failures, including private pending
cleanup carriers, propagate without decoration or replacement. A lost reply
does not become a known failure or permit resend. The original Effect/Store
owner must retain and reconcile it. Neither matching payload nor marker DATA
alone is an applied receipt. The pre-send version guard is not reconciliation.

## Lifetime and limits

Metadata wire/node/depth/entry bounds, physical path/body/identity bounds,
explicit projection bounds and physical request/response clamps are distinct.
They are finite representation ceilings, not a reservation or byte quote.
No default capacity, Model grant or normal numeric profile is issued here.

The preparation envelope must include the original physical metadata graph,
binding and permission references, body/path/CID, authored-changes String,
logical after-state, detached before/after JSON trees and parsed projections,
canonical/UTF8/hash workspace, frozen request/control records, association
record and caller closures. Shared String/Buffer backing is charged once under
its actual owner while distinct records/views and simultaneous copies remain
separate. Response body/headers, awaiting Promise/authorization/signal aliases
and any failed-close custody overlap that preparation until their actual
owners acknowledge retirement. Dropping a JS reference, WeakMap membership,
GC opportunity or callback return is not physical cleanup evidence.

## Collection target material

`ObjectCollectionBinding` derives the existing Mapping collection identity body
from the explicitly selected target, resource kind and exact project/bucket/
prefix. Its ResourceRef wire reuses the existing GCS provider/scope domains and
the selected Catalog boundary. It does not infer writes from a Source alias.
The installation identity is retained in the original opaque binding, not
silently inserted into an existing identity domain. Equal resource wire from
another installation cannot substitute that original binding.

`prepareGcsCollectionTarget` is a typed DATA adapter, not a ResourceIssuer. The
existing installed Common receiver must separately admit and retain its exact
Mapping/Command pair, actual installation/current matcher and original issued
ReferenceValue. A copied frame, wire or CID cannot restore that custody. No
installation, currentness, STORE dispatch, recovery or send grant follows from
the synchronous DATA guard. The intended collection resource kind must match
the actual checked Command target; this helper does not publish that Command.

The existing preparation envelope must include the original binding, immutable
project/bucket/prefix/target/installation aliases, collection/reference wires,
CID strings, canonical JSON trees, UTF8/hash workspace and transient provider/
scope identity strings. The JS projection and private association add their own
records/references. Three separate representation clamps do not make their
peak overlap a funded bound. Retain escaped borrowers through the original
receiver's actual lifetime; WeakMap membership or deletion is not physical ACK.

## Upload declaration closure

The portable `object_upload_command_json` supplies the real GCS upload
declaration. Its inline Command input and original `command_input` Envelope
contain the same complete closed presence record. `content` and `name` are
required; `content_type` and `overwrite` may be absent but are non-null when
supplied. The typed ContentRef has no media restriction and is never reduced
to a String, JSON payload or fabricated reference. Array order remains in the
preimage. The role is the explicitly adopted Command-only extension, not a
general optional Object ValueContract or an upgrade of legacy role bytes.

`object_upload_catalog_json` preserves the original declaration's SourceViews,
evidence and manifest while adding complete original roles and the Command to
its Catalog. It checks the old complete registry correspondence and Catalog
self-identity, rejects conflicting declarations, and returns `command_bodies`
for the existing Common environment assembler. The final Catalog is self-sealed
under the same initial 0.1 identity domain, not the previous Catalog CID.

`object_upload_mapping_json` borrows the original collection binding and emits
the exact Mapping-to-Command relationship for `connector://<id>/objects`.
Its complete target schema retains all four field contracts, including the
ContentRef. `primary_identity: null` remains collection-only `create/none`;
the four exact field-set rules do not admit row STORE or invent a row key.
The fixed Command's declared requirements cover both creation and explicit
replacement/readback: `storage.objects.create`, `storage.objects.delete` and
`storage.objects.get`. These are static requirements, not inferred permissions
or a stronger credential identity. Approval/current authorization remain with
their original owners. Optional fields are never assigned defaults by these
declarations. Overwrite conditions belong to original Preview/physical request
preparation, not to a refreshed Catalog observation after approval.

The typed Node adapters use the existing checked Result facade. They return
bounded immutable wire DATA, not a ResourceRef issuer or an installed original
selection. The Mapping adapter borrows its original collection association;
copied JS frames cannot recover that handle. Actual Common admission must
validate every declared contract, the original Catalog/environment/pair and
the selected installation before the existing trusted issuer supplies a target.
The new `published_store` canonical selector is an independent Common change;
no hidden Source/Result/Values field or Parameter Ref is introduced here.

Declaration construction retains input wire, strict parser tree, ordinary JSON
tree, canonical/hash/writer workspace, original/new Catalog and registry arrays,
role/Command/Mapping representations and typed projection/callback records
through their actual preparation lifetime. Repeated string parsing and escaped
borrowers are not free. Bounds limit representation sizes, not aggregate
funding, physical retirement or a normal numerical profile. The read-only
installation is not silently activated for writes by these DATA functions;
upload transport, exact Content acquisition, physical issuer/currentness,
reconciliation and normal installed approval/restart acceptance remain needed.

## Exact object metadata pages

`admit_object_metadata_page` shares the existing strict, bounded metadata
parser and field checks with single-object GET admission. It parses the original
response once, checks every item under the same scope and whole-page node/text
bounds, and exposes no partially validated page. Generation, metageneration
and size remain exact nonnegative Int64 values, including values above the
binary64 safe-integer range. Empty pages retain their exact continuation token;
an absent member is not NULL or an empty String. Unexpected nonempty prefix
pages remain unavailable for this flat, delimiter-free physical profile.

The opaque page retains its complete original response digest. Detached item
fields hide only the exact private request marker and cannot mutate the page's
metadata array. They are not single-object `ObjectMetadata` observations for
mutation, issued Resource references, scan completion or apply receipts.
An individual member is not reserialized into a supposed original GET response.

The existing Decimal(19,0) carrier can preserve each checked Int64 coefficient
and emits its specified decimal wire as JSON text without binary64 conversion.
This is not a public String alias or permission to widen the GCS integer domain:
GCS rejects Int64 overflow even when the wider Decimal contract could represent
the coefficient. The current installed `files` view and its seven-column
LIST_FILES projection are unchanged. The separately documented `gcs.objects`
field set still needs its full original Source schema, physical page receiver
and SDK/installed matching acceptance; this primitive does not claim them.

The physical raw page, strict parser/decode trees, item array, per-item records,
exact strings and metadata arrays, detached logical views, digest workspace,
decimal admission/emission and pending physical callbacks can overlap. The
same Source reservation must cover their actual lifetime before acquisition;
page clamps do not establish that aggregate funding or retire an outstanding
read/cleanup responsibility. No normal numerical profile is introduced.

## Verification boundary

The catalog white-box tests execute the portable semantics with independent
request byte/CID expectations. The Node tests consume the actual compiled GCS
bridge and the existing scoped invocation helper, using explicit physical
counter/failure ports. They test exact values, nominal refusals, changed
generation/metageneration, pre-I/O refusal, raw backing and primary-failure
identity. These ports do not prove genuine Core authorization, durable
Effect/Store reconciliation, installed public acceptance or live GCS service.
