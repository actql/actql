# GCS provider ownership

The portable `connectors/gcs/catalog` package owns exact object metadata,
conditional physical request material, logical metadata projection and request
identity. `connectors/gcs/host_node` is a typed compiler bridge, not another
interpreter. The existing installed Source/Effect, Credential, Store and Run
owners continue to own admission, approval, durable claims, response capture,
reconciliation and cleanup. A private function's existence does not publish a
capability or make an installation available.

## Exact ordinary object rows

The ordinary `updated` field enters the existing exact UTC Timestamp contract.
The portable GCS owner converts RFC 3339 whole seconds, up to nine fractional
digits and offsets to the same UTC instant, with no Host Date parser or
binary64 conversion. Millisecond values retain their exact `.SSSZ` bytes;
finer values keep only significant extra digits and are never rounded.
The original provider spelling and physical page digest remain unchanged.
The original physical spelling, calendar and offset grammar and range checks
remain in force; more than nine fractional digits still refuse. The bounded
temporary timestamp prefix/fraction/zone/output strings, exact seconds and
nanosecond fields, and existing calendar conversion workspace
belong to the same Source parser/row envelope, not a free byte grant.

Ordinary and keyed physical RowRun pages use the shared preserving UTF-8/JSON
decoder, then the existing checked row and Value contracts. JSON payload keys
are data, including distinct NFC/NFD spellings and a literal `$json` key. The
decoder does not repair physical field names into the schema: undeclared keys,
missing required fields, exact duplicates, invalid UTF-8 and all original
page/node/depth/capture limits still refuse the complete attempt. Source
capture/export/reopen must preserve these original admitted values, not use a
newly reconstructed provider response or a freshly issued permission.

The standard provider-backed installation publishes `objects` as a genuine
ordinary Source beside `files` and `contents`. It does not fabricate a Source
field to carry a collection STORE target. The seven-column listing declaration
remains byte-identical. Ordinary `contents` declares the five public columns
`resource`, `version`, `name`, `media_type` and `content`, and the complete
extended Catalog has its own CID. An explicitly supplied source-only legacy
installation keeps its original two views, including the three-column
`contents` carrier.

`object_listing_prefix` interprets the original typed Request before I/O.
Absent or NULL prefix selects the installed prefix; an explicit prefix may
only narrow it. Unicode, percent text and page tokens are never normalized or
translated into a glob. The ordinary scan follows empty continuation pages
and refuses repeated tokens or an exhausted page/row ceiling without issuing
completion. The existing Source/Credential owns current read admission before
each send, original physical response charges, RowRun capture and cleanup.
Flat scans request no delimiter; unexpected nonempty prefix pages still refuse.

Installed and physical prefixes use the same opaque Unicode scope: bounded
UTF-8 and well-formed scalars, without header/identifier control-character
restrictions. The original query encoder percent-escapes them; it does not
normalize, decode percent text or widen a prefix. Object names still separately
reject CR/LF. The returned name and generation, original page/body charges,
credential scope and exact prefix containment remain unchanged. This repairs
prefixes containing otherwise legal object-name controls, not a new grant,
reservation or installed/live-service acceptance.

The portable parser checks every item and preserves exact Int64 generation,
metageneration and size before projection. `objects` declares these fields with
the existing `int64` logical contract, not a Decimal, Number or String alias.
The provider's nonnegative signed Int64 check remains authoritative. Ordinary Source DATA contains an
unwrapped metadata object; only the Value Owner emits the `$json` wire envelope.
User keys literally named `$json`, decomposed text and CR/LF values stay DATA.
Only the exact reserved `actql-request` key is hidden from logical reads; the
physical page and its digest retain it. Missing provider metadata becomes SQL
NULL, while an empty reported object remains `{}`; explicit provider null is
invalid metadata. This is not a general missing-to-null repair.

The original physical page and RowPageCharge, bounded parser tree, detached
metadata fields and filtered entry array, per-row canonical writer/String,
parsed row objects, Resource DATA, row array, normalized UTF-8 encoding and
retained capture may overlap. They remain in the original acquisition's
retained/execution and caller workspace inventory until their actual retirement;
clamps, callback return, weak references and GC opportunities are not funding or
physical cleanup ACK. No new reservation, numerical profile or Model grant is
introduced. The Source still uses the existing before-I/O RowRun reservation
and transfers the same raw charge into ordinary page admission.

Focused tests distinguish actual compiled GCS parsing and actual Value/Command
schema consumption from the controlled physical port and reference callback.
Existing public Local/HTTPS empty-path checks prove no-I/O connectivity only.
Installed nonempty service reads, complete pushdown/ordering obligations,
same-Run restart and live GCS acceptance remain separate required work. A JSON
Result needs its original ordering evidence; the caller test retains the
unordered refusal and uses an explicit checked uniqueness/sort for publication.

## Exact content companion columns

The ordinary `contents` carrier includes `name` and `media_type` beside the
original `resource`, exact generation `version` and issued `content_ref`.
Both strings are borrowed from the same checked metadata that preceded the
verified media read. They are not copied from configuration, normalized or
resolved again after capture. In particular the reported MIME spelling stays
unchanged in the string column; ContentRef's checked descriptor projection
remains with the existing capture/Value Owner.

The explicit source-only legacy installation and its body-only transport keep
their earlier three-column carrier. The ordinary carrier and Catalog have
different identities; an old capture cannot be relabelled with the new schema.
The checked response-port columns are selected before the first await, so a
three-column declaration using the modern parser still receives no undeclared
companion fields; a mutable caller Array cannot widen that selection later.
The seven-column file listing, resource/version lookup correlation, read
authorization, original charge tickets and no-retry behavior are unchanged.

Two additional String references in the emitted row extend the original
metadata/report lifetime through capture; bounded row serialization, encoded
bytes and retained output still overlap the same Source reservation. No
clamp, successful callback, timer or weak reference is a capacity grant or
physical release ACK. A failed/cancelled handoff retains the same Content
custody and pending media charge rather than manufacturing a partial row.

## Original object request

### Original ordered composition

The existing portable GCS Owner seals a bounded composition from the original
collection/Command DATA binding, observed destination and original source
metadata. The same bucket/scope, source order, repetitions, exact generations
and destination generation/metageneration stay in the physical request. The
new operation marker replaces only the reserved protocol key. No source is
deleted. The expected size remains Int64, and CRC32C is composed algebraically
from the exact source checksums/lengths without downloading their payloads.
One request contains at most 32 sources and the provider's 5 TiB object ceiling;
smaller explicit Host/body/path/identity clamps remain independently enforced.

The [finite metadata profile](../../../docs/spec/protocols/contracts.md#gcs-compose-destination-profile)
selects captured destination user metadata/content type for replacement, or
the first original source's content type and an empty user map for an observed
absence. It is not provider-default inheritance. The original raw responses
and exact marker remain in the private request identity; the logical projection
omits only the private marker value and declares its assignment. This unit does
not preserve ACL, encryption or retention fields, support arbitrary encoded
representations, or infer absent objects from failed reads.

The three-field composition binding borrows the same existing collection/Command
binding. Its request retains original destination/source handles, a copied
source-reference Array, selected user-metadata Array, body/path/CID Strings,
marker, size/checksum and exact intended properties. Temporary JSON/maps,
bounded writers, permission/source-response views, decoded checksum bytes and
two 32-element UInt matrices can overlap the original metadata/response and
subsequent physical body/Promise. Neither scalar clamps nor a bounded matrix
count is a resource reservation, native exemption, byte price or normal Model
four-role profile. Original acquisition/capture funding and real retirement
remain obligations of the installed caller.

The private typed Node projection additionally retains a WeakMap association
with the exact provider/binding/request handles, a copied source-handle Array,
the bounded parsed Preview tree and deep-frozen nested maps/arrays. Body
projection borrows the original String; scoped invocation adds its own request,
authorization/credential envelope, operation Map, closure and pending Promise.
Direct-response parsing and logical projection overlap the original response
backing, parser/tree/writer and returned JSON/String view. These aliases and
temporary copies stay in the same caller's inventory until its last real
borrower and cleanup duty retire; WeakMap/Promise completion is not that ACK.

The method's [explicit preconditions](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/compose)
and [composition/integrity semantics](https://docs.cloud.google.com/storage/docs/composite-objects)
are selected without a live service call. Pure consistency or a matching
response does not authenticate the existing Effect's retained dispatch claim.
Installed Command declaration/capture, actual Site read/write admission,
saved same-Run recovery and normal-distribution/live acceptance remain separate
requirements; this primitive does not advertise those unfinished boundaries.

The original raw response, three header tuple wrappers and borrowed Strings,

actual original read admission, Content byte borrow and saved Run restoration
remain separate required connections; this primitive does not publish them.

### Original mutation preparation child

The private `createGcsMutationRequestChild` is an I/O-free synchronous factory
for the existing capture cleanup protocol. Capture must retain it before
`prepare()`. Its original caller supplies the justified preparation envelope,
separate same-row read approval, original Credential/Site and synchronous
current fence. Selected `maxSecretBytes` is mandatory; it has no default and is
not funding. This unit does not install a normal supplier, add a permission or
turn a DATA capacity declaration into a reservation.

Preparation validates the selected binding kind/path/ABI and snapshots the
admitted changes before the first await. It requests the original read approval
once, creates one existing Credential binding and retains the original GET
before the provider builds its exact conditional request. Repeated prepare
calls share that same Promise; no failure or release starts another read.
Parent capture must still compare the request's facts/CID with the original
Program and hold all downstream borrowers through apply/Unknown/recovery.
The generic guarded preparation receiver remains a separate connection.

Release first invalidates use of this child's request, then drives only the
same Credential binding and any original failure's cleanup handle. A pending
prepare, invalid asynchronous fence, pending Credential close, false/rejected
same-handle cleanup or malformed cleanup facet stays with the child. The
primary error is never rewritten, including frozen/read-only diagnostics and
ordinary null/undefined throws. There is no reacquisition or resend. Only after
those duties retire are this child's raw response, request/preparation Promise,
original configuration and method aliases detached; the old request can no
longer be sent through its private original map. Escaped status snapshots are
immutable. This is component custody, not a claim of heap/GC ACK or retirement
of a later write, an escaped caller alias or a numerical Store loan.

The new child/control/lifetime records, original configuration/fence/callbacks,
single preparation/release/fence Promises and handlers, pre-await changes wire
and Buffer, raw GET, parsed before metadata, conditional request/body and
failure/cleanup/method references overlap the existing capture envelope.
No body/secret clamp, callback return or weak-map deletion prices that overlap.
Focused controls use the actual GCS compiler bridge, a fresh real FD failure,
and the actual existing Credential binding before TCP. The success response
ports and Credential claim controls are explicit doubles, not genuine Account
approval, normal installed metadata/update/delete acceptance or live GCS.
An additional actual capture-receiver counter executes the unchanged Common
cleanup progress law from the qualified retained runtime and proves that the
same pending FD child blocks input/Result/Source retirement. It checks that
law's current source equality; it is not a fresh whole-Common build or proof
that all compiler inputs match the latest installed product cohort.

### Exact stored gzip Content

The version-fixed content transport admits `contentEncoding: gzip` only as a
stored representation selected by the original metadata response. Its media
request explicitly uses `Accept-Encoding: gzip`; metadata still uses identity.
For a nonempty gzip object, the same request selects the one complete stored
byte range `0..size-1` derived from that metadata, with no added attempt. A 206
reply must declare exactly that full interval and total; a 200 reply is usable
only without a Content-Range and still must pass the same complete byte checks.
Generation and metageneration conditions, original request observation and
current Credential/Run scope are unchanged. A matching gzip response header,
the original stored size and checksums are required before the same raw Buffer
is handed to the existing Content capture owner. No gzip codec, transparent
decompression, new attempt or alternative latest-version request is used.
Identity reads keep their original request bytes and behavior.

Missing/changed media representation, incomplete/foreign `Content-Range`, transformed or
corrupt bytes, over-limit metadata and changed version headers still refuse.
All actual response tickets and already-transferred bytes remain with the same
RowRun/capture/Store cleanup owner; refusal or callback return is not cleanup
ACK. The new bounded encoding field borrows the admitted metadata spelling,
and its request/response/header views overlap under the existing envelope.
It is not a new reservation, grant or normal numeric profile.

This closes the exact full-object gzip representation path, not general
partial-range assembly or live GCS/installed acceptance. A partial response
still cannot become a complete ContentRef. The Google Cloud
[transcoding contract](https://docs.cloud.google.com/storage/docs/transcoding)
explains why identity negotiation or an ignored Range cannot prove stored-byte
fidelity. A provider representation that does not satisfy the retained size,
encoding and checksums is refused even if its decoded content looks correct.

`ObjectMetadata` retains the admitted physical fields and digest of the actual
input bytes. Its private projection emits generation, metageneration and size
directly as exact decimal text from Int64; this control DTO is not a public
String-typed Source schema. A public exact-number Source must use the matching
existing value contract and retain the provider's original range checks.

`ObjectMutationRequest` retains its original binding, metadata, exact body and
path, request CID, canonical authored changes and intended logical after-state.
The request identity still hashes the same original physical preimage. Neither
the body nor the authored value is regenerated by the Node adapter. Its
before/after view is intended Preview data, not an observed resulting version.

The exact `actql-request` reservation and logical/physical distinction are
normative in [the Connector/Mapping contract owner](../../../docs/spec/protocols/contracts.md#gcs-private-request-metadata).
The logical projection excludes that one key only. Empty user-map replacement
explicitly removes old user keys and assigns the current marker. This finite
request profile refuses explicit NULL maps/values and unsupported clear
representations; it never substitutes empty for NULL or claims complete Mapping
null support. It preserves all other keys and text without normalization.
