# Installed HubSpot row Source

The normal installation table selects this Source factory. Its component tests
use actual separately compiled Common and HubSpot runtimes, the original
Account/Credential owners, SQLite and loopback HTTPS. This is not evidence of a
pristine installed distribution, live service, adopted numerical profile or the
complete HubSpot read/write target.

- Responsibility: supply original account/property metadata, physical target
  binding and requests to the existing generic installed row Source. The Common
  declaration, checked Program, Account decisions, RowRun, capture and cleanup
  remain with their original owners.
- Inputs and outputs: a closed explicit Source/Site profile and bounded complete
  original metadata bytes produce the Common full relation declaration. Every
  observed property goes through the existing provider value contract; unknown
  types refuse rather than disappear. The factory exposes the standard Source
  port, never raw credentials or a parallel acquired result.
- Identity: bind connector, canonical portal, origin, original metadata, Site
  generation, runtime and Account context. The top-level original record id is
  a conditional declared candidate key. Provider page admission and cross-page
  duplicate checks must succeed before capture; company domain is not a key.
- Ownership: the generic Host retains the original acquisition, one borrowed
  response/cleanup port and the same private Credential binding. The connector
  installs that cleanup callback before I/O. Initialization failures retain any
  already acquired Site on the existing cleanup carrier.
- Synchronization: separate current Account decisions cover data, account
  details and properties. Each operation has its own authorized nominal use;
  current checks surround awaits and the physical send. The retained binding
  prevents a resolver rotation from substituting another account's token.
- Failure: preserve original codes, complete received observations, physical
  Unknown and cleanup custody. Schema drift, duplicates, foreign metadata or
  exhausted bounds refuse a complete Source. No replacement lookup, partial
  capture or implicit retry is performed.
- Cancellation: forward the original signal. Cancellation is not a close ACK;
  the original RowRun response cleanup and Credential binding must confirm
  retirement before releasing the original retention.
- Resources: the trusted installer supplies independent positive response,
  parse, page/request/row, schema/output and secret limits. Every received
  identity/schema/data body is charged to the same original acquisition before
  decode. These units and the cleanup callback do not establish wholephase
  simultaneous retention funding or a normal numerical profile.
- Extension: use the normal connector bundle generator and existing Common
  declaration/Account/RowRun APIs. No connector-local ledger, finish/capture
  owner, permission fallback, sampled schema or Provider URL redirection.
- Verification: `../test/installed-hubspot-source.test.mjs` checks full decimal
  and array schema, exact record ids, same-RowRun capture, separate metadata
  permission, current token rotation, foreign originals, cross-page duplicates,
  final schema drift and cancellation. `../test/hubspot-object-schema.test.mjs`
  retains independent full schema and key-fact expectations. Execution/runtime
  source and artifact correspondence are recorded separately from this source
  reference; no current distribution or public acceptance is inferred.
