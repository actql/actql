- Responsibility: HubSpot adapters prepare one original UPDATE request and decode Account, complete property Catalog and selected target observations. The existing common row Effect retains Program admission, Preview, approval, current checks, durable claim, dispatch and cleanup. These helpers alone do not register an installed Effect.
- Inputs and outputs: The same installed Catalog and Mapping produce a logical request, then a marked physical request using the common owner's original dispatch key. Describe reads Account and schema. Each target observation reads Account, schema-before, the exact target and schema-after. Native projectors retain decimal strings, array values, complete schema correspondence and response bounds.
- Identity: The logical request binds connector, HTTPS origin, portal, resource, Mapping reference/CID, existing marker property, complete value and selector. The physical identity additionally binds the actual dispatch key and complete marked body. A target version binds portal, object type, Mapping and the complete canonical typed row including its update timestamp. A digest supplies no authority or atomic provider comparison.
- Ownership: Private request and current carriers belong to their original adapter instance. Cold request restoration reconstructs through fresh Native originals and compares complete saved wire and both identities. Foreign or copied carriers are refused. Source and Effect share the same Native Account identity projection rather than separate validation rules.
- Synchronization: Named credential read slots select distinct original member or row operations inside the existing total-operation limit. Fixed metadata resources use their own Account read decisions. Only the exact target slot consumes the retained same-row target authorization. Fresh current checks and the existing physical Credential binding remain mandatory before every send and after every read.
- Failure: A rejected HTTP outcome, foreign portal, changed Catalog, wrong/missing/archived/duplicate target, incomplete response, malformed marker or changed restored body is refused. Private failure custody retains the original received response sequence. Nothing classifies these failures as absence, permits a write or authorizes a resend.
- Cancellation: Original signal/current refusal propagates without completing a target observation. A synchronous response projection must finish inside the original physical child; asynchronous callbacks or pending results cannot acknowledge projection completion. Existing failed/pending physical children remain the common owner's cleanup duty.
- Resources: Request and read constructors use captured immutable limits. Named slots do not raise operation, transfer or response limits. Each read retains its original funded response extent until Native decoding completes. No new quantity price, Owner, ledger, cache or reusable permission is introduced. The installing recipe must fund all constructors and physical occurrences before these helpers are used by a standard factory.
- Extension: Further connector drivers may reuse the common named read slots and synchronous projection boundary while retaining their own Native request/response meaning. Unlabelled existing recipes keep their prior selection. Named and unlabelled selection cannot mix within a phase; unsupported write/check/confirmation slots and resource substitution are refused.
