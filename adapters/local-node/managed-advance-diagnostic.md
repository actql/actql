# Local managed control-work diagnosis

## Responsibility

The existing Local managed execution owns each cumulative control counter.
Cross Join distinguishes failure of that counter from row, workspace and
physical memory bounds at the original failed charge. This diagnosis changes
no acceptance rule, public error, dispatch, stop or cleanup decision.

## Inputs and outputs

`checkedLocalManagedAdvance` checks the SAME original `operations.advance`
Result once. Only its typed Core getter may project `control_work` from the
closed `Configuration(ControlWorkLimit)` constructor. Successful yields and
completions, missing getters and all other causes produce no diagnosis.

## Identity

The original Result, namespace receiver, checked exception and Task ordinal
stay unchanged. The existing dispatch owner binds the fixed DATA to its SAME
original Run reference. No request, tag, CID or authority is issued here.

## Ownership

The existing execution and failure-settlement owners retain every physical
child and cleanup duty. The optional frozen `primaryDiagnostic` has only
constant code, phase and kind strings plus the bounded original Task ordinal.
It is attached to the original error without replacing its cleanup carrier.

## Synchronization

The persistent `ControlBudget.remaining` starts from the selected execution
work limit and spans repeated polls. The poll quantum only yields to the Host;
exhausting a slice is successful progress, never `ControlWorkLimit`. Existing
row, then work, then workspace checks keep their original order and debits.

## Failure

Only failed cumulative control charges in Cross Join select the new reason.
Physical `ExecutionLimit` is memory, and `RowLimit`, workspace, input, stop and
unclassified causes stay distinct. The adapter neither guesses from numeric
compiler tags nor classifies a generic unpublished Result. An optional getter,
property definition or diagnostic failure never replaces any thrown value,
including `undefined`; it does not invoke a thrown code accessor.

## Cancellation

Cancellation and mandatory physical stop remain on the existing managed
execution path. Diagnosis supplies no stop acknowledgement, retry or resend
permission. A later independent query still needs its own ordinary admission
under the same Host policy.

## Resources

The fixed diagnostic has no row, Program, provider body or key payload. It
creates no Ledger or reservation and does not widen a quota. The configured
source-free work selection also bounds runtime Fragment Root/Demand
preparation; Program parsing/checking retain separate compiler limits. Each
execution counter is cumulative across polls, not total Host or Run lifetime.

## Extension

Another operator can expose a reason only at its own exact original exhaustion
point. Broad capacity, row or execution errors must not become work evidence.
The typed Node/RelA getter is private implementation material; the public wire
and terminal error semantics stay unchanged.

## Verification

The existing bounded Cross Join test covers exact 52 and one-short 51 work at
quantum one, independently of exact/short workspace and product row bounds.
Provider, managed-owner and Node Result tests preserve that closed reason and
refuse memory, row, input, stop and success substitutions. Adapter tests cover
same Result/receiver, original exceptions/cleanup, absent or failing optional
inspection, and the existing full Model diagnostic. These are component and
source checks; ordinary installed resource-refusal/recovery and performance
observations remain separate.
