# Local managed execution diagnostics

## Responsibility

The existing Local managed execution owns each cumulative control counter.
Cross Join distinguishes failure of that counter from row, workspace and
physical memory bounds at the original failed charge. This diagnosis changes
no acceptance rule, public error, dispatch, stop or cleanup decision.
The existing value-capture owner separately preserves a failed short-name
UTF-8 charge when its strictly smaller bound was the original work allowance.
`value_capture_work` is distinct from the provider's `control_work` counter.
The same failed advance can separately identify the original physical
retained-byte or execution-byte quota constructor. Generic capacity failures
are not evidence of either dimension.

## Inputs and outputs

`checkedLocalManagedAdvance` checks the SAME original `operations.advance`
Result once. Only its typed Core getter may project `control_work` from the
closed `ControlWorkLimit(initialWorkLimit)` constructor. The already-retained
immutable execution limit supplies that scalar only when the provider reports
its original `ControlWorkLimit`; no new state counter or allowance is added. Successful yields and
completions, missing getters and unclassified causes produce no diagnosis.
The separate Capture getter accepts only the SAME failed advance's
`Configuration(Execution(Capture(step, CaptureWorkLimit(limit))))` and returns
the fixed `[step, limit]` DATA vector. It does not classify `CaptureLimit`.
The actual pinned Node export returns that vector inside boxed `Some`;
`runtimeIsBoxedSome` and `runtimeField` from the existing generated compiler
binding read it. A raw array is not an alternative ABI or fallback. The
control-work `Int?` projection retains its separate original unboxed layout.
The resource getter accepts only `Execution(Physical(RetentionLimit))` or
`Execution(Physical(ExecutionLimit))`. Its closed diagnostic has phase
`local_managed_advance`, kind `resource`, the original Task ordinal, and
dimension `retained_bytes` or `execution_bytes`. It supplies no new allowance.

## Identity

The original Result, namespace receiver, checked exception and Task ordinal
stay unchanged. The existing dispatch owner binds the fixed DATA to its SAME
original Run reference. No request, tag, CID or authority is issued here.
An existing cleanup wrapper can retain the original exception in its own
`primaryFailure` DATA slot. When the wrapper has no own `primaryDiagnostic`,
the existing dispatch snapshot reads that one original slot's own diagnostic
and applies the same closed-field validation. It does not walk `cause`, deeper
wrappers or getters, and never unwraps execution or cleanup ownership.

## Ownership

The existing execution and failure-settlement owners retain every physical
child and cleanup duty. The optional frozen `primaryDiagnostic` has only
constant code, phase and kind strings, the bounded original Task ordinal and
the original initial control-work limit.
Value-capture diagnosis instead retains its original Capture step and the
immutable `ValueBudget.limits.max_work`, with no new counter or cleanup owner.
It is attached to the original error without replacing its cleanup carrier.
The existing failure wrappers preserve this own diagnostic DATA slot. A pending
cleanup may separately expose its fixed owner category, phase and continuation
state; those observations do not acknowledge stop or resource release.

## Synchronization

The persistent `ControlBudget.remaining` starts from the selected execution
work limit and spans repeated polls. The poll quantum only yields to the Host;
exhausting a slice is successful progress, never `ControlWorkLimit`. Existing
row, then work, then workspace checks keep their original order and debits.
`charge_text_issue` performs the original single `admit_utf8_length` call with
`min(text_remaining, work_remaining)` and the same successful text/work debit.
`charge_text` remains its boolean projection. Only the bounded output's short
name charge preserves the detailed issue; other boolean callers keep their
existing rejection behavior. No second measurement, retry or Unicode repair
occurs.

## Failure

Only failed cumulative control charges in Cross Join select the new reason.
Physical `ExecutionLimit` is memory, and `RowLimit`, workspace, input, stop and
unclassified causes stay distinct. The adapter neither guesses from numeric
compiler tags nor classifies a generic unpublished Result. An optional getter,
property definition or diagnostic failure never replaces any thrown value,
including `undefined`; it does not invoke a thrown code accessor.
Capture work is selected only from that original scalar `LimitExceeded` when
`work_remaining < text_remaining`. Ties, text limits, malformed Unicode and
invalid limits stay generic. Node, depth, row and workspace failures are not
reclassified. All existing Capture constructors retain their original tags.

## Cancellation

Cancellation and mandatory physical stop remain on the existing managed
execution path. Diagnosis supplies no stop acknowledgement, retry or resend
permission. A later independent query still needs its own ordinary admission
under the same Host policy.

## Resources

The fixed diagnostic has no row, Program, provider body or key payload. It
creates no Ledger or reservation and does not widen a quota. The configured
source-free work selection also bounds runtime Fragment Root/Demand
preparation; Program parsing/checking retain separate compiler limits. Each
execution counter is cumulative across polls, not total Host or Run lifetime.

## Extension

Another operator can expose a reason only at its own exact original exhaustion
point. Broad capacity, row or execution errors must not become work evidence.
The typed Node/RelA getter is private implementation material; the public wire
and terminal error semantics stay unchanged.

## Verification

The existing bounded Cross Join test covers exact 52 and one-short 51 work at
quantum one, independently of exact/short workspace and product row bounds.
Provider, managed-owner and Node Result tests preserve that closed reason and
refuse memory, row, input, stop and success substitutions. Adapter tests cover
same Result/receiver, original exceptions/cleanup, absent or failing optional
inspection, and the existing full Model diagnostic. These are component and
source checks; ordinary installed resource-refusal/recovery and performance
observations remain separate.
The new scalar test covers strict work/text ordering, ties, malformed UTF-16,
successful UTF-8 debit and prior work. The actual Request component executes
the original collection SQL with work 100000 and 1GiB, retains the exact typed
Capture work cause at step 41 before the same owner's cleanup, then verifies
the original holder/Run retirement and zero live reservations. Its normal
installed refusal, later query and prior Saved read still require the matching
immutable distribution; component checks do not establish that acceptance.
Selected Filter tests exercise counted reclamation of an actual stopped,
unpublished output and unchanged work/source availability. Provider and typed
bridge tests retain the original continuation and exact resource constructor.
These checks do not establish normal first-close or post-refusal recovery.
