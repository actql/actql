# Standard REST Source authoring

## Declaration and identity

The author supplies one `actql-rest-connector/0.1` JSON definition and,
optionally, one synchronous `decodePage` module. The existing connector build
resolver projects the definition into its closed Host manifest, static
SourceViews, npm package and installation module. No connector MoonBit
package, provider bundle, generated Core identity or handwritten Host reader
is needed. The same normal package copy graph owns the generated inputs.

`createInstalledRestSource` accepts that generated definition. Its profile has
only `version`, `connectorId`, `siteProfilePath` and
`accountConfigurationWire`. Common's original declaration constructor checks
the original fields and produces the Catalog, contracts, SourceViews and
manifest entry. The facade neither interprets a new schema language nor
converts a Common issue into a successful refusal. Static publication reports
those original bodies; it observes no provider metadata and claims no new
durable publication write.

Identity includes the complete definition and selected Site. A separate hash
of exact original strings preserves physical distinctions that configuration
canonicalization can normalize, including Account wire and Unicode spelling.
Changing the definition, connector id, Site or its generation must not become
a Saved binding alias. Site origin must equal the original fixed HTTPS origin.

## Installation and lifetime

The normal Host supplies the original selected installation and captured
service methods. It selects the implementation profile and typed capacity;
author page limits must be covered in full and supply no physical credit.
The Host opens the nominal credential Site and constructs exactly one managed
reader factory for the installation. The facade selects pure page adapters
by resource, without replacing that factory or adding a cleanup wrapper.

The same RowRun owns acquisition, current checks, read decisions, per-call
grants, cancellation, charging, capture and retirement. The managed reader
retains each original response before accounting and charges bytes before
decode. The Common page projector preserves row-array bytes; JavaScript does
not parse provider numbers and reserialize them. The original charged wire
consumer performs Common row admission. Missing methods, uncovered limits,
provider failures, cursor cycles and malformed pages fail; none imply EOF.

Failed initialization must pass the same factory as `sourceReader` and the
same Site as `sourceProfile` to existing Host initialization cleanup. Only the
original factory's synchronous `true` retirement permits Site release.
Pending or failed retirement remains with that owner, including unexpected
returned computations. A public close acknowledgement, physical closure and
complete borrower retirement are distinct observations.

## Optional projection

The author callback receives frozen `{rowsWire, rowCount, nextCursor}` and
`{resource, columns}` DATA. It receives no credential, authorization, Site,
Run, current fence, stop method or private invoker. The adapter invokes it
through the managed reader's original active-frame invoker. An unexpected
Promise is refused and remains joined to the same owner until settlement;
the facade must not create another observer or pending set. A changed row
wire is checked by the same Common projector. An author cannot supply a row
count or change the declared next cursor.

## Initialization bounds

TLS configuration is initialization work, not a per-page secret allowance.
An explicit `caPath` requires a trusted original configuration bound and its
normal parent backing. Until that input exists, the standard facade refuses
it before reading the CA; it must not substitute `maxSecretBytes`, a generic
JSON ceiling or an invented public tuning field. Default trust is meaningful
only when the original configuration actually selects it. It does not prove
custom-CA or own-TLS conformance. Private-key initialization and all other
normal parent backing remain the Host's duties.

## Verification scope

Metadata/scalar-port components, constructor composition, package input-graph
checks and TypeScript controls each prove only their selected boundary. They
do not prove a funded normal read. External conformance must use a matching
normal package installation, public SDK and actual Host, with independent
empty/one/multiple-page oracles and distinct provider-error, byte-limit,
current-loss, cancellation, cleanup and multiple-connection controls. Saved
recovery must use its successful original reference without resubmission.

The conformance caller records the original pending submission projection
before awaiting it, the returned reference before waiting, the actual first
close and its separate scoped physical observations. Generic Unknown,
absence of a Run or process exit is never nonacceptance or close proof.
Only after a first successful ordinary read can authoring measurements report
handwritten files/lines, commands, elapsed setup, connector Core delta and
callback count. Framework preparation and generated output stay visible as
separate costs rather than being silently counted as zero.
