# Managed Source capture compilation

The captured Plan's publication artifact is produced by the same Request-owned
Pure artifact emitter as the source-free Plan. Its original typed compilation
is retained in that Plan before completion and Run adoption. The shared emitter
keeps its original measure, absolute reserve, encoding work receipt and failure
continuation; the capture entry does not run a second compiler or create an
artifact cache. It checks the same Plan, Prepared, installed contracts, selected
contract bodies and retained-output selection before entering that emitter.

The installed Run's compilation getter returns the original from its actual
captured Plan only for the same live Prepared. Retirement severs both captured
Plan and source-free payload access before their original holders return.
Reading this artifact performs no current callback, re-encoding or compilation.
The new source continuation does not replace the captured Plan constructor's
required same-parent domain backing or the Host's still-required caller join.

`clientProgramPrepareRequestCaptureModuleBody` forwards the original Request,
input and captured Plan to this existing emitter. It selects the same generated
manifests, standard compilation limits and fixed installed provider family as
the source-free Request bridge. It accepts no separate contract inventory or
retained-output option: those remain the selected Plan's originals. This port
does not reconstruct a Plan, issue a compiler input or reserve its constructor
domain. The real Host caller must retain the original Plan input borrow through
construction, artifact preparation, completion and adoption, and settle it under
the existing Run retirement duties.

## Initial Source configuration and original bytes

The candidate initializer creates its one existing Source service before its
first installation-identity file read. The actual initial parent precedes that
service; the managed configuration reader consumes its Source successor. The
Host loader later reuses the same runtime/root/principal service and retains
its actual Project original and Host current callback. A failed construction
keeps the same parent and selection for original cleanup. Source retirement
precedes initial-parent close, and the selection clears only after that close.
A Source-free identity does not create a configuration material merely to hash
an empty source inventory.

The existing file owner handles both original key text and CA bytes. It
observes the extent on the opened FD, reserves the existing native workspace
before reading, then reserves output/parser overlap before concatenation. A
growing file refuses, while that same owner keeps failed close/transfer duties
and retry. The Source material retains each actual output with prior inputs and
failed/sibling workspaces. Raw CA bytes do not pass through UTF8 normalization,
a JSON/secret ceiling or a second file/cleanup owner. REST captures the original
byte-reader method and receiver before configuration awaits, includes the
original CA path and exact byte digest in its physical-binding identity, and
passes those same bytes to its original Site service. Absence keeps the old
identity preimage. No author-facing capacity field is added.

These Source/constructor and file-owner connections do not establish the full
normal backing or execution result. The complete actual declaration, Environment,
Site/native TLS, Reader, retained output and failed-child overlap still require
the real matching initial/Request/Plan holdings. They supply no new Account,
read permission, current decision, Ledger or cleanup acknowledgement. General
unfiltered Source capture and ordinary read/failure/release/Saved remain separate
required work. The focused initializer and raw-file cases use explicit parent,
current and I/O accounting ports; they are not nominal Core or normal acceptance.

## Bound connector construction

The installed loader binds construction to the same checked profile, initial
Resource, configuration reader and current selection. Connector loaders supply
only domain configuration and producer operations. The common boundary reserves
before calling each constructor, retains returned Site, Reader and authorization
children before another callback or await, and registers the final adapter once.
A provider projection cannot replace close, publish an unregistered copy, or
transfer a sibling adapter into this scope. Specialized Site domain projections
receive the original Site's close from the common boundary.

The bound reader captures the original method and receiver. A mutable domain
Site profile is captured as a private frozen own-data snapshot; accessors and
proxies are refused without invoking them. This does not cache external
currentness: the required final identity observation still reads current inputs.
Provider-native declarations remain in their issuing runtime. A provider Effect
uses its actual Site-owned declaration and mappings, never a fabricated common
RowDeclaration. Existing private Effect correspondence resolves only a projection
with the same owner, methods, Environment, selectors and close.

`installed-source-construction-geometry.mjs` supplies pure structural upper bounds
for the existing JSON and Environment constructors. It neither parses inputs nor
issues admission, identity, cancellation or cleanup authority. The caller retains
the original wires and obtains actual Resource backing before construction.
Successful synchronous Source Environment construction retains its actual output
strings and record; unreachable parser and canonicalization workspace can then
leave the peak. A throw after admission keeps that admitted peak as failure debt
on the same material, including during sibling reconciliation. A refused reserve
adds no ungranted debt. Pure failed workspace does not invent pending physical
work or prevent eventual retirement after all real children acknowledge close.
Effect and Table phases retain their peaks until their later consumers have their
own backing. Native producers separately describe actual escaped outputs and
construction workspace; connector authors do not manage release or retention.

The actual installed-bound-construction tests compose generated selection,
Resource, common constructors and physical cleanup. External provider I/O alone
is substituted. These initializer tests do not establish normal packaged
Run/Result/Saved acceptance or the coverage of every external provider operation.

## Original binding retirement acknowledgement

The shared Reader captures each returned binding's original close and optional
retirement method before provider use. A failed method capture leaves that
binding unconfirmed through the outer read failure. A socket-close acknowledgement
cannot clear this separate retirement duty or permit the Reader/factory to report
cleanup complete. A valid original retirement that reports pending remains held
until the same retry observes its acknowledgement; no replacement method or
second binding is selected.

## Failed Reader and Account initialization

The existing initialization cleanup owner retains a supplied `sourceReader`
factory and `authorization` Account before its first cleanup await. It captures
each original method and receiver once, retries only an unobserved method, and
requires that original owner's synchronous `true` before clearing its holding.
An unexpected Promise is joined and remains an invalid acknowledgement even
when it resolves true. The same failure/status/retry owner retains every pending
phase and the original primary error.

Factory retirement precedes Source Site close. A separately supplied Account
closes only after those dependent phases settle, and initial-parent close stays
behind all original child owners. The normal failed-Site constructor supplies
`{authorization}` only when no Site was returned; a returned owned Site keeps
its existing Account-close duty. This does not create another Account/cleanup
owner or duplicate its grant/current decisions. The constructed Account, factory,
method references and failed-child overlap still belong in the actual original
initial/Source reservation; the explicit-port regression is not physical or
normal retirement acceptance.

## Original Source evidence transfer

Live row capture can prepare Source evidence with
`prepareSourceEvidenceOriginal(options)`, which performs the existing current
check and calls the same Core issuer through its typed Node projection. The
existing capture retains that exact `RunEvidenceValue` until
`capture.takeSourceEvidenceOriginal()` transfers it once. Taking is synchronous
and performs no current callback, wire encoding, parsing or evidence admission.
The original wire-returning issuance API retains its existing semantics.

An unconsumed evidence value and its original capture association remain held
while RowRun cleanup is pending. Only successful original RowRun retirement
clears them; closing during the issuance current check prevents later issuance.
The retained value, capture reference and preparation state are part of the
existing capture/publication overlap that the actual constructor and caller
must fund. This port supplies no reservation, publication authority, persisted
evidence admission or normal execution acceptance.
