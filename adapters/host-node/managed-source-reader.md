# Managed Source capture compilation

The captured Plan's publication artifact is produced by the same Request-owned
Pure artifact emitter as the source-free Plan. Its original typed compilation
is retained in that Plan before completion and Run adoption. The shared emitter
keeps its original measure, absolute reserve, encoding work receipt and failure
continuation; the capture entry does not run a second compiler or create an
artifact cache. It checks the same Plan, Prepared, installed contracts, selected
contract bodies and retained-output selection before entering that emitter.

The installed Run's compilation getter returns the original from its actual
captured Plan only for the same live Prepared. Retirement severs both captured
Plan and source-free payload access before their original holders return.
Reading this artifact performs no current callback, re-encoding or compilation.
The new source continuation does not replace the captured Plan constructor's
required same-parent domain backing or the Host's still-required caller join.

`clientProgramPrepareRequestCaptureModuleBody` forwards the original Request,
input and captured Plan to this existing emitter. It selects the same generated
manifests, standard compilation limits and fixed installed provider family as
the source-free Request bridge. It accepts no separate contract inventory or
retained-output option: those remain the selected Plan's originals. This port
does not reconstruct a Plan, issue a compiler input or reserve its constructor
domain. The real Host caller must retain the original Plan input borrow through
construction, artifact preparation, completion and adoption, and settle it under
the existing Run retirement duties.

## Initial Source configuration and original bytes

The candidate initializer creates its one existing Source service before its
first installation-identity file read. The actual initial parent precedes that
service; the managed configuration reader consumes its Source successor. The
Host loader later reuses the same runtime/root/principal service and retains
its actual Project original and Host current callback. A failed construction
keeps the same parent and selection for original cleanup. Source retirement
precedes initial-parent close, and the selection clears only after that close.
A Source-free identity does not create a configuration material merely to hash
an empty source inventory.

The existing file owner handles both original key text and CA bytes. It
observes the extent on the opened FD, reserves the existing native workspace
before reading, then reserves output/parser overlap before concatenation. A
growing file refuses, while that same owner keeps failed close/transfer duties
and retry. The Source material retains each actual output with prior inputs and
failed/sibling workspaces. Raw CA bytes do not pass through UTF8 normalization,
a JSON/secret ceiling or a second file/cleanup owner. REST captures the original
byte-reader method and receiver before configuration awaits, includes the
original CA path and exact byte digest in its physical-binding identity, and
passes those same bytes to its original Site service. Absence keeps the old
identity preimage. No author-facing capacity field is added.

These Source/constructor and file-owner connections do not establish the full
normal backing or execution result. The complete actual declaration, Environment,
Site/native TLS, Reader, retained output and failed-child overlap still require
the real matching initial/Request/Plan holdings. They supply no new Account,
read permission, current decision, Ledger or cleanup acknowledgement. General
unfiltered Source capture and ordinary read/failure/release/Saved remain separate
required work. The focused initializer and raw-file cases use explicit parent,
current and I/O accounting ports; they are not nominal Core or normal acceptance.

## Native Source input and declaration completion

`prepareInputConstruction` and `prepareNativeDeclaration` consume the same
private initialization context as authored declarations. Each captures one
original synchronous quantity/projection pair, composes its existing Source
constructor quantity into the original parent, then enters the projection.
The input entrance retains the returned original Buffer or opaque value without
walking, freezing or copying it. The declaration entrance retains the returned
nominal declaration and provider material, uses the captured Common serializer
on that declaration, and reserves the existing Host JSON/Environment envelope
before parsing and merging. It does not restore a second nominal declaration.
The returned declaration, DATA and Environment are the originals required by
Source construction and registration.

Each entrance is one-shot, including reservation refusal, thrown `undefined`
and failed native construction. Copied receivers and reentry refuse. An invalid
native Promise remains with the same initial material until settlement; its
completion cannot turn the refused constructor into success. The full selected
native peak stays retained until original Source retirement. There is no
retained-output approximation or physical cleanup acknowledgement at this
entrance. Provider recipes must cover their own complete native serializer,
failed-prefix and coexisting outputs before calling it.

BigQuery uses the bound `prepareNativeDeclaration` entrance with one actual
`ReadDeclarationConstructionCapacity` quote for the canonical base64 Buffer,
metadata parser, table description, nominal declaration and exported declaration
wire, including their coexisting outputs and failed-prefix peak. It does not
also invoke the raw input entrance or add a generic declaration envelope for the
same construction. The original description and limit records feed its later
`PrepareRead`; no nominal Query is reconstructed from detached schema DATA.
Host parsing and Environment merging receive their own existing same-parent
backing before construction. Initial identity hashes the original metadata DATA
separately from native schema admission. The actual loader uses the bound
configuration reader, `openRowSite` and `createRowSource` owner to retain the
original Site, authorization and Source children before current checks or awaits.
Custom acquisition preparers also read protocol assets through the same physical
file owner, while retaining their original native protocol admission. Job
selection, original-operation CAS, read permission and cancellation remain with
their existing owners.

The registered BigQuery component exercises real Core/Resource/Source/Site and
file cleanup with I/O-only TLS fixtures. Failure cases retain the original
metadata/native refusal inside the existing cleanup carrier and require no
pending cleanup and scoped state FDs. The Job callback case remains a separate
explicit-port component. Neither establishes current-source normal packaging,
business execution, real-service credentials or cold Job recovery.

## Bound connector construction

The installed loader binds construction to the same checked profile, initial
Resource, configuration reader and current selection. Connector loaders supply
only domain configuration and producer operations. The common boundary reserves
before calling each constructor, retains returned Site, Reader and authorization
children before another callback or await, and registers the final adapter once.
A provider projection cannot replace close, publish an unregistered copy, or
transfer a sibling adapter into this scope. Specialized Site domain projections
receive the original Site's close from the common boundary.

The bound reader captures the original method and receiver. A mutable domain
Site profile is captured as a private frozen own-data snapshot; accessors and
proxies are refused without invoking them. This does not cache external
currentness: the required final identity observation still reads current inputs.
Provider-native declarations remain in their issuing runtime. A provider Effect
uses its actual Site-owned declaration and mappings, never a fabricated common
RowDeclaration. Existing private Effect correspondence resolves only a projection
with the same owner, methods, Environment, selectors and close.

`installed-source-construction-geometry.mjs` supplies pure structural upper bounds
for the existing JSON and Environment constructors. It neither parses inputs nor
issues admission, identity, cancellation or cleanup authority. The caller retains
the original wires and obtains actual Resource backing before construction.
Successful synchronous Source Environment construction retains its actual output
strings and record; unreachable parser and canonicalization workspace can then
leave the peak. A throw after admission keeps that admitted peak as failure debt
on the same material, including during sibling reconciliation. A refused reserve
adds no ungranted debt. Pure failed workspace does not invent pending physical
work or prevent eventual retirement after all real children acknowledge close.
Effect and Table phases retain their peaks until their later consumers have their
own backing. Native producers separately describe actual escaped outputs and
construction workspace; connector authors do not manage release or retention.

The actual installed-bound-construction tests compose generated selection,
Resource, common constructors and physical cleanup. External provider I/O alone
is substituted. These initializer tests do not establish normal packaged
Run/Result/Saved acceptance or the coverage of every external provider operation.

## Original binding retirement acknowledgement

The shared Reader captures each returned binding's original close and optional
retirement method before provider use. A failed method capture leaves that
binding unconfirmed through the outer read failure. A socket-close acknowledgement
cannot clear this separate retirement duty or permit the Reader/factory to report
cleanup complete. A valid original retirement that reports pending remains held
until the same retry observes its acknowledgement; no replacement method or
second binding is selected.

## Failed Reader and Account initialization

The existing initialization cleanup owner retains a supplied `sourceReader`
factory and `authorization` Account before its first cleanup await. It captures
each original method and receiver once, retries only an unobserved method, and
requires that original owner's synchronous `true` before clearing its holding.
An unexpected Promise is joined and remains an invalid acknowledgement even
when it resolves true. The same failure/status/retry owner retains every pending
phase and the original primary error.

Factory retirement precedes Source Site close. A separately supplied Account
closes only after those dependent phases settle, and initial-parent close stays
behind all original child owners. The normal failed-Site constructor supplies
`{authorization}` only when no Site was returned; a returned owned Site keeps
its existing Account-close duty. This does not create another Account/cleanup
owner or duplicate its grant/current decisions. The constructed Account, factory,
method references and failed-child overlap still belong in the actual original
initial/Source reservation; the explicit-port regression is not physical or
normal retirement acceptance.

## Original Source evidence transfer

Live row capture can prepare Source evidence with
`prepareSourceEvidenceOriginal(options)`, which performs the existing current
check and calls the same Core issuer through its typed Node projection. The
existing capture retains that exact `RunEvidenceValue` until
`capture.takeSourceEvidenceOriginal()` transfers it once. Taking is synchronous
and performs no current callback, wire encoding, parsing or evidence admission.
The original wire-returning issuance API retains its existing semantics.

An unconsumed evidence value and its original capture association remain held
while RowRun cleanup is pending. Only successful original RowRun retirement
clears them; closing during the issuance current check prevents later issuance.
The retained value, capture reference and preparation state are part of the
existing capture/publication overlap that the actual constructor and caller
must fund. This port supplies no reservation, publication authority, persisted
evidence admission or normal execution acceptance.

## Native signed children and original typed cells

An installed native sequence may return its Site's `originalAuthorization` and
its associated `authorization` envelope in the same prepared child descriptor.
The shared reader snapshots only those two references, forwards them unchanged
to the existing child-occurrence/current callback, and refuses substitution.
The same Site's private `readChildCredential` then checks the original grant
against the already retained acquisition. Equal scope, copied grant envelopes
or an operation label cannot supply that original. Ordinary descriptors retain
the existing grant-issuance path; the native handoff issues no second grant.

The Row Source still spends the selected immutable operation occurrence before
its current callback. A failed nominal handoff cannot refund the use or replace
its parent. Field accessors refuse without evaluation; invalid asynchronous
fields remain joined to the same reader until settlement. Response retention,
physical byte charging, current checks, stop and binding/provider retirement
remain in the original reader and RowRun.

`consumeValues(columns, rows)` passes the original typed cell arrays with the
same response charge into the existing `clientProgramRowSourceAcceptChargedValues`.
It creates no JSON wire, new CheckedValue or second schema checker. Core's
returned count must equal the original row count. A failed or pending consume
retains those same cells and charge through stop; successful consumption alone
cannot acknowledge physical closure. Legacy readPages receives no
new typed-value callback.

The existing JSON reader recipe includes two allocated callbacks and their
original slots (2 record headers and 4 references). Its simultaneous control
workspace includes the two native field descriptors, two-field handoff, extra
argument, optional method envelope and typed-call controls (6 headers,
10 references and 8 scalar words). These are fixed logical constructor units,
not a new tariff, engine heap claim or user limit. No variable credential,
response or native metadata tree is copied by this handoff. A selected native
protocol must still supply its complete metadata/graph/query workspace before
callbacks; this shared connection is not that Salesforce recipe or its normal
caller acceptance.

## Native Salesforce original Reader protocol

The Salesforce Site registers its original credential in the existing private
operation-Site association through that credential's own custody. This entry
retains the same principal, runtime, issuer, Journal and binding methods; a
copied credential or a second Site cannot replace the registered original.
The installed Site's query grant records its actual admitted read decision and
Resource as private purpose. Describe grants record their independently
admitted metadata decision (or the same original admitted approval), Resource
and invocation. Operation names and request DATA issue no authority.

A native prepared sequence receives the same already prepared acquisition
facts and the Site's original authorization at Reader preparation. Preparation
performs no provider read. The first invocation, including its original use ID,
is forwarded unchanged only after the same Reader opens its binding. Existing
sequences without prepared facts retain their one-argument read protocol.
Accessors refuse without invocation; asynchronous prepared inputs remain with
the Reader until the original computation settles, even after stop.

`prepareSalesforceSourceReadSequence` runs the existing Describe and query
codecs inside that Reader. The first Describe rechecks the original row
projection; the independent Describe immediately before query execution
remains. Both descriptions use the same original dispatch and their separately
issued Site originals. `readSalesforceSourceChild` compares every copied
primitive scope field, then hands the Site original and actual request
occurrence unchanged to `readChild`. The same Site's nominal purpose,
Resource, invocation and binding checks still precede physical use.

The shared Reader retains and charges each actual response once before codec
projection. Metadata consumes that same charge as an observation; query pages
pass the original Common typed columns/cells to `consumeValues`, without a row
JSON roundtrip or a second charge. Rejected query bodies remain charged and
cannot reach typed admission. The already observed original child failure,
including thrown `undefined`, survives a provider's later status conversion.
A provider failure observed before an outstanding child settles remains its
primary failure while the same Reader joins that child.

The protocol's pending read prevents its retirement. After settlement the
original Reader owns physical close, pending callbacks, unconfirmed charges
and provider retirement; no returned status is a physical acknowledgement.
The protocol releases its acquisition, Site, declaration, codec and credential
aliases only through that original retirement. Existing Effect record bindings
and their separate current/profile checks do not use a replacement wrapper.

Installation must compose the actual native metadata, recovery, query,
projection and failed-prefix inventory with the shared Reader recipe before
constructing this protocol or calling its codecs. The fixed shared handoff
adds only the original field descriptor, two borrowed input references, one
invocation reference and one retained selection flag. It neither covers the
variable native codec inventory nor supplies admission by itself. The original
Describe/query limits, row bounds and approvals remain independent of this
representation inventory; no cap, fallback read or standalone Run is implied.

## Original read rejection during retirement

The existing reader phase records rejection presence independently of its
value. A provider may reject with `undefined` after an original stop request;
that remains the original read rejection. If cleanup of the same provider or
binding also throws in the outer `finally`, keep that retirement failure in
the original transport-failure state and retain its cleanup duty. It must not
replace the read rejection merely because the original value is undefined.
The same original reader retry remains fallible until that provider actually
retires; no cleanup flag is cleared to manufacture acknowledgement. A cleanup
exception after a previously successful read is still a cleanup exception.
This changes no current boundary, capacity, callback count, physical stop or
response evidence rule.
