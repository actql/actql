# Source alias request DATA construction

## Responsibility

The existing installed Source metadata reader funds Host alias parse, immutable
request snapshots, exact identity encoding and aggregate alias collection.
The shared MoonBit installed-profile recipe quotes profile parsing and checked
snapshot construction through the original metadata reader. The remaining
`source-alias-construction.mjs` recipes cover identity and collection;
`source-alias-request.mjs` validates and snapshots constant request DATA.
Neither module resolves Sources, admits native Catalogs, grants authority or
creates another Resource owner. Installed alias identity and publication reuse
these same constructors instead of a second provider-specific model.

## Inputs and outputs

A bounded original UTF-8 profile wire is parsed once within the funded snapshot
constructor. Alias request records accept plain JSON DATA and preserve absence
versus explicit null. Snapshot construction recursively freezes arrays and
sorted object keys without normalizing user strings or adding omitted fields.
Identity rows include the request only when present. Collection construction
produces an immutable outer alias list and validates duplicate names; downstream
publication borrows validated frozen request DATA rather than copying it again.

## Identity

`captureSourceAliasConstruction` captures the exact reader and runtime quote
methods before asynchronous profile loading. Calling the retained reader method
still requires the nominal original receiver and material. Alias identity
retains the existing generation domain and includes exact request DATA;
insertion order does not change object identity, while absent and null requests
remain distinct. Namespace, environment and actual Source matching are separate
checks and are not replaced by alias string equality.

## Ownership

The same Source material retains parsed profile, provider spread, frozen alias
requests and funded identity/collection outputs. Providers receive the retained
immutable request DATA. No mutable caller graph crosses the reservation
callback. Standalone diagnostics without a configuration reader retain their
historical direct construction path; they do not impersonate an installed
reader or establish installed funding. Returned snapshots contain DATA only,
not original capabilities, grants or cleanup acknowledgements.

## Synchronization

Geometry inspects the original wire or an already immutable graph before the
constructor. Reservation precedes parse, snapshot, identity stringify/hash and
aggregate collection. Own-method capture rejects proxies, asynchronous methods
and accessor substitution. Installed source loading reuses the acquired profile
and captured constructor across provider metadata and final alias identity;
optional metadata recovery does not encompass the later funding constructor.

## Failure

Malformed DATA, proxies, accessors, cycles, sparse arrays, ill-formed strings,
nonfinite numbers, negative zero and unsupported prototype objects refuse.
Request traversal enforces its node, text and depth bounds, and rejects direct
singleton parameter/binding references where constant DATA is required.
Reservation failures, including an undefined thrown value, propagate unchanged.
Cleanup-bearing errors are not converted into an unresolved namespace or
optional missing metadata. Failed construction remains on the same initializer.

## Cancellation

Pure snapshot/identity work is synchronous and starts only after reservation.
Currentness, asynchronous metadata reads and cancellation remain the existing
reader/Source responsibilities. A snapshot does not settle the original file,
provider cleanup or parent initialization. Pending cleanup preserves originals;
retry is not permission to re-read or replace a failed construction owner.

## Resources

The shared MoonBit profile recipe covers parse backing, provider spread, alias
rows, request snapshots, descriptor/key scans, sorting, recursion and
serialization overlap. Its decoded parse output is distinct from later checked
projections: those retain their own containers while borrowing the original
immutable String leaves, without charging another decoded text body. The
existing bound reader still reserves before each native constructor, and only
a successful original current fence permits the retained-only cut.
Immutable DATA geometry scans without serializing the whole request. Identity
geometry includes exact identity row construction, stringify and hash-related
backing; collection geometry covers the retained list, duplicate-name Set and
validation workspace. Bounded scalar numeric token conversion is distinct from
serializing a request tree. These are Host JavaScript quantities, not funding
for complete native Catalog, publication, Mapping or Environment admission.
The latter retain their independent original construction recipes.

## Extension

Additional request values or reference forms require an explicit grammar and
matching bounds, snapshots and identity tests. Do not infer schemas from sample
rows or introduce scenario-specific alias rules. Pure alias construction does
not authorize provider reads, network effects, installed namespace fallback or
new native admission shortcuts.
