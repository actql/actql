# Declared catalog staged JS construction

- Responsibility: The common installed catalog geometry adapter describes only
  the actual JavaScript constructor families used by the declared catalog loader.
  It returns demand DATA, not parsed catalog content, capacity, admission or a
  new constructor owner. Shared canonical construction follows the existing
  canonicalJson data-key path, preserving opaque member names without NFC.
- Inputs and outputs: Entry and subsequent stages scan exact borrowed Strings.
  Scope uses connection, configured provider namespace, resolved data path and
  whole original catalog wire separately. File facts use the original entry,
  initial native declaration export, scope CID and validated binding count.
  Physical overrides and Mapping inputs use exact validated invocation counts.
  Final descriptors accept original frozen Mapping records with own body Strings
  or the diagnostic String array. Outputs use bigint logical constructor nodes,
  UTF16 backing bytes (two bytes per unit), wire bytes, retained/workspace sums
  and explicitly named output bounds. Bounds are not accepted item counts.
- Identity: Provider namespace is distinct from logical Source connection
  identity. Schema/CID Strings, original paths and actual native Mapping bodies
  remain their callers' originals. Counts and equal text cannot authenticate a
  source, resolve a path, replace a declaration, or manufacture a receipt. Record
  inspection rejects proxies and accessors instead of invoking arbitrary code.
- Ownership: The existing installed SourceInitialization material retains every
  stage quote through its ordinary preparation and retirement. Its existing
  native construction-capacity operation converts the geometry before the
  corresponding prepareNativeInput projection. Source/effect member/prepared
  tuple references and original Mapping records remain borrowed; this helper
  creates no Root, Run, Ledger, source installation or approval authority.
- Synchronization: Fund strict catalog reading and native catalog/connections
  admission separately before obtaining entry spans. Fund entry JS parsing and
  initial saved-view construction before native restore. With the funded native
  export, separately fund scope hashing, initial export parsing/File facts and
  final saved-view construction. Fund every native restore separately. Physical
  payloads coexist across all actual overrides. Fund authored UPDATE JSON and
  frozen operation/source records before prepareBorrowedDeclaration and then
  prepareMappings. Fund final descriptors before assembling the returned tuple.
  Quote functions never parse, canonicalize or hash proportional caller input.
- Failure: Malformed-prefix geometry does not admit its input. Non-String input,
  invalid count domains, proxies and accessor Mapping bodies refuse. Empty
  physical override stages still own their Map wrapper; empty Mapping input
  stages still own their arrays, output wire and result wrapper. Failed parse,
  canonical, hash and projection prefixes retain their full constructor overlap;
  a failed later stage cannot reclaim earlier material implicitly.
- Cancellation: Synchronous geometry reports no physical cleanup or stop ACK.
  Currentness, reentry, failed constructor debt and pending cleanup remain with
  the existing initialization material and original Source/Effect owners. No
  successful geometry return permits premature release of captured originals.
- Resources: Entry demand includes the parsed tree, validation keys/vocabulary,
  saved records and Strings, alias/data/file-binding collections, seven native
  input arrays, schema hashes and first restore wire. Canonical families include
  entries/pairs/filter/replacement arrays, keys/Set, sort, child text, recursion
  and final output. Later stages count scope/version hash preimages and buffers,
  initial exported JSON, fixed File-fact descriptor vocabularies, generated facts,
  physical candidate-key payloads and the single physicalDeclarations Map whose
  values are replaced with native declarations. Final output counts four borrowed
  installation fields plus descriptor/freeze traversal. UPDATE input counts
  authored records/wire and frozen operation/source arrays, borrowing repeated
  target/field name Strings. Actual invocations sum; prior owner peaks remain
  separate and are never replaced by the largest stage or by transfer bytes.
- Extension: Native catalog/connections admission, declaration restore/export,
  actual Mapping construction, Environment construction and physical I/O are
  excluded and retain their separate existing-owner recipes. New literals,
  descriptors, stages, invocation multiplicity or owner lifetimes require an
  updated constructor inventory and caller ordering; an entry-only byte factor
  cannot cover foreign path/catalog/native-output inputs or new authority.
- Verification: declared-project-catalog-construction.test.mjs exercises actual
  canonical/hash/output bounds, multi-view and repeated invocation sums, borrowed
  native outputs, empty-stage minima, malformed input geometry, exact Mapping
  payloads and refusal without parse/stringify/coercion. Installed-stage tests
  separately exercise the selected caller. These are source/component checks;
  neither the sidecar nor those tests establish full normal-package, artifact,
  runtime coverage or release acceptance.
